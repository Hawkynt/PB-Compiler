# PB 3.6 — an envisioned successor dialect

Design sketch for a hypothetical "PowerBASIC 3.6": what the next DOS release
*could* have looked like, implemented as `--dialect pb36` on top of PB-Compiler.

**Mission: blazingly fast and lean.** PB 3.6 is an *optimizing* PB — same
language, same observable behavior, but aggressive compiler optimizations,
386/486-aware code generation with 32-bit registers, DWORD-wide memory and
video primitives, and a runtime that is paid for strictly by use: a hello
world should come down to mere bytes.

Guiding rule: **pb36 is a strict superset of pb35** — any source that compiles
under pb35 compiles under pb36 with *byte-identical observable behavior* (the
differential harness against genuine PBC 3.50 must stay green when run through
pb36); the dialect only changes time, size and memory, plus new opt-in surface.

Requirements use MoSCoW; each item names its verification gate.

## The optimizer is dialect-agnostic

pb36 never added syntax - it is pb35 plus optimization. The optimizer lives
between the binder and the emitter, operating on the bound `SemanticModel` (the
shared intermediate representation every dialect produces), and it reads that
model's *per-dialect* types, wrap rules and semantics. So it preserves
observable behavior for every dialect, not just PB. The master gate is
`CodeGenerator.Optimize` (defaults on for pb36); any dialect opts in with the
`--optimize` CLI flag, and `--no-optimize` is the pb35-faithful escape hatch.
Even the *lean-output* features (P7 raw-COM lowering, P1 runtime trimming, P3
BSS) and float demotion are gated on `Optimize`, not the dialect, so a QB or TB
program compiled with `--optimize` also shrinks to a trimmed image - we have
full control over the executable layout and type (EXE/COM) for any dialect.
Verified: with the optimizer forced on for *every* dialect, all differential
batteries (QB 1.0-4.5, PDS 7.0/7.1, TB 1.0/1.1, PB 2.x/3.0/3.5) stay
byte-identical to their genuine compilers - the complete chain (expression
folding, SSA/SCCP/DSE, strength reduction, register allocation, float demotion,
lean output) is dialect-agnostic. "pb36" is therefore just a convenience preset
= pb35 front-end + `Optimize` on; it adds no syntax *today*.

**Why pb36 is kept as its own dialect (future work).** It is reserved as the
home for features that would make it a genuinely new language rather than a flag:
`VAR`/`AUTO` type inference with fused declare-and-initialize, lambdas and
expression-bodied members (VB.NET-style), EMS/XMS-backed heaps that truly use
more than 1 MB, a deterministic reference-counting GC (C++-style, not a
stop-the-world collector), and additional data types where feasible. The first
of these have started landing (see *New syntax* below); the rest remain future
work, and the dialect slot stays so that work has somewhere to land.

## New syntax (pb36-only language features)

These constructs compile only under `--dialect pb36`; every one is rejected
below 3.6 with the standard `requires PowerBASIC 3.6` gate, and none changes the
meaning of any pb35 program (the superset guarantee holds). Each is sugar that
desugars to a construct the binder/codegen already handle, so it shares the same
verified runtime paths.

- **Expression-bodied FUNCTION** — `FUNCTION F(...) [AS T] = expression`
  declares a function whose whole body is one result expression, mirroring
  `DEF FN`'s `= expr` form for the modern `FUNCTION` syntax. It desugars in the
  parser to a single `FUNCTION = expression` result assignment, so the existing
  function-result codegen carries it unchanged. Gate:
  `LanguageFeature.ExpressionBodiedProc`; coverage in
  `ParserDeclarationTests`, `DialectGateTests`, and the DOSBox battery
  `Pb36LanguageFeatureTests`.

- **Compound assignment operators** — `target OP= value` for
  `+= -= *= /= \= ^= &=`, e.g. `n% += 1`, `s$ &= text$`. The parser desugars
  `target OP= value` to `target = target OP value` (the lvalue node is reused in
  both the read and write position, which is structurally what the operator
  means), so the existing assignment/binary codegen carries it unchanged. Gate:
  `LanguageFeature.CompoundAssignment`.

- **DIM with initializer (fused declare-and-initialize)** —
  `DIM x = value` infers the variable's type from the initializer;
  `DIM x AS type = value` uses the explicit type. Works for procedure locals and
  module/main globals. The binder binds the initializer (so its type is known),
  declares the variable with the inferred or explicit type, and records a real
  assignment which a post-bind splice pass inserts immediately after the DIM in
  the executable stream. So codegen and *every* optimizer pass (SSA, float
  demotion, dead-store, …) see an ordinary declaration-then-assignment pair —
  there are no hidden writes, which keeps the dataflow analyses sound (e.g. a
  fractional initializer correctly blocks float demotion). Inference picks a type
  wide enough for the initializer (a literal like `100000` infers LONG, not
  INTEGER). Gate: `LanguageFeature.DimInitializer`.

- **Short-circuit ternary `IF()`** — `IF(condition, whenTrue, whenFalse)` as an
  expression (VB.NET-style `If` operator). Only the selected branch is evaluated
  at runtime: codegen emits a real branch (reusing the IF/loop condition test),
  so a side-effecting or trapping untaken branch is skipped (e.g.
  `IF(x = 0, 42, 100 \ x)` never divides by zero). The result type is the common
  type of the two branches (both numeric → the wider; both string → STRING;
  mixing the two is an error). `IF` is a reserved keyword, so intercepting `IF(`
  in expression position shadows nothing. Gate: `LanguageFeature.TernaryIf`.
  Implemented as a new `IfExpr` node registered in `AstQuery.Subexpressions`, so
  the optimizer's conservative walkers handle it soundly (see below).

- **Short-circuit boolean operators `ANDALSO` / `ORELSE`** — VB.NET-style: unlike
  PB's bitwise `AND`/`OR`, they stop once the result is known. They lower in the
  parser to the ternary — `a ANDALSO b` → `IF(a, b <> 0, 0)` (b skipped when a is
  false), `a ORELSE b` → `IF(a, -1, b <> 0)` (b skipped when a is true) — so they
  reuse the ternary's short-circuit codegen and stay sound in the optimizer for
  free, and the result is the normalized PB truth value (-1 / 0). `ANDALSO` sits
  at `AND` precedence, `ORELSE` at `OR`. Gate: `LanguageFeature.ShortCircuitOps`.

- **Object initializer** — `DIM p = NEW Udt { .field = value, ... }` (and
  `DIM p AS Udt = NEW Udt { ... }`) declares `p` as the UDT and initializes the
  listed fields; fields left out keep their zero-initialized value. The binder
  lowers it to one `p.field = value` assignment per listed field (spliced after
  the DIM like any DIM initializer), so it reuses the existing UDT field-assignment
  codegen and the `NEW` node never reaches the emitter. Valid only as a DIM
  initializer (used elsewhere it is an error). Adds `{`/`}` lexer tokens. Gate:
  `LanguageFeature.ObjectInitializer`.

- **SUB/FUNCTION overloading** — several SUBs/FUNCTIONs may share a name as long
  as their parameter signatures differ; each call resolves to the best match
  (the unique arity match, then, among same-arity candidates, the one with the
  most exact argument-type matches). The procedure table became an overload set
  (`Overloads` by name, `ProcedureList` for emission, `Procedures` still the
  primary for "exists / is a function" checks); each overload gets its own
  emitted label (the first/only one keeps the plain `p_<name>` so non-overloaded
  programs are byte-identical). A redefinition with an *identical* signature is
  still the existing "already defined" error; a DECLARE prototype is matched to
  its definition by signature. Gate: `LanguageFeature.SubFunctionOverloading`
  (a same-name/different-signature definition under pb35 reports the gate error).

- **Shift / rotate / bitwise operators** — new operators whose width is the left
  operand's integral type: `<<` (shift left), `<<<` (logical shift left, same as
  `<<`), `>>` (arithmetic/signed shift right), `>>>` (logical/unsigned shift
  right), `<<>` (rotate left), `<>>` (rotate right), and `|` (bitwise OR). They
  bind looser than `+`/`-` but tighter than comparison, and each has a
  compound-assignment form (`<<=`, `>>=`, `<<<=`, `>>>=`, `<<>=`, `<>>=`, `|=`).
  16-bit operands shift/rotate via the 8086 `CL` forms; 32-bit operands use a
  per-bit loop. The lexer maximal-munches the multi-char operators without
  disturbing `<`, `<=`, `<>`, `>`, `>=` (these sequences were never valid pb35,
  so nothing existing changes meaning). Gate: `LanguageFeature.ShiftRotateOps`.

- **Scaled pointer arithmetic** — `ptr +* index` / `ptr -* index` move a typed
  pointer by `index * sizeof(target)` (the same scaling `@p[index]` uses);
  `ptr +* 1` on an `INTEGER PTR` advances 2 bytes, on a `LONG PTR` 4 bytes. The
  result is the pointer's type, so it chains and assigns to a pointer. The codegen
  is offset-only real-mode arithmetic (segment fixed, offset wraps at 64K),
  matching `@p[i]`. Distinct `+*`/`-*` operators were chosen on purpose so raw
  `ptr + n` keeps its existing unscaled DWORD meaning — pb36 stays a byte-identical
  superset of pb35. New `+*`/`-*` lexer tokens; gate:
  `LanguageFeature.PointerArithmetic`.

- **`ENUM` blocks** — `ENUM Name [AS type] : A, B = 5, C : END ENUM` declares a
  group of named integer constants (auto-incrementing from 0 / last+1, or explicit
  `= value`). Members are bare compile-time constants in their own namespace (a
  real variable of the same name wins); the enum name aliases its underlying
  integer type, so `DIM c AS Color` works. The binder records each member
  reference in `ResolvedConstants` (emitted as a literal, ungated so it is correct
  with the optimizer off) and `ConstantFolder` knows members too (for CASE/bounds/
  `DIM`-init). Compile-time only, no runtime, no OOP. Gate:
  `LanguageFeature.EnumType`.

- **`WITH expr … END WITH`** — inside the block a leading `.member` refers to
  `expr.member` (nestable; the innermost WITH wins). Pure parser desugar: the
  leading dots are rewritten to member accesses on the subject and the block is
  spliced inline (no WITH node reaches the binder/codegen, so it composes with
  every later pass for free). The subject is re-read per access — use a simple
  subject if that matters. Reduces UDT-access repetition, no OOP. Gate:
  `LanguageFeature.WithBlock`.

- **Default parameter values** — `SUB Foo(x AS INTEGER, y AS INTEGER = 10)`: a
  defaulted parameter is optional, and a call site may omit it (trailing). The
  default lives on the definition's signature (a `DECLARE` may omit it; the
  definition's params win on replace); the codegen fills omitted trailing
  arguments with each parameter's default expression, evaluated at the call site.
  It composes with overloading through the existing `Optional`/`RequiredParameters`
  mechanism. Note: IPCP was taught about defaults too — a call that omits a
  defaulted argument is folded as passing that default, so the optimizer no longer
  mistakes a parameter for a constant when some call sites use the default. Gate:
  `LanguageFeature.DefaultParameters`.

- **Named arguments** — `Foo(y := 5)`: an argument may be given by parameter name
  (`name := value`). The binder reorders the call's arguments into positional
  order (positional args first, then named by name) and fills any omitted
  parameter with its default, storing the positional list which codegen and IPCP
  consume; the AST nodes (`NamedArgExpr`) are still walked by the optimizer via
  `AstQuery.Subexpressions`. Errors on an unknown/duplicate name, a positional
  argument after a named one, or a missing argument. Gate:
  `LanguageFeature.NamedArguments`.

- **XMS/EMS arrays (opt-in memory surface)** — `DIM EMS a(...)` / `DIM XMS a(...)`
  new array storage classes alongside `VIRTUAL`. `EMS` uses the existing EMS-paged
  array allocator; `XMS` is routed through it as a working stand-in (observably
  identical — it is just where the storage lives) until the optimizer instance
  lands a true XMS-backed runtime. This is the language *surface* for the
  memory-handling work; the deeper runtime (true XMS, stack-allocation of small
  non-escaping locals via `$OPTIMIZE STACKALLOC`, heap/stack reuse) is the
  optimizer instance's lane. Gate: `LanguageFeature.XmsEmsArrays`.

- **From-end array index** — `arr(^n)` is the n-th element from the end (`^1` =
  last). The binder rewrites it to `arr(UBOUND(arr[,dim]) - n + 1)` — `UBOUND`
  folds to a constant for a static array and reads the descriptor for a dynamic
  one — and codegen substitutes the rewrite at the single index-emission point
  (`EmitInt16Argument`), so it works as both rvalue and lvalue and for every array
  class. Valid only as an array subscript (an error elsewhere). Gate:
  `LanguageFeature.FromEndIndex`.

- **Array initializer literals** — `DIM a%() = {10, 20, 30}` (auto-sized) or
  `DIM a%(n) = { ... }` (explicit size; unfilled trailing elements stay zero).
  Elements may be a value, an inclusive integer range `lo..hi` (expanded), or a
  spread `..arr` of a 1-D **static** array (its elements flattened in). The binder
  expands the literal to a flat value list, declares the static array, and lowers
  it to one element assignment each (spliced after the DIM, reusing the array
  element-store codegen). New `..` (`DotDot`) lexer token — the number lexer no
  longer eats `..` as a decimal point (`0..3` is `0`,`..`,`3`). Spread of a
  *dynamic* array (runtime size) and the `{^3}` count-from-end form are deferred.
  Gate: `LanguageFeature.ArrayInitializer`.

- **Bracketed collection / range literal** — `[v1, v2, lo..hi, ..arr]` is the same
  literal with square brackets instead of braces (same `CollectionElement` grammar
  and lowering), so `DIM a%() = [99..105]` fills the array like `{99..105}`. It also
  serves as a `FOR EACH` source. Gate: `LanguageFeature.CollectionLiteral`.

- **`FOR EACH v IN source … NEXT`** — desugared (parser-only) to a counted `FOR`:
  a `[lo..hi]` range literal becomes `FOR v = lo TO hi`; an array (`a()` / `a`)
  becomes `FOR <hidden> = LBOUND(a) TO UBOUND(a) : v = a(<hidden>) : …` (one
  dimension; the element is copied into `v` each iteration). The hidden index's name
  contains `$`, so it can never collide with a source identifier. `FOR EACH` is told
  apart from a loop variable literally named `each` by the token after it (the loop
  variable vs `=`). Gate: `LanguageFeature.ForEach`.

- **Nested local SUB/FUNCTION (stack capture)** — a `SUB`/`FUNCTION` may be defined
  inside another proc and reference the enclosing proc's scalar locals. Each nested
  proc is **lifted** to its own top-level proc (mangled `Outer$Inner`); a referenced
  outer local is **captured as a hidden BYREF parameter**, and every (scoped) call
  site passes that local by reference — so the capture is true stack capture with no
  heap, reusing the existing BYREF codegen. The binder discovers captures via a scope
  chain (`Scope.CaptureFrom`) while binding the lifted body, then appends the capture
  arguments to the recorded call sites. Nested procs are callable only from their
  enclosing proc. **This is the stack-based first stage**; escaping closures (a
  returned method-pointer that captures locals, needing hidden heap state) remain
  future work. Current limits: one level of nesting, scalar (non-array) captures.
  Gate: `LanguageFeature.NestedProcedures`.

- **Inline lambdas** — `FUNCTION(params) [AS type] => expr` is an
  anonymous function lifted to an anonymous top-level proc; the lambda *expression*
  evaluates to that proc's far code pointer (like `CODEPTR32`), assignable to a
  `???`/DWORD variable and invoked via `CALL DWORD`. In PB 3.6 the arrow `=>` is its
  own token, lexed distinctly from the `>=` comparison (older dialects keep the
  historical `=>`-as-`>=` tolerance), so the lambda forms are unambiguous: a terser
  **concise form** drops the `FUNCTION` keyword — `(a, b) => a + b` — and a single
  parameter may drop the parentheses entirely — `x => 2 * x`. `>=` always remains the
  comparison (`x >= 2 * x` compares). Parameter types, their
  `BYVAL`, and the result type may all be **omitted and inferred** from the delegate
  the lambda is bound to (an assignment or `DIM` target — see below); a bare `(a, b)
  => a + b` assigned to a `FUNCTION(LONG, LONG) AS LONG` delegate gets `BYVAL a AS
  LONG, BYVAL b AS LONG` and a `LONG` result. A lambda may **capture** the
  enclosing procedure's stack locals: each reference to an outer local is reached
  through the closure's environment pointer (the fat delegate value's second dword),
  and capture is **by reference** for a non-escaping closure — it reads and writes the
  live local, and mutations are shared with the defining scope. A lambda may capture the
  enclosing procedure's stack **locals** and its **BYVAL parameters** (both are
  BP-relative cells); a BYREF parameter (a pointer) and a STATIC/SHARED (reachable
  directly in DS) are not captured. There are two environment kinds, chosen by escape
  analysis:
    - **Stack closure (non-escaping)** — the default first stage: the environment *is*
      the enclosing frame, so the closure is valid while that frame is live (it may be
      passed to and called from another procedure, since the env travels with the
      value). Capture is **by reference**: the closure sees later mutations of the
      captured locals, and its own writes are visible back in the defining scope.
    - **Heap closure (escaping)** — when escape analysis finds the closure value can
      outlive the enclosing frame (it is returned as the enclosing FUNCTION's result,
      or stored in a SHARED/GLOBAL/STATIC; a closure whose definition cannot be proven
      to stay local is conservatively treated as escaping), the enclosing procedure
      allocates a small **heap environment record** (in the far array heap) at
      closure-creation and copies the captured values into it. The closure then reads
      that record through the same env far pointer. Capture is therefore **by value at
      creation** — a *snapshot*: mutations of the captured locals after the closure has
      been built are **not** shared (sharing across an escape would require boxing the
      captured local into the heap env on both the producer and the closure side —
      out of scope). Each closure value gets its own snapshot, so two escaping closures
      from one producer keep independent captures.

  A returned escaping closure stays valid after the producing frame is gone (it reads
  its heap snapshot, not the dead stack). Limitation: heap closure environments are
  **never freed** — PB has no GC and the array-heap bump allocator only reclaims its
  topmost block — so closures created in a long-running loop leak their env records.
  To call a lambda *with arguments* and a return value, assign it to a typed procedure
  pointer (below) rather than the untyped `CALL DWORD` path. Gate:
  `LanguageFeature.Lambdas`.

- **Typed procedure pointers / delegates (fat closures)** — `DIM f AS FUNCTION(types)
  AS type` / `DIM g AS SUB(types)` declares an 8-byte delegate value: a far code
  pointer followed by a far environment pointer (null for a non-capturing target).
  A lambda (`f = FUNCTION(BYVAL x AS LONG) AS LONG => x*x`) or a
  named procedure's address (`f = CODEPTR32(Triple&)`) is assignable to it, and it
  is **callable directly** — `PRINT f(7)`. Because the call site knows the declared
  parameter types it pushes each argument **BYVAL coerced to the exact width** and
  reads the result in the FUNCTION's return registers. This is the proper fix for
  the untyped-`CALL DWORD` width mismatch (a bare `CALL DWORD ptr(21)` pushed an
  INTEGER where the callee read a LONG → garbage). Lambda parameters bound to a
  pointer must be `BYVAL` and match arity. The delegate is plain storage, so it can
  be reassigned to switch the callee at run time. Storing one into a 4-byte
  `???`/DWORD keeps only the code half (the `CALL DWORD` interop path, env dropped).
  Gate: `LanguageFeature.ProcPointers`.

- **Named delegate types** — a `DECLARE`d (or defined) `SUB`/`FUNCTION` name doubles
  as a procedure-pointer *type*: `DECLARE FUNCTION Comparator(BYVAL a AS LONG, BYVAL
  b AS LONG) AS LONG` then `DIM cmp AS Comparator` declares a typed pointer carrying
  that prototype's signature, and `cmp = (a, b) => a - b` infers the lambda's types
  from it. The name is equally usable as a **parameter type** — `FUNCTION Apply&(BYVAL
  f AS Comparator, ...)` accepts a proc pointer type-safely and may invoke it (`f(x,
  y)`), giving statically-checked higher-order procedures. Forward references work
  (procedures are collected before bodies bind); an overloaded name is rejected as a
  delegate type (a delegate needs one signature). Gate: `LanguageFeature.NamedDelegates`.

## Optimizer soundness for new expression nodes

Adding an expression node (the ternary above, and the operators/initializers to
come) is only sound if every optimizer pass that reasons about reads, escapes or
purity accounts for the node's children. Rather than touch ~13 walkers per node,
there is one registration point — `AstQuery.Subexpressions(expr)` lists a node's
immediate child expressions — and the conservative passes fall back to it for any
node they do not model explicitly: `SsaForm` escapes every contained variable
(excluding the node from SSA/SCCP/dead-store), float demotion blocks contained
candidates, IPCP assumes a contained write, and the DEF SEG pruner treats a
contained PEEK as observing the segment. So a new expression node is sound by
default (merely unoptimized inside); each new node need only be added to
`Subexpressions`, bound, and emitted.

Beyond sound-by-default, the optimizer now actively optimizes the new constructs:

- **Shift/rotate operators** are pure integral `BinaryExpr`s, so they are already
  SSA-tracked; they are now recognized as pure by CSE (`IsPure`) and as
  value-exact by float demotion (`TreeIsValueExact`), so they participate in
  common-subexpression elimination and never block de-floating. `ConstantFolder`
  folds shift-*left* (`<<`/`<<<`) at compile time (it is width/sign-independent;
  the emitter wraps to the bound type). Shift-*right* and rotates stay runtime —
  their result depends on the operand width and signedness, which the type-less
  folder does not know, so folding them would risk a wrong value.
- **The ternary `IfExpr`** is now tracked through the whole SSA pipeline rather
  than excluded: `SsaForm` (escape analysis + `RecordUses`), `Sccp`
  (`TrackedReads`/`Substitute`) and `DeadStore` (seeded from `UseVersions`) all
  recurse its condition and both branches. This matters because escaping is a
  *global* property — without this, a single ternary use would disable SSA/SCCP
  for that variable everywhere, not just in the ternary. The emitter already
  folds proven-constant reads inside the ternary (each branch emits through
  `EmitExpression` → `TryEmitProvenConstant`), and a constant-condition ternary
  folds to its taken branch at compile time (`ConstantFolder` + the
  `TryEmitFolded` path), with the untaken branch never evaluated.
- **CSE/folding correctness** is gated the same way as the existing ops: shifts
  are pure and never trap, and the constant-condition ternary fold only takes the
  selected branch (preserving short-circuit and never evaluating a side-effecting
  untaken branch). Verified by `Pb36LanguageFeatureTests` running under the
  optimizer (on by default for pb36): constant folds, SSA-through-ternary
  consistency with dead-store, and a non-constant-param ternary whose store must
  survive.

## Implementation status (— first wave landed)

`--dialect pb36` exists and emits optimized code today:

- **P1 Runtime trimming** — implemented (`CodeGen/RuntimeTrimmer.cs`): a
  one-time probe emission maps every runtime label to its providing section
  and every section to its referenced labels; a reachability closure from the
  labels the user program references selects the minimal section set, emitted
  AFTER the user code (`DosRuntime.BindDeferred` pre-binds the label surface).
  The probe derives from the genuine emission, so the graph cannot drift.
- **P2 partially** — section-granular data (string console cells split from
  the 2 KiB descriptor table; per-subsystem data sections).
- **P4 heap demand** — unused string/array heap segments are not reserved
  (MZ MinAlloc): hello world drops from ~192 KiB resident to the single
  64 KiB main segment.
- **O1 constant folding** — pure integral expressions fold at the emitter,
  wrapped to the bound type (`CodeGenerator.WrapToType`), bit-equal to the
  runtime ALU result.
- **O4 subset** — `x * 2^n` (and `* 0` / `* 1`) lower to 8086-safe shifts
  with operand side effects preserved. Under `$ERROR OVERFLOW ON` the
  strength reducer backs off (a shift chain cannot raise the genuine `IMUL`'s
  error 6) so the checked multiply keeps its real instruction and `JNO` guard
  - oracle battery `tests/diff/DIFF41.BAS`. In the modular int16 path
  (`v% * c`) `$OPTIMIZE SPEED` widens the reduction past powers of two:
  two-bit multipliers `2^a+2^b` lower to `(v + v<<(a-b))<<b`, contiguous-run
  multipliers `2^a-2^b` to `(v<<(a-b) - v)<<b`, negatives via a trailing
  `NEG`, three-term multipliers keeping the compact `IMUL` - sound because the
  modular path only runs unchecked, so every chain reproduces the product's
  low 16 bits exactly (oracle battery `tests/diff/DIFF42.BAS`).
- **P7 trivial-I/O lowering** — implemented (`CodeGen/CodeGenerator.Trivial.cs`):
  programs whose only effects are PRINTing compile-time strings/integrals and
  END lower to a raw COM-style image (DOS/DOSBox load signature-less files as
  .COM regardless of extension): the whole output text - including PB number
  formatting, 14-column comma zones and CRLFs - is precomputed and written
  with one DOS call (AH=9 when '$'-free, else AH=40h), exit via INT 20h /
  AH=4Ch. Hello world: **25 bytes**, verified running in DOSBox.
- **O19 definite-assignment zero elision** — implemented for stack frames
  (`CanElideFrameZeroing`): a conservative straight-line prefix proof (whole
  variable assignments, FOR headers; aborts at calls/branches/labels reads of
  unassigned locals) drops the per-invocation `REP STOSW`, keeping individual
  zeroing only for dynamic-string handle slots; main frames (temps only)
  always qualify when no error handler exists. Array/ArrAlloc elision is
  roadmap (needs O16). Oracle battery: `tests/diff/DIFF22.BAS` (locals must
  read 0 / "" before assignment on every call, with and without elision).
- **O21 register parameters** (`$OPTIMIZE SPEED`, `OptRegParm`) — when the
  compiler owns every call site of a procedure (defined in a self-contained
  module, never address-taken via CODEPTR/`CALL DWORD`), its leading word-sized
  BYVAL scalar parameters are passed in registers (AX,DX,BX,CX) instead of on
  the stack, reusing the WATCALL lowering (see docs/LINKER.md). Caller and callee
  flip together, so behaviour is identical and the per-call push/pop traffic
  disappears. Disabled wholesale if any procedure address is taken; skipped when
  external units/libraries are linked (they may call with the stack convention)
  and for non-pb36 dialects (the pb35 golden output is never touched).
- **O22 dead procedure elimination** (`OptReachability`) — under `Optimize`, a whole
  program's entry point is its top-level code (the synthetic "main"); tracing the call
  graph from there (direct calls, CODEPTR/`CALL DWORD` references — recorded in
  `CallBindings` — and lambdas) marks every procedure that can actually run. Unreachable
  procedures are dropped. It is **transitive**: a procedure reached only from other dead
  procedures is itself dead. Only *fully-owned* procedures are dropped (`IsFullyOwned`:
  a nested procedure, or any procedure in a self-contained main) — an exported
  `$COMPILE UNIT` entry point, or a procedure a linked foreign object could call by name,
  is kept regardless. Soundness rests on `OptReachability.DescendantNodes` visiting every
  statement and expression by reflection (complete by construction, so no reference is ever
  missed). Unoptimized/pb35 output is unchanged (gated on `Optimize`). *Dead global data and
  the CODEPTR-to-dead-global cascade build on this reachability (next).*
- **O23 dead global / data tree-shaking** (`OptDeadGlobals`) — adds the DATA dimension to the
  tree-shaker. A fully-owned simple scalar module global that no reachable code ever **reads** is
  dead: its data slot and every pure store to it (`global = <pure rhs>`) contribute nothing.
  References are classified soundly — a global occurrence is a *read* unless it is exactly a
  top-level `AssignStmt` whose target is `NameExpr(global)`; every other form (INCR/SWAP, array
  index, BYREF arg, VARPTR/VARSEG, a dotted-name `MemberExpr`, any operand) keeps it live. A
  `CODEPTR(P)` that appears **only** as the RHS of a store to a dead global is not a live edge to
  `P`, so the dead-global set, the dead-store set and the live-procedure set are solved together to
  a **fixpoint** (excluding dead stores from the `OptReachability` walk): a method kept alive only
  by a never-read global pointer cascades to dead too. Hard conservative guards keep a global no
  matter what — address taken (VARPTR/VARSEG/STRPTR/…/32), SHARED/COMMON/exported, array/UDT/
  string/BCD/FIX, `DIM … AT`, a PB internal cell, or a store whose RHS could trap (a function call,
  or — under `$ERROR NUMERIC/OVERFLOW/BOUNDS` — arithmetic/an array read, since dropping it would
  skip the Error 6/9 trap). Restricted to a self-contained main (`Optimize && !unit && !linked`), so
  pb35/unoptimized output is byte-identical.
- **R3 subset — DWORD string copy**: the string runtime's literal/concat copy
  (`EmitRepMovsbWidened`) moves DWORDs plus a &lt;=3-byte tail under `$CPU
  80386` (~4x on long strings) instead of `REP MOVSB`; the copied bytes are
  identical (oracle battery `tests/diff/DIFF40.BAS`, a 386 string storm). The
  whole-TYPE/array block copies were already widened (below).
- **C1/R3 subset — block-move widening**: whole-TYPE copies (and LSET/BCD
  block moves) run word-wide (`REP MOVSW`, 8086-safe) under pb36 and
  DWORD-wide (`REP MOVSD`) under `$CPU 80386`, odd tails byte-copied; the 3.1
  whole-value TYPE compare runs `REPE CMPSW` for even sizes. Oracle battery:
  `tests/diff/DIFF23.BAS` (odd/even TYPE sizes, copy + compare).
- **O2 unreachable-statement elimination** — implemented
  (`CodeGen/OptPruner.cs`): statements after an unconditional transfer
  (GOTO/END/EXIT/RETURN/RESUME) drop until the next label; DATA/equates/
  DEFtype/metastatements survive (compile-time effects). Applied recursively
  through IF/SELECT/loop blocks before emission.
- **O7 small-trip unrolling** — implemented under `$OPTIMIZE SPEED`:
  constant-trip INTEGER FOR loops with at most 4 iterations and a small
  straight-line body (no jumps/exits/nested loops/counter writes) unroll
  completely; the counter slot ends on the increment-then-test final value
  (QUIRK 2.28, wrap included). Oracle battery: `tests/diff/DIFF26.BAS`.
- **O9 literal concat folding** — implemented: pure string concatenations
  (`+`/`&` over literals/equates) fold into one pooled literal at the emitter
  (and the `ConstantFolder` now folds `&` for string equates).
- **O10 DEF SEG coalescing** — implemented (`OptPruner`): a DEF SEG whose
  window to the next DEF SEG contains only provably segment-transparent
  statements drops; PEEK-family expressions, POKE/BLOAD/BSAVE/interrupts,
  inline asm, user calls and any control flow end the window conservatively.
- **O11 literal pool packing** — implemented (containment + suffix/prefix
  overlap): `"World!"` and `"lo, W"` share the bytes of `"Hello, World!"`.
  Sound because generated code only reads literals (StrMem copies/PrintStr).
- **O8 subset** — zero idiom: `XOR r,r` for constant zeros at expression
  positions (flag-dead by construction). In the modular int16 path, `v% +/- c`
  for a compile-time constant folds to one immediate `ADD AX,imm` (subtraction
  adds `-c`; `c - v` negates then adds), dropping the constant load and the
  push/pop around the second operand - unconditional, since it is both smaller
  and faster (oracle battery `tests/diff/DIFF43.BAS`). The general int16 binary
  path folds a constant operand the same way: `AND/OR/XOR AX,imm` for bitwise
  masks, `ADD/SUB AX,imm` (keeping the `JNO` overflow trap under `$ERROR
  OVERFLOW`), and `CMP AX,imm` for comparisons - the constant may sit on either
  side (commutative ops; an ordering compare with the constant on the left
  mirrors the operator), and the value is taken modulo 2^16, the same low word
  the register path would coerce into BX (oracle batteries
  `tests/diff/DIFF44.BAS` bitwise/compare, `tests/diff/DIFF45.BAS` checked
  add/sub overflow). A comparison against zero collapses further to `OR AX,AX`
  (two bytes, same ZF/SF; the cleared OF is harmless because the signed and
  unsigned conditions reduce to SF/CF tests when OF = 0). A `+/-1` add/subtract
  (modular or checked) folds to `INC`/`DEC AX` (one byte) - INC/DEC still set
  OF so the `JNO` overflow trap is preserved, and they leave CF alone, which
  the add/sub paths never read (oracle battery `tests/diff/DIFF46.BAS`). The
  32-bit (LONG/DWORD) binary path folds a constant the same way into immediate
  pair ops - `AND/OR/XOR` on the low word in AX and high word in DX, and
  `ADD AX,imm`/`ADC DX,imm` (`SUB`/`SBB`) keeping the `JNO` trap, and `=`/`<>`
  subtracting the halves to test for zero (against `0` the operand's own
  `AX|DX` already decides, so the subtract is skipped - the common `ptr& = 0`)
  - dropping the constant's CX:BX load and the push/pop dance (oracle battery
  `tests/diff/DIFF47.BAS`).
- **O15 subset — UDT copy/compare lowering** — the whole-TYPE block copy and
  `=`/`<>` compare are already lowered to word/dword-wide `REP MOVSW`/`MOVSD`
  and `REPE CMPSW` (the C1/R3 wide-op work). Added here: a self-copy
  (`rec = rec`, structurally identical non-string lvalue) is elided as a pure
  no-op, and a self-compare folds to its constant truth (`rec = rec` -> -1,
  `rec <> rec` -> 0; memcmp of identical bytes is always equal, NaN-immune).
  Field access is already a direct constant-offset memory access (zero-cost).
  Full scalar replacement / register-resident UDT fields await O5 register
  allocation. Oracle battery: `tests/diff/DIFF34.BAS`. Escape-blocked types
  (dynamic string handles) keep the real copy/compare.
- **O4 divide subset** — `x \ 2^n` and `x MOD 2^n` lower to shift/mask
  sequences with the PB truncation fix-up (signed forms bias by `2^n - 1`
  before the arithmetic shift; MOD reconstructs the dividend-signed remainder
  as `((x + b) AND mask) - b`), 8086-safe shift counts (CL beyond four 1-bit
  shifts, never the 186+ immediate form), DWORD forms unsigned (plain
  `SHR`/`AND`). Legal under every $ERROR mode - a positive constant divisor
  can neither raise error 11 nor overflow a quotient. Oracle battery:
  `tests/diff/DIFF27.BAS`.
- **O12 float demotion (first wave)** — implemented
  (`CodeGen/OptFloatDemotion.cs`): SINGLE/DOUBLE variables whose writes are
  FOR headers with foldable integral bounds (plus integral constant resets)
  and whose reads all sit in value-exact contexts (no `/`/`^`, no float
  literals, no calls over the value, no USING/WRITE#) silently re-type to
  INTEGER/LONG - the accidental-float counters of DOS-era code run on
  integer registers again. Range proofs respect SINGLE's 2^24 exact-integer
  bound; call arguments (BYREF), INPUT/READ/SWAP targets, INCR (unbounded),
  non-integral CASE comparisons and inline asm/indirect flow block or kill
  the pass. Oracle battery: `tests/diff/DIFF28.BAS` (demoted and blocked
  twins side by side).
- **O14 tail-call subset** — implemented in two shapes. (1) *Self-call*: a
  self-call in tail position (last statement of the body or of trailing
  IF/SELECT arm chains) rewrites its parameter slots in place and jumps back
  to the frame entry, re-zeroing locals exactly like a fresh invocation -
  recursion in constant stack space (60 000-deep tail recursion completes
  where the genuine compiler's default 2 KiB stack dies at ~170 frames).
  (2) *General (cross-procedure) tail call*: a SUB A whose last action is
  `CALL B(args)` (B another in-module SUB) tears down A's frame, lays B's
  whole call frame (return address + arguments) at A's caller's pre-call SP
  boundary, and `jmp`s B's entry - so B's own `RET nb` returns straight to
  A's caller, removing one frame + return per tail call (mutual recursion
  through two procs runs in constant stack). The teardown accounts for A's
  and B's argument-byte counts independently (B's return-address slot lands
  at `[BP+2+(na-nb)]`), so the convention's callee-cleans `RET n` discipline
  stays balanced even when A and B take different argument bytes. Conservative
  gates (both shapes): every parameter a small (≤4-byte) BYVAL non-float
  scalar, numeric-only locals (no string/FLEX cleanup pending), no ON ERROR,
  no GOSUB, a stack callee-cleans convention (not CDECL, not a register
  convention), no capturing-lambda env. The general shape additionally
  requires B to be a defined in-module SUB (a known local jump target) and is
  not applied to FUNCTIONs - a FUNCTION's result-load epilogue, and a
  discarded FUNCTION result's StrFree / FPU pop, must still run, so those
  fall back to an ordinary CALL. Oracle batteries: `tests/diff/DIFF29.BAS`
  (self-recursion + BYREF/blocked twins), `tests/diff/DIFF87.BAS` (mutual
  recursion, a forwarding call with a different argument count, and a
  deliberately non-tail call that stays an ordinary CALL).
- **O18 subset — interprocedural constant propagation** — implemented
  (`CodeGen/OptIpcp.cs`): a scalar parameter that receives the same
  compile-time constant at every call site and is never written (directly or
  via a BYREF pass to another proc, in statements or expressions) reads as
  that literal inside the callee - feeding O1 folding, O2 dead-code and O17
  branch elimination there. The call ABI is unchanged (the argument is still
  passed), so output is identical; only the callee body specializes. Disabled
  wholesale when any procedure address is taken (CODEPTR / CALL DWORD), whose
  indirect call could pass an unseen argument. Leaf-frame zeroing elision is
  O19; the internal register calling convention remains roadmap. Oracle
  battery: `tests/diff/DIFF38.BAS`.
- **O6 inlining subset** — implemented: a small **leaf** SUB/FUNCTION inlines as
  its body at every call site - the frame, CALL and RET overhead disappear and
  (when every call inlines) the procedure is reachability-purged from the image.
  BYVAL scalar arguments evaluate once into fresh per-inline frame temps (effects
  and order preserved); the body's statements emit with every read and write of a
  parameter, body local or the result variable remapped onto those temps (so two
  inlinings - or a self-mutating BYVAL param at two call sites - never collide),
  body locals start zeroed exactly like a real frame, and a FUNCTION's result is
  the value left in the result temp. Conservative leaf gate: BASIC convention only,
  not STATIC, no ON ERROR, no closure/capture, BYVAL scalar parameters only, and a
  body of at most a few plain scalar assignments and LOCAL declarations - no calls,
  loops, labels, GOTO/GOSUB/RETURN, EXIT, SELECT or nested procs (the trivial
  single-result-assignment FUNCTION is the fast path, emitting the expression
  straight into the registers with no result temp). The reachability purge
  (`OptInlining.FullyInlinedProcedures`) only fires for a self-contained main and
  bails the moment a procedure's address is taken (CODEPTR) or the program uses any
  error handling - either of which can force a real call that must keep the body.
  Anything uncertain falls back to the genuine call, so output is byte-identical.
  Oracle battery: `tests/diff/DIFF30.BAS` (mixed eligible/ineligible callees,
  side-effecting and nested arguments).
- **O16/O17 subset — check & branch elimination** — implemented: a constant
  IF/ELSEIF condition selects its arm at compile time and the dead arms are
  not emitted (SCCP-lite, cascading through the ELSEIF chain; the folder is
  pure so dropping the untaken arm is sound). Under `$ERROR BOUNDS ON`, an
  array access with a constant index provably inside the static DIM bounds
  drops its Error-9 check entirely (a check that *could* fire is kept, and a
  constant out-of-range index is already a genuine compile error). Oracle
  battery: `tests/diff/DIFF37.BAS`. Full SSA range-narrowing/GVN/LICM remain
  roadmap.
- **O17 SSA + SCCP mid-end** — implemented (`CodeGen/Ssa/`): a real
  static-single-assignment pipeline now runs between binder and emitter for
  structured bodies. `ControlFlowGraph` builds basic blocks over straight-line
  code, IF/ELSEIF/ELSE, and FOR / pre-test or infinite DO-WHILE/UNTIL loops
  (back-edge to the header, so loop phis form; the FOR counter is treated as an
  implicit write and never tracked), with EXIT SUB/FUNCTION/FOR/DO and END as
  region exits and EXIT/ITERATE wired to the enclosing loop. SELECT CASE is
  modeled conservatively as an opaque multi-way branch (every arm and the
  no-match path reachable, the subject and selector expressions recorded as
  reads) so SCCP/DSE analyze SELECT bodies instead of bailing; EXIT SELECT is
  wired to the merge. It still bails on post-test loops, GOTO/labels, GOSUB,
  ON ERROR or any construct it cannot model precisely - so every graph it
  produces is sound; the cyclic constant lattice converges because the lattice
  is monotone. `DominatorTree` computes immediate dominators
  (Cooper-Harvey-Kennedy) and dominance frontiers (Cytron); `SsaForm` places phi
  functions and renames every non-escaping integral scalar local/global into
  versioned values, mapping each read to the version that reaches it
  (variables that escape via a call BYREF, an address intrinsic or any opaque
  statement are conservatively dropped). `Sccp` then solves the constant lattice
  and block reachability together (Wegman-Zadeck): a branch whose condition
  folds constant lights only its taken edge, so phi merges ignore dead arms, and
  PB's zero-initialized locals make uninitialized reads provably zero. The
  arithmetic is delegated to the emitter's `ConstantFolder` (via leaf
  substitution) and every stored value is wrapped to its variable's type, so a
  proven constant equals the exact value the program computes. The emitter folds
  each proven read (`TryEmitProvenConstant`) - cross-block constant propagation
  the local folder cannot do - disabled under `$ERROR OVERFLOW/NUMERIC` (a
  folded constant would skip the runtime trap the real arithmetic must still
  raise). Oracle battery: `tests/diff/DIFF48.BAS` (and `DIFF49.BAS` for loops);
  unit coverage in `PowerBasic.Compiler.Tests/CodeGen/SsaTests.cs` (CFG,
  dominators/frontiers, SSA renaming, SCCP). This is the mid-end the deeper
  O16/GVN/LICM passes will build on.
- **O2 SSA dead-store elimination** — implemented (`CodeGen/Ssa/DeadStore.cs`):
  an aggressive mark-sweep over the SSA removes assignments to non-escaping
  tracked scalars whose version is never really read - either the value is dead
  outright, or SCCP already folded every read to a constant, so the store that
  produced it is now pointless. Liveness is seeded from real (unfolded) reads in
  statements that are not themselves removable and from branch conditions, then
  propagated through phi inputs and the right-hand sides of kept assignments, so
  a value kept alive only by a dead copy chain still dies. Only literal / equate
  / variable-copy right-hand sides qualify (they cannot trap and have no side
  effects, so dropping the store is unobservable); the emitter skips the dead
  statements. Composes with SCCP - `x% = 5 : PRINT x%` folds the print to 5 and
  then drops the assignment entirely. Oracle battery: `tests/diff/DIFF50.BAS`.
- **Promotion lowering (O12/O17 family)** — implemented: assignments of
  +,-,*/negate trees over 16-bit integral leaves into 16-bit integral
  targets run on the plain 16-bit ALU - the low bits of the exact x87
  result ARE the modular result at every depth, so the FPU round-trip the
  integral-promotion semantics would otherwise cost disappears; checked
  arithmetic stays integral in the binder and never reaches the lowering.

**Measured** (hello world, current runtime): pb35 **14 254 bytes** on disk /
~192 KiB resident → pb36 **25 bytes** (P7 fast path; 916 bytes via the general
trimmed path when a variable is involved) / 64 KiB resident, output verified

## What's left — the next optimizations (priority order)

The SSA mid-end (`CodeGen/Ssa/`: CFG → dominators/frontiers → SSA → SCCP) now
exists and SCCP / dead-store / dead-arm run on it. That unblocks the passes the
matrix still calls "subset" or "roadmap". Each builds on the SSA and must stay
byte-identical under the differential harness.

1. **O5 register allocation (the big speed win, partially landed).** Most locals
   are still stack cells. A real allocator keeps hot locals in registers across a
   region, using the SSA liveness:
   - *8086*: SI/DI are the only safe callee-stable GP registers (BX/CX/DX/AX are
     the evaluation/ABI scratch). **Done so far**: an SI/DI-clean FOR loop keeps
     its counter in SI *and* one hot 2-byte INTEGER accumulator in DI
     (`TryEmitForCounterInRegister` + the residency paths; battery DIFF52) - the
     per-iteration cell load/store of both disappears. A **nested** INTEGER loop
     under an SI-resident outer keeps *its* counter in DI instead of an accumulator
     (`TryEmitNestedForCounterInRegister`; battery DIFF90): both counters live in
     the two safe index registers, so neither spills to the stack. Two levels is the
     hard limit - SI and DI are the only callee-stable index registers, and they have
     no 8-bit halves, so a third level falls back to memory (`IsNestedRegisterableFor`
     keeps the nest leaf-only). The inner counter is flushed to its cell on loop exit,
     so a post-loop read sees the increment-then-test end value. A **DO/WHILE/LOOP** (no
     counter, so SI is free) likewise keeps one hot INTEGER accumulator in SI when its body is
     SI/DI-clean and its loop tests are SI-clean (`TryEmitDoLoopInRegister`; battery DIFF96) -
     the first generalization past the FOR-loop shape. The clean-body proof
     also accepts a **conditional** (`IF`/`ELSEIF`/`ELSE`) whose test is SI-clean and whose
     arms are themselves SI-clean (battery DIFF91) - the branch touches no GP register, so
     the counter in SI and any DI resident survive it, covering the common
     `FOR i … : IF c THEN s = s + i : NEXT` conditional-accumulate shape. Next: generalize
     beyond the FOR-loop shape to any hot non-escaping scalar whose live range is
     CALL/GOSUB-free (needs the interval liveness + interference graph).
   - *386/486*: a true win — six 32-bit GP registers (EAX-EDX, ESI, EDI) and
     EBX/ESI/EDI survive the internal ABI, so several hot LONG/INTEGER locals
     can live in registers at once. Pairs with the C1 DX:AX→EAX representation
     change.
   - **8-bit sub-register packing** (user-suggested): two non-escaping BYTE
     locals can share one 16-bit register's halves (e.g. `DL`/`DH`, `BL`/`BH`).
     Sound only when the allocator proves neither half is clobbered by an op
     that writes the whole 16-bit register (MUL/DIV/string ops touch AX; LEA/
     address math touches BX/SI/DI) — so AX's halves are poor candidates but
     BX/DX halves work for BYTE-heavy code. Best done inside the allocator,
     which already tracks per-register liveness, rather than as a separate pass.
   - Hard parts: spilling, the call ABI (calls clobber AX/BX/CX/DX), ON ERROR
     re-entry (a handler must see memory, not registers), and string/FLEX
     locals (handles the epilogue must free). Gate conservatively, like O5.
2. **O9 string-temp reuse (user-suggested).** `LEFT$/RIGHT$/MID$/`concat build a
   fresh heap temp per expression node today. With the SSA live ranges, a temp
   whose handle is dead can be reused for the next string temp instead of
   alloc/free per node, and a whole-string `MID$(s,i)` over a fixed buffer can
   reuse an existing local's storage. Cuts heap churn and the descriptor-table
   pressure. Lower risk than register allocation (no ABI concerns) - a good
   next target. ✅ first step done — **self-concat** `s$ = s$ + rhs` (append) *or*
   `s$ = lhs + s$` (prepend), where the other operand is a string literal or bare
   variable: s$'s handle is passed straight to `StrCat` (which copies both operands
   then frees them) and the result stored, dropping the redundant `StrDup` of s$ and
   the `StrAssign` free — one fewer full copy of the growing string per concat; pure
   codegen, no heap-routine change (`tests/diff/DIFF83.BAS`). ✅ second step done —
   **in-place literal self-append**: `s$ = s$ + "literal"` calls a new `rt_strcatlit` runtime
   routine that, when `s$` is the topmost heap block (and there is room under the `$STRING`
   cap), appends the literal bytes straight after `s$`'s data and grows the block in place,
   keeping the SAME handle — so an `O(n)` build loop is `O(n)` total instead of recopying the
   whole string each append. A literal needs no heap temp, so `s$` stays topmost across loop
   iterations; when `s$` is not topmost the routine falls back to the exact `StrMem`+`StrCat`
   path, so the result is always identical (`tests/diff/DIFF94.BAS`). ✅ third step done —
   **in-place variable self-append**: `s$ = s$ + v$` (`v$` a bare string variable) reads `v$`'s
   RAW handle (no `StrDup` temp, so `s$` stays topmost) and `rt_strcatvar` copies `v$`'s bytes
   heap-to-heap straight after `s$` when topmost, leaving `v$` intact; this also covers the
   self-double `s$ = s$ + s$` (the destination begins exactly where the source ends and `REP
   MOVSB` copies forward, so no byte is read after being overwritten), and falls back to
   `StrDup`+`StrCat` when `s$` is not topmost (`tests/diff/DIFF95.BAS`). ✅ fourth step done —
   **concat-chain dead-temp reuse**: in a left-associative chain `a$ + b$ + c$ = (a$ + b$) + c$`
   the inner concat produces a fresh, dead, topmost temp, so the next barrier-free operand
   (literal or variable) is appended to it in place (reusing `rt_strcatlit`/`rt_strcatvar`)
   instead of allocating a new `StrCat` result at every node — `O(n)` rather than `O(n²)`. Sound
   because the left is a temp (operands are only read as raw handles, never mutated); the runtime
   checks topmost and falls back to a copy otherwise (`tests/diff/DIFF97.BAS`). Still to do:
   dead-temp reuse across non-left-leaning / non-barrier-free concat shapes — needs SSA string
   live ranges.
3. **GVN / cross-block CSE.** ✅ first step done: `OptCommonSubexpr` now inherits its
   live value cache from before an `IF` into the (dominated) branches, so a value computed
   before the IF and recomputed inside a branch reloads the slot instead - the common
   `y*320+x` "compute then reuse in a branch" pattern. Gated on barrier-free conditions;
   byte-identical across the full harness. ✅ second step done (`RetainPastMerge`): the
   value now flows PAST the merge too - an inherited entry survives the join (instead of the
   whole cache being cleared) when no branch can have overwritten its inputs, so a value
   computed before an IF and reused *after* it reloads as well. Sound only when every branch
   is a flat, call-free straight line (`IsRetainableBranch`), so `CollectWrites` captures the
   exact write set; nested control or a call falls back to the conservative clear. Battery
   `tests/diff/DIFF67.BAS`. ✅ third step done: the same inherit + `RetainPastMerge` now also
   covers `SELECT CASE` joins (barrier-free subject and selectors), so a value flows into the
   arms and past the merge exactly as for an IF (`tests/diff/DIFF68.BAS`). ✅ fourth step
   done — **redundant-load elimination**: a repeated array-element read `a%(i%)` with no
   intervening write to the array or an index name reloads the first read's stashed value
   instead of re-reading memory. A safe array read (`CacheableArrayReadSymbol`: plain static,
   non HUGE/VIRTUAL/ABSOLUTE, 2-byte non-float element, simple name/literal indices) is now a
   cacheable CSE leaf keyed by array symbol + indices; any write to the array (any element),
   to an index, or a barrier invalidates it, a write to a *different* array keeps it live
   (`tests/diff/DIFF69.BAS`). Still to do: cross-block reuse through loop pre-headers.
4. **LICM (loop-invariant code motion).** ✅ done for **FOR and DO/WHILE loops**
   (`OptCommonSubexpr.AnalyzeLicm` + `CodeGenerator.EmitLicmPreheader`): a pure integer or
   modular-int16 subexpression in a flat loop body whose operands are all loop-invariant is
   hoisted to the preheader (computed once into a CSE frame slot via the existing
   DEFINE/reload mechanism) and reloaded each iteration. For a FOR loop "invariant" excludes
   the counter; a DO/WHILE loop has no counter (the analysis takes a nullable counter), so
   invariance is simply "not written in the body". Zero-trip-safe: only fires under
   `$OPTIMIZE SPEED` with no checked arithmetic / error handler, and `\`/`MOD` need a
   constant non-zero divisor, so no trap can fire in the preheader of a loop the body skips.
   Battery `tests/diff/DIFF66.BAS`; DO/WHILE covered by `DoLoopLicmTests`. Still to do:
   hoisting loads (needs alias/memory-SSA).
5. **Induction-variable strength reduction.** ✅ first shape done (O6b): a FOR loop whose
   single-statement body reads a static rank-1 INTEGER array by the loop counter
   (`x% = a%(i%)`) steps a DS-relative pointer (advanced by `elementSize*step` per
   iteration) instead of recomputing `base + (i-lbound)*size` - the hot path becomes a
   plain load with no per-iteration multiply. Gated very conservatively ($OPTIMIZE SPEED,
   constant STEP, no bounds/overflow/numeric checking, no aliasing/calls); byte-identical
   under the harness (battery `tests/diff/DIFF64.BAS`). Array STORES `a%(i%) = expr` also
   step the pointer now (the value lands in AX via the normal expression emitter, BX
   saved/restored across it, then `MOV [BX], AX`; `expr` must not reference the array, so
   there is no read-after-write through the stepped pointer; battery `DIFF65.BAS`). ✅ widened
   to **signed-LONG (4-byte) element arrays** for both read and store: the pointer steps by 4
   (two 8086-safe shift-by-1), the LONG value moves as DX:AX (battery `DIFF76.BAS`). Broader
   shapes (multiple arrays, non-counter index strides) remain.
6. **Copy propagation.** ✅ done (`CodeGen/OptCopyProp.cs`): a copy `y = x` (RHS a
   bare read of another tracked scalar of the same type) redirects every read of `y` to
   `x`'s cell and drops the copy; sound because the source must be assigned at most once
   (its cell is stable across the live range) and copy chains resolve to the root whose
   cell is actually written, so a removed copy never leaves a read on an unwritten cell.
   Composes with the SSA dead-store pass; byte-identical across the full harness.
7. **Reciprocal-multiply division by a constant.** `x \ 10`-style divides by a
   non-power-of-two constant become a multiply by a magic reciprocal plus a
   shift (the standard libdivide trick) - removes the runtime divide loop;
   pairs with the two-digit-table number formatter (R3).
8. **SELECT → jump table.** ✅ done (`CodeGenerator.TryEmitSelectJumpTable`): a 16-bit

   matching arm (CASE ELSE / no-match → the default). The same arm runs as the compare
   chain, so output is byte-identical (battery `tests/diff/DIFF62.BAS` under pb35 + pb36).
9. **O16 range/value lattice.** Extend SCCP to intervals/known-bits so types
   narrow (LONG that fits a BYTE runs as BYTE), `$ERROR` checks that provably
   can't fire are dropped, and more branches fold. The widest remaining mid-end.
   ✅ FOR-counter range lattice landed — registered by `EmitFor` (disposable scope,
   strict call-free counter-stable body) and applied to two of the three named uses:
   (a) **bounds-check elimination** — an array index that is a FOR counter, an affine
   counter expression (`a(i)`, `a(i±k)`), or the sum/difference of two range-known operands
   (`a(i+j)`, `a(i-j)` with `j` a derived range-known var) whose `[lo,hi]` lies inside the

   `x AND m` (m a non-negative constant) to `[0,m]` for any `x`, `x MOD k` (k constant) to

   scaled-down indexing `a(h AND mask)` / `a(i MOD n)` / `a(i \ 2)` drops its check too

   (c) **overflow-check elimination** — an INTEGER add/subtract over an affine counter
   range that stays inside 16 bits drops its Error-6 check under `$ERROR OVERFLOW ON`

   add/subtract whose exact value range stays inside the signed 32-bit range, dropping the
   32-bit `ADD/ADC` (`SUB/SBB`) Error-6 trap (`ProvablyNoOverflow32`; `tests/diff/DIFF87.BAS`);

## Architecture: a real optimization pipeline

Today statements are emitted directly to the assembler. pb36 inserts passes
between binder and emitter, each independently testable and switchable:

```
Binder → SSA construction → [SCCP const-prop] → [Range analysis / narrowing]
       → [GVN] → [Alias / memory SSA] → [LICM + sink] → [Strength reduce]
       → [Inline + IPCP] → [Unroll / Duff] → [If-convert] → [TCO]
       → [Register allocate + coalesce] → Emitter → [Peephole] → [Align]
       → [Runtime trim] → [Layout/BSS] → MZ/COM writer
```

The mid-level passes operate on an SSA form of the bound AST (every
assignment creates a version; PHIs at joins), which is what makes the
whole-program reasoning below tractable — the same representation family a
modern C++/LLVM pipeline uses, adapted to PB's wrap-and-error semantics.

`$OPTIMIZE OFF` bypasses the whole pipeline and reproduces today's codegen
exactly — that is the pb35-compatibility escape hatch and the differential
control: every pass must keep all suites byte-identical in *output*.

## Pillar 1 — size: pay only for what you use (Must)

- **P1 Runtime trimming.** The assembler knows every label and fixup; emit the
  runtime as a reachability-closed set seeded from the labels generated code
  actually references. Hello world keeps `rt_print_str`, `rt_print_nl`,
  `rt_exit` — not the string heap, file table, x87 formatter or array engine.
  Gate: per-golden size regression tests + all suites green.
- **P2 Data-on-demand.** String descriptor table, capture buffer, file table,
  REG block, DATA pool: emitted only when the trimmed runtime references them;
  sizes become tunables next to `$STRING` (descriptor count 512 → configurable).
- **P3 BSS instead of image bytes.** Zero-initialized data (variable slots,
  tables) moves behind the image via MZ `MinAlloc` instead of being written as
  zero bytes into the EXE — costless on disk, zeroed by the entry stub.
- **P4 Right-sized memory footprint.** The 64-KiB-main + 2×64-KiB-heap layout
  becomes demand-driven: no string usage → no string segment; `$STACK` honored
  downward; MinAlloc computed from actual use instead of the fixed worst case.
- **P5 `.COM` output (`$COMPILE COM`).** Tiny model (CS=DS=SS, org 100h, no
  header, no relocations) for utilities — a trimmed hello world is the DOS
  classic `MOV AH,9 / MOV DX,msg / INT 21h / RET` ≈ 25–40 bytes.
- **P6 Header & padding squeeze.** Minimal MZ header (0x20 paragraph-aligned),
  no padding between trimmed sections, literal deduplication (exists) extended
  to cross-procedure tail-merging of identical code sequences.
- **P7 Intrinsic lowering of trivial I/O.** Pattern-match whole-program shapes
  before runtime selection: a program that only PRINTs literals and ENDs
  lowers to the DOS string writer directly (`MOV AH,9 / MOV DX,msg / INT 21h`
  with a `$`-terminated literal, then `INT 21h`/4Ch) — no PrintStr, no column
  tracking, no capture buffer; with the direct-video option (R1) the same
  shape becomes a `REP MOVSW` into B800h. That is the "hello world in a few
  bytes" path: ≈ 12 bytes of code plus the text in a `.COM`. Falls back to
  the generic runtime the moment column state, zones, USING or non-literal
  operands are involved.

## Pillar 2 — speed: compiler optimizations (Must)

- **O1 Constant propagation + folding** beyond equates (the `ConstantFolder`
  exists): variable-free expressions, single-assignment locals within a basic
  block, `IF` with constant conditions drops dead arms (the preprocessor
  already drops `$IF` regions).
- **O2 Dead-code & dead-store elimination.** Unreachable statements after
  `GOTO`/`EXIT`/`END`, stores to never-read temporaries (the stack-machine
  pattern produces many provably dead push/pop pairs).
- **O3 Common subexpression elimination** within a basic block — the SVGA
  corpus recomputes `y * 320 + x`-style addresses constantly. *(implemented,
  `CodeGen/OptCommonSubexpr.cs`)* A pre-pass marks pure integer subexpression
  trees that recur within a straight-line run; the first occurrence computes
  into a frame slot, the rest reload it. Two emission contexts are cached
  separately: genuinely integer-typed trees (LONG/DWORD/comparison) through
  the normal emitter, and the SINGLE-promoted modular-int16 trees (the
  `y*320+x` graphics case, computed on the 16-bit ALU) through
  `EmitModularInt16`. Soundness: a reload only ever follows a define from
  identical inputs with no intervening write or barrier, so any $ERROR trap
  the define would raise fires exactly where the un-CSE'd first occurrence
  would. Block-local: every call/branch/label/loop/POKE clears the cache, a
  scalar write invalidates the slots reading it; modular CSE is disabled when
  `$ERROR NUMERIC/OVERFLOW/ALL` is active (matching the emission gate).
  Oracle battery: `tests/diff/DIFF33.BAS`.
- **O4 Strength reduction & LEA multiply-add.** `* 2^n` → `SHL`; `\ 2^n` →
  `SAR` with PB-truncation fix-up; `MOD 2^n` → `AND`; loop induction
  variables (array pointers stepped by element size instead of re-indexed
  each iteration). Integer **multiply-add fuses into `LEA`**: even on 8086,
  `a + b + const` is one `LEA AX,[BX+SI+const]`; under 386 the scaled forms
  make `x*2+y`, `x*4+y`, `x*8+y` single instructions and `x*3`, `x*5`, `x*9`
  one `LEA EAX,[EAX+EAX*n]` — chains cover `*320` (`LEA` ×5, `SHL` 6) and
  the corpus's `y*320+x` pixel addressing in two flag-free instructions that
  also leave the operands intact for CSE reuse.
- **O5 Register allocation.** Hot 16-bit locals cached in SI/DI (today every
  local is a memory cell); FOR counters live in a register across bodies free
  of CALL/GOSUB; spills proven safe by the corpus gate.
- **O6 Procedure inlining.** `$OPTIMIZE INLINE` plus automatic inlining of
  small leaf SUB/FUNCTIONs (no STATIC, no ON ERROR, no GOSUB): parameters map
  to argument places, eliminating frame setup and BYREF indirection.
- **O7 Loop unrolling.** Constant-trip FOR loops unroll fully below a size
  budget or by factor 2/4 (`$OPTIMIZE UNROLL n`). Variable-trip loops unroll
  with a **Duff's-device entry** in the emitted assembler: the body repeats N
  times and execution enters the chain at offset `count MOD N` via a computed
  jump, so no scalar prologue loop is needed — profitable for strided or
  structured bodies that `REP` string ops cannot express (planar masks,
  per-element transforms). Must preserve the PB increment-then-test counter
  end value (QUIRK 2.28) — the counter cell holds the same final (possibly
  wrapped) value afterwards.
- **O8 Peephole + jump threading.** `MOV AX,0` → `XOR AX,AX` (flags-dead),
  push/pop elision, store/reload forwarding, jump-to-jump collapse,
  fallthrough inversion, `CMP x,0` → `TEST x,x`.
- **O9 String-temp economy.** Reuse handles across expression nodes instead of
  alloc/free per node; fold literal concatenation runs at compile time
  (feeding the O11 overlap packer); `LEN`/`MID$`/`LEFT$` over fixed buffers
  become constants/direct moves.

- **O10 Redundant-statement elimination.** Statements with provably
  unobservable effects disappear:
  - **Empty loops**: a FOR/DO body with no statements and no volatile reads
    reduces to its closed-form effects — the counter cell is set directly to
    the final (possibly wrapped, QUIRK 2.28) value, and an `$ERROR NUMERIC`
    overflow still raises exactly when the looped original would have.
    CAUTION: DOS-era code uses empty loops as **delay loops** — the pass is
    part of `$OPTIMIZE SPEED` only, and any TIMER/INP/PEEK access or
    `$OPTIMIZE HOT` annotation (C5) in scope keeps the loop.
  - **DEF SEG coalescing**: consecutive `DEF SEG`s with no intervening
    PEEK/POKE/PEEK$/POKE$/BLOAD/BSAVE/CALL ABSOLUTE collapse to the last;
    `DEF SEG` to the value already in effect drops entirely. Inline asm or an
    external call in between blocks the pass (either may read `rt_defseg`).
  - **Bounds-check elimination**: under `$ERROR BOUNDS`, duplicate checks of
    the same index/position in a dominating position collapse to one,
    loop-invariant checks hoist out of the loop, and checks proven in-range
    from constant bounds vanish. A check that *can* fail is observable
    behavior (error 9) — it is only deduplicated or hoisted, never dropped.
- **O11 Static-string interning with overlap.** The literal pool already
  deduplicates exact matches; pb36 packs literals into a greedy shortest
  common superstring so substrings and overlapping parts share bytes
  ("Hello, World!" also serves "World!" and "lo, W") — lengths are supplied
  at each use site, so any slice of the pool is addressable. Sound only while
  the pool stays provably read-only: escape analysis disables packing for
  literals whose storage can leak through VARPTR/STRPTR on literal-backed
  values, inline asm referencing literal labels, or BYREF/external (unit)
  calls that could write through the reference — exactly the
  pointers/asm/external-ref-call hazards. Escaping literals fall back to
  private copies.
- **O12 Float demotion ("de-floating").** PB defaults bare variables to
  SINGLE, so most DOS-era counters and flags are floats by accident. When
  whole-program analysis proves a SINGLE/DOUBLE variable only ever holds
  integral values inside INTEGER/LONG range (assignments from integer
  expressions, `+`/`-`/`*` chains with integral operands, FOR counters with
  integral bounds/STEP), re-type it silently and run it on integer registers
  — no x87 traffic, no scratch round-trips. Soundness: any `/`, fractional
  literal, EXP/SIN-class intrinsic, VARPTR/SEG escape, BYREF pass to an
  unproven callee, or DATA/READ blocks the demotion; PRINT/STR$ formatting is
  safe by construction (integral floats already print without a decimal
  point — verified against genuine PBC, QUIRKS.md).
- **O13 Silent fixed-point arithmetic.** Where float values provably carry a
  constant scale (monetary `*0.25`/`*0.01`-step chains, FOR loops with
  fractional constant STEP, interpolation accumulators), compute in scaled
  LONG fixed-point and convert at the observation boundary (PRINT/STR$/
  store-to-escaping-location). Only applied when **bit-exactness is
  provable**: power-of-two scales are always exact; decimal scales only when
  every intermediate stays within the exact-integer range of the original
  float type, otherwise the rounding of the x87 original could differ by an
  ULP and leak into PRINT output. FOR with STEP 0.25 becomes an integer
  counter with 2-bit fraction — the classic DOS demo-effect win.
- **O14 Tail-call optimization.** A CALL in tail position (last statement
  before END SUB/FUNCTION or EXIT) reuses the frame: arguments are rewritten
  in place and the call becomes a `JMP`, turning self-recursion into loops
  (PB allows recursion — deep recursions stop eating stack). Blocked when
  the frame must outlive the call: string/FLEX locals pending release, a
  BYREF argument pointing into the current frame, armed local ON ERROR
  state, or GOSUB return addresses on the stack. GOSUB+RETURN pairs in tail
  position thread to plain jumps the same way.
- **O15 Zero-cost UDT abstractions.** Escape analysis (shared with O11)
  classifies TYPE/UNION values; non-escaping ones (no VARPTR/SEG, no whole
  BYREF to unproven callees, no inline-asm reference, not in arrays/files)
  get:
  - **Scalar replacement (SROA)**: the UDT decomposes into independent field
    variables that register-allocate like plain locals — field access costs
    exactly a scalar access, the abstraction is free.
  - **Copy elision**: whole-UDT assignment between non-escaping values
    becomes per-live-field moves or nothing at all (forwarded source);
    `REP MOVS` block copies remain only for escaping values.
  - **Compare lowering**: the 3.1 whole-value `=`/`<>` memcmp becomes
    field-wise compares with early-out, which then fold further when fields
    are constant.
  - UNIONs decompose only when a single member is ever touched; LSET, FIELD
    and file GET/PUT force materialization back to the packed layout.
- **O19 Definite-assignment zero elision.** PB guarantees LOCALs start at
  0 / empty; the runtime today pays a whole-frame `REP STOSW` per invocation.
  When every local is provably assigned before any use, the fill is
  unobservable and disappears. Safety rails: dynamic STRING/FLEX handle slots
  always stay zeroed (their first assignment frees the previous handle and the
  epilogue releases them), error-handler re-entry (`ON ERROR`/`RESUME`) blocks
  the proof, and types embedding string handles never qualify. The same idea
  extends to arrays and string buffers (skip ArrAlloc zero fill when a full
  initialization loop dominates every read) — roadmap, needs the loop-fill
  pattern proof from O16's range analysis.
- **O16 Whole-program assignment tracking & value-range analysis.** Every
  assignment to every variable is tracked over SSA (constants, intervals,
  known bits, congruences `a MOD n = k`); ranges propagate through
  arithmetic, FOR bounds, and branch conditions (a `IF x% > 0` refines the
  range on each arm). What the lattice buys:
  - **Range narrowing as far as possible**: a LONG whose every reaching value
    fits 0..255 runs as a BYTE; EXT/DOUBLE collapse to SINGLE when precision
    is provably unused; cascades feed O12/O13 (de-floating, fixed-point) and
    shrink data slots, frames and spill traffic. CAUTION — PB wraps silently:
    narrowing must prove that *intermediates*, not just stored values, stay
    in range under the original type's wrap behavior, otherwise a 16-bit wrap
    would appear where 32-bit code wrapped differently (observable). With
    `$ERROR NUMERIC ON` the proof must also preserve *which* statement
    overflows first.
  - **Constant folding on steroids**: a variable assigned once (or assigned
    equal constants on all paths) folds at every use; decidable comparisons
    (`x% < 300` when x% ∈ 0..255) fold their branches, cascading into O2
    dead-code removal.
  - **Check elision**: array/string bounds checks (O10) and `$ERROR
    NUMERIC/OVERFLOW` test sites vanish where the range proves them
    redundant — never where they could fire.
- **O17 The modern pass catalog, adapted to PB.** Everything a C++/LLVM
  mid-end does that pays off at this scale, with PB-specific legality rules:
  - **SCCP** (sparse conditional constant propagation): constants and
    reachability solved together — stronger than O1's local folding.
  - **GVN** (global value numbering) superseding block-local CSE, with
    redundant-load elimination across statements.
  - **Memory SSA / alias analysis**: loads and stores get dependency edges;
    PB's aliasing barriers are explicit and few — VARPTR/STRPTR escape,
    BYREF parameters, `@p` stores, PEEK/POKE after DEF SEG, inline asm,
    external unit calls — everything else is provably non-aliasing (better
    than C++: no arbitrary pointer arithmetic to spoil the analysis).
  - **LICM + sinking**: loop-invariant address computations and string-handle
    lookups hoist; rarely-used computations sink into their branch.
  - **Reassociation & if-conversion**: integer chains reassociate to expose
    LEA/CSE patterns; short branches become branchless `SETcc`/`SBB` idioms
    (no CMOV before Pentium Pro — stays inside the 486 gate).
  - **Loop rotation, induction-variable simplification, fusion** of adjacent
    same-trip loops over the same arrays.
  - **Iterative cleanup**: inline → SCCP → GVN → DCE rounds until fixpoint,
    LLVM-style.
- **O18 Interprocedural & ABI optimizations ("plus more").** PB-Compiler
  sees the whole program by default (units only via `$LINK` — and even then
  it links the objects itself), so it can go where separate compilation
  stops C++ compilers:
  - **IPCP**: constant arguments propagate into callees; dead parameters are
    dropped; SUBs called with one argument shape get specialized clones.
  - **Internal calling convention**: intra-module calls pass leading scalar
    args in registers (AX/BX/CX:DX) instead of pushed near pointers; BYREF
    collapses to direct access after inlining (zero-cost with O15).
  - **Leaf-frame elision**: SUBs without locals/strings/GOSUB skip the whole
    BP frame and the frame-zeroing `REP STOSW`.
  - **Segment-register allocation**: keep ES pinned to the string/array heap
    across statement runs instead of reloading per access — a register class
    LLVM never gets to play with.
  - Escape hatches stay absolute: any inline asm, CALL INTERRUPT, CODEPTR
    or external reference in scope pins the standard ABI and full frames.

- **O20 Algorithmic idiom replacement.** Beyond statement-level passes, the
  compiler recognizes whole algorithms and substitutes better ones: series
  summations fold to closed forms, constant fills become string ops, empty
  loops become their counter end value (first wave implemented, above);
  copy loops (`dst(i)=src(i)` over a range) lower to one `REP MOVSW` between
  distinct 16-bit arrays (near/far segment dance, counter end preserved);
  further idioms (MIN/MAX scan, bubble-sort shapes -> ARRAY SORT) remain
  roadmap - each gated on bit-identical observables and `$OPTIMIZE SPEED`.

## Pillar 3 — 386/486 code generation (Must)

Real mode on a 386+ executes 32-bit operations via operand/address-size
prefixes — no protected mode required. Gated by the existing `$CPU`
metastatement (`-G386`, new `-G486`):

- **C1 `$CPU 80386`: 32-bit registers wherever they pay.**
  - LONG/DWORD arithmetic in EAX/EDX: one `ADD EAX, [x]` replaces the 4-op
    DX:AX pair dance; `IMUL r32, r/m32, imm` replaces the LongMul runtime
    call; 32-bit `DIV`/`IDIV` replaces LongDiv/LongMod. ✅ **divide/modulo by a
    compile-time-constant divisor of magnitude >= 2** uses the exact hardware
    `IDIV`/`DIV` (truncate toward zero, remainder takes the dividend's sign =
    PB's `\`/`MOD`); the `>= 2` gate rules out the divide-by-zero and `MININT \ -1`
    traps, so the runtime path is dropped only where it can't trap. Battery
    `tests/diff/DIFF71.BAS`. (Variable divisors still use LongDiv/LongMod.)
  - QUAD in EDX:EAX pairs (add/sub/cmp, shifts via `SHLD`/`SHRD`) instead of
    x87 round-trips where profitable. ✅ **64-bit bitwise AND/OR/XOR/EQV/IMP**
    (`EmitQuad386Bitwise`) run inline as two 32-bit halves in EAX instead of the
    runtime `QuadAnd/..` call (bitwise can't trap); battery `tests/diff/DIFF72.BAS`.
    ✅ **64-bit SHIFT LEFT/RIGHT** by a constant count 1..31 collapse the per-bit
    loop to `SHLD`/`SHRD` across the dword halves (EAX/EDX only); counts ≥ 32 and
    rotates stay on the loop; battery `tests/diff/DIFF73.BAS`. (QUAD *arithmetic*
    add/sub/mul stay on the x87 — they match PBC's lossy >2^53 behaviour.)
  - ✅ **32-bit SHIFT/ROTATE collapse** (`EmitShiftRotate`): a LONG `SHIFT`/`ROTATE`
    statement with a compile-time-constant count in 1..31 becomes a single
    `SHL/SHR/ROL/ROR dword [cell], imm8` instead of the CX-times per-word
    RCL/RCR loop. Constant 1..31 only (the 386 masks the count to 5 bits, so
    `>= 32`/runtime counts stay on the loop); `SHIFT RIGHT` stays logical.
    Battery `tests/diff/DIFF70.BAS` (byte-identical to genuine PBC 3.50, which
    accepts `$CPU 80386`).
  - `MOVZX`/`MOVSX` for BYTE/WORD widening (kills the `XOR AH`/`CWD` chains);
    `SETcc` for relational results (kills the branchy −1/0 sequences).
  - Scaled `LEA` for array addressing — base + index*size in one instruction.
  - **DWORD-wide block primitives**: `REP MOVSD`/`STOSD`/`CMPSD` for memory
    fills, copies, UDT assignment/SWAP/compare, string assigns, array zeroing
    and the BeginFrame zero-fill — misaligned head/tail bytes handled, ≈4× on
    (✅ `REP STOSD` ERASE static-array zero-fill `tests/diff/DIFF74.BAS`; ✅ `REP
    STOSD` constant FOR-loop array fill — 16-bit value broadcast into both EAX
    halves — `tests/diff/DIFF75.BAS`)
    fills and copies.
- **C2 NEW `$CPU 80486` gate** (new `LanguageFeature.Cpu486`, `-G486`):
  - `BSWAP` for endian flips (MKx$/CVx big-endian helpers, graphics masks);
    `XADD`/`CMPXCHG` exposed to inline-asm authors.
  - **Alignment-driven layout**: DWORD-align hot data slots, align loop heads
    and procedure entries to 16 bytes (486 cache lines) — misaligned DWORD
    access costs extra cycles on the 486.
  - Instruction selection tuned to the 486's 1-cycle simple ops: prefer
    `MOV/ADD/INC` chains over microcoded instructions (`LOOP` → `DEC CX/JNZ`,
    avoid `XLAT`/`ENTER`/`LEAVE`) — partially beneficial on the 386 too.
- **C3 x87 scheduling.** Keep loop-invariant constants resident on the FPU
  stack across unrolled bodies; avoid `FSTSW/SAHF` stalls where comparisons
  can run on pre-truncated integer values.

## Pillar 4 — runtime speed: drawing, text, strings (Should)

- **R1 Fast text output.** A direct-video `PRINT` path (B800h `REP MOVSW` with
  attribute bytes, software cursor, `REP MOVSD` scrolling under 386) — which
  *also* closes the documented divergence from genuine PB (QUIRKS: real PB
  prints straight to video memory). `STDOUT`/`PRINT #` keep the DOS-handle
  path; a `$OPTION` selects the console strategy so the differential harness
  keeps its file-based comparisons.
- **R2 Fast graphics primitives.** Mode 13h pixel spans as `REP STOSB`
  (`STOSD` under 386), HLINE/box fills, run-sliced Bresenham lines, planar
  EGA/VGA writes batched per plane (map mask set once per span, not per
  pixel) — feeding LINE/CIRCLE/PSET/PAINT and new blit-style primitives.
- **R3 String engine.** DWORD-wide compare/copy/fill inside
  StrCat/StrCmp/StrFill; heap free-lists to avoid compaction storms;
  two-digit-table number formatting (halves the divide-by-10 loop for
  PRINT-heavy code).
- **R4 More inline-asm intrinsics.** `! MEMCPY dst, src, n`, `! MEMSET`,
  `! ZERO var`, `! BSWAP var` (486-gated), plus named access to the runtime's
  string-manager ABI (GetStrLen etc., see DIALECTS.md) and the new fast
  primitives — so hand-tuned corpus code can stay in BASIC.

## Should (rest)

- **S1 `$OPTIMIZE SPEED|SIZE|OFF` semantics** selecting pass sets (SIZE favors
  runtime calls over inlined sequences; SPEED the opposite).
- **S2 Finish the deferred 3.5 wave behind pb36 first**: QUAD `\`/`MOD`/
  bitwise, BCD/FIX arithmetic, REDIM PRESERVE codegen, HUGE/VIRTUAL (EMS)
  arrays — completion items piloted here before graduating to pb35
  conformance.
- **S3 Link-time tail merging** across procedures and the runtime.

## Could

- **C4 Multi-segment code** (`$CODE SEG`) lifting the 64 KiB guard (QUIRK 2.8).
- **C5 Profile hints**: `$OPTIMIZE HOT label` forcing alignment/unrolling of
  marked loops.
- **C6 UMB/XMS awareness** for the array heap (frees conventional memory).
- **C7 Pointer-arithmetic sugar** (`p + n` scaling by the target size).

## Won't (out of scope for 3.6)

- Protected mode/DPMI, Windows targets (REQUIREMENTS W1).
- Pentium-specific scheduling (U/V pairing, AGI avoidance) — nothing past the
  486 gate.
- Source-level incompatibilities with 3.5 — pb36 never *removes* or changes
  the meaning of an accepted 3.5 construct.

## Verification strategy

1. Every pass and fast path lands behind `--dialect pb36` (or
   `$OPTIMIZE`/`$CPU`) and runs the **complete existing gate**: full NUnit
   suite, 17 goldens, TESTLIB batteries, all differential batteries — outputs
   stay byte-identical to genuine PBC 3.50, because optimizations may change
   time, size and memory only. `$OPTIMIZE OFF` must reproduce today's images
   bit-for-bit.
2. **Size gates**: per-golden EXE-size budgets become regression tests (hello
   world ≤ 512 bytes, …); resident-memory checks scripted via DOSBox `MEM`.
3. **Speed gates**: cycle batteries (TIMER-bracketed fills, loops, PRINT
   storms) in the `Performance` category — advisory in CI, never
   merge-blocking (house rule).
4. **CPU gates**: 386/486 batteries run with DOSBox `cputype=386/486`, plus a
   guard battery proving 8086-mode images contain no gated opcodes (the
   assembler knows per-instruction CPU levels).
5. New surface (R4 intrinsics, S2 completions) gets NUnit + golden batteries;
   where genuine PB has the feature, differential batteries pin the behavior.
6. **Elimination-pass safety batteries**: empty-loop removal is pinned by
   counter-end-value and `$ERROR NUMERIC` batteries (the closed-form result
   must equal the looped result, including wrap); DEF SEG coalescing by
   PEEK/POKE interleavings; bounds-check passes by error-9 batteries; O11
   interning by a battery that takes STRPTR of literal-backed strings and
   mutates via MID$ — the packer must have backed off for those literals.
7. **Re-typing safety batteries**: O12/O13 are pinned by PRINT/STR$
   formatting storms over demoted variables (must match the x87 originals
   byte-for-byte, incl. the integral-float no-decimal-point rule), boundary
   values at the INTEGER/LONG demotion limits, and ULP probes for fixed-point
   scales; O14 by deep-recursion stack-depth tests plus ON ERROR/string-local
   blockers; O15 by UDT batteries mixing escaping and non-escaping values
   (VARPTR'd twin must stay packed while the SROA'd twin behaves identically).
8. **Range-analysis batteries** (O16-O18): wrap-semantics probes at every
   narrowing boundary (values driven exactly to ±1 of each proof limit; the
   narrowed program must wrap/raise exactly like the wide original under both
   `$ERROR NUMERIC` settings), alias stress tests (VARPTR/`@p`/POKE
   interleavings must block the load elimination they touch), and IPO twins
   (a SUB called both internally and via CODEPTR must keep its standard-ABI
   entry while the specialized clone serves the direct calls).
