# PB 3.6 — an envisioned successor dialect

Design sketch for a hypothetical "PowerBASIC 3.6": what the next DOS release
*could* have looked like, implemented as `--dialect pb36` on top of PB-Compiler.

**Mission: a richer language, blazingly fast and lean.** PB 3.6 is two distinct
things, and the distinction matters: (1) **the dialect** is a *language-extension*
successor — it adds real new syntax and syntactic sugar (object-model `TYPE`s with
methods/properties, nullable `?` types, generics, SIMD and up-to-512-bit wide-int
types, string interpolation, `YIELD` coroutines, bit-fields, and more); and (2) it
ships **the heavy optimizer on by default** — aggressive compiler optimizations,
386/486-aware code generation with 32-bit registers, DWORD-wide memory and video
primitives, and a runtime paid for strictly by use (a hello world down to mere
bytes). Crucially, that optimizer is a **separate, dialect-agnostic axis** (see
"The optimizer is dialect-agnostic" below): it is *available to every dialect* and
merely *defaults on* for pb36 — it is not what makes pb36 pb36; the new language is.

Guiding rule: **pb36 is a strict superset of pb35** — any source that compiles
under pb35 compiles under pb36 with *byte-identical observable behavior* (the
differential harness against genuine PBC 3.50 must stay green when run through
pb36); pb36 only *adds* opt-in language surface and, by default, changes time,
size and memory. Programs that use no pb36 syntax behave identically.

Requirements use MoSCoW; each item names its verification gate.

## Natural type-name aliases

pb36 adds modern, explicit-width spellings of the existing scalar types so the language reads more
naturally (gate: `LanguageFeature.TypeAliases`, pb36-only, parsed only in type position so they never
clash with identifiers). **The classic widths are preserved** — `INTEGER` stays 16-bit and `LONG`
32-bit — so the differential harness (which runs the pb35 batteries through pb36) is untouched; the
aliases are alternative names, not a redefinition. The wide tiers mirror `QUAD`/`QWORD` with
`D`/`Q`/`O` = double/quad/octa prefixes.

| bits | signed (friendly / explicit) | unsigned (friendly / explicit) | underlying type |
|------|------------------------------|--------------------------------|-----------------|
| 8    | `SBYTE` / `INT8`            | `BYTE` / `UINT8`               | `SByte` (int8) / `Byte` (uint8) |
| 16   | `SHORT` / `INT16` = `INTEGER` | `WORD` / `UINT16`              | `Integer` (int16), `Word` (uint16) |
| 32   | `INT32` = `LONG`             | `DWORD` / `UINT32`             | `Long` (int32), `Dword` (uint32) |
| 64   | `QUAD` / `INT64`            | `QWORD` / `UINT64`            | `Quad` (int64) / `QWord` (uint64) |
| 128  | `DQUAD` / `INT128`         | `DQWORD` / `UINT128`           | `Int128` / `UInt128` |
| 256  | `QQUAD` / `INT256`         | `QQWORD` / `UINT256`           | `Int256` / `UInt256` |
| 512  | `OQUAD` / `INT512`        | `OWORD` / `UINT512`            | `Int512` / `UInt512` |

`SBYTE`/`INT8` is a `ScalarType(SByte, 1, signed)` and `QWORD`/`UINT64` a `ScalarType(QWord, 8,
unsigned)` — the two scalars classic PowerBASIC lacked (it has unsigned `Byte`/`Word`/`Dword` and
signed `Integer`/`Long`/`Quad`). Signed-byte loads sign-extend (`CBW`) where `Byte` zero-extends, the
constant folder wraps to `sbyte`, and the binder ranks `QWord` as a 64-bit type so it dominates a
narrower signed operand (keeping 64-bit arithmetic). Verified by execution: signed wrap (`127+1` =
−128), sign-extension on widening, signed compare, and `QWord` sums beyond 2³² (`4000000000 +
290000000` = `4290000000`). Unsigned-64 values above 2⁶³ print via the signed-`Fild` formatter (the
same limitation as the wide-int decimal printer) — a follow-up.

### MMX / SSE2 / AVX / AVX-512 SIMD intrinsics (inline asm)

The assembler and inline-asm parser support the **MMX** (Pentium MMX, 64-bit `MM0..MM7`),
**SSE2** (128-bit `XMM0..XMM7`), **AVX** (256-bit `YMM0..YMM7`, VEX-encoded) and **AVX-512**
(512-bit `ZMM0..ZMM7`, EVEX-encoded) integer-SIMD instruction sets, so a program can hand-vectorise
with `!` statements: `MOVD`/`MOVQ`, `MOVDQA`/`MOVDQU` and the VEX/EVEX `VMOVDQA`/`VMOVDQU` (load/store
between an MMX/XMM/YMM/ZMM register, a GP register, or memory), packed `PADDB/W/D`(`/Q`) ·
`PSUBB/W/D`(`/Q`) (and saturating `PADDSW`/`PADDUSW`/`PSUBSW`/`PSUBUSW`), `PMULLW`/`PMULHW`,
`PAND`/`PANDN`/`POR`/`PXOR`, the packed compares `PCMPEQB/W/D` and `PCMPGTB/W/D`, the shifts
`PSLLW/D/Q` · `PSRLW/D/Q` · `PSRAW/D` (by a register or an immediate count), the pack/unpack family,
and `EMMS`.

- The **same MMX/SSE2 mnemonic** assembles to the MMX form for an `MM` operand or the 66-prefixed
  SSE2 form for an `XMM` operand — `! PADDW MM0, MM1` vs `! PADDW XMM0, XMM1`.
- The **AVX / AVX-512** forms are the three-operand `V`-mnemonics (`! VPADDW YMM0, YMM1, YMM2`),
  encoded with the 2-byte **VEX** (`C5`) prefix for `XMM`/`YMM` (128/256-bit) or the 4-byte **EVEX**
  (`62`) prefix for `ZMM` (512-bit) — selected automatically by the operand register class.

So the inline assembler scales 4 → 8 → 16 → 32 lanes by register choice (`MM` → `XMM` → `YMM` → `ZMM`).
Only MMX executes under DOSBox; the XMM/YMM/ZMM encodings are verified by assembler unit tests against
hand-computed VEX/EVEX opcodes, and the MMX path is execution-verified.

```basic
DIM a AS DWORD, b AS DWORD, c AS DWORD   ' two packed 16-bit lanes each
a = 1 + 2 * 65536 : b = 10 + 20 * 65536
! MOVD MM0, a
! MOVD MM1, b
! PADDW MM0, MM1                          ' lanes: 1+10, 2+20
! MOVD c, MM0
! EMMS                                    ' release the MMX/x87 state before any float use
' c now holds 11 and 22 in its two words
```

A variable named in an inline-asm body is treated as live by the optimizer (its data
slot and stores survive), so MMX intrinsics work with the optimizer on. MMX executes
under DOSBox, so these are verified by execution + assembler encoding unit tests (genuine
PBC 3.50 has no MMX, so it is not a differential oracle).

### `$CPU` feature flags

`$CPU 80586 [MMX] [SSE] [AVX] [AVX512] [AES]` declares the target microarchitecture floor
(`Cpu586`) and the SIMD extensions the program may assume. The optimizer's auto-vectoriser
emits the widest width the requested feature set allows and falls back to a narrower one (or
scalar) otherwise. The flags are off by default, so no existing program emits SIMD; genuine
PBC 3.50 predates `$CPU 80586`, so a program using it is verified by execution, not the oracle.

### Auto-vectorisation (R4)

Under `$OPTIMIZE SPEED` with `$CPU 80586 MMX`, a constant-trip loop of the shape

```basic
FOR i = lo TO hi : c(i) = a(i) OP b(i) : NEXT     ' OP is + - AND OR XOR *
```

over rank-1 static **2-byte-element** arrays is **auto-vectorised**, processing as many lanes per
iteration as the **widest available vector register** allows — selected by the `$CPU 80586` feature:

| feature | register | width | lanes | encoding |
| --- | --- | --- | --- | --- |
| `MMX` | `MM0` | 64-bit | 4 | legacy `0F` (+`EMMS`) |
| `SSE2` | `XMM0` | 128-bit | 8 | `66 0F` |
| `AVX2` | `YMM0` | 256-bit | 16 | 2-byte VEX `C5` |
| `AVX512` | `ZMM0` | 512-bit | 32 | 4-byte EVEX `62` |

The loop body becomes `load a[i..]` · `vec = a OP b[i..]` · `store c[i..]`, stepping three pointers by
the vector width; MMX/SSE2 use the 2-operand `Pxxx` (dest = dest OP src), AVX/AVX-512 the 3-operand
`VPxxx` (dest = src1 OP src2). A fully-unrolled scalar tail handles the last `n MOD lanes` elements,
and the counter is left at its `FOR` end value. Each operation is **wrap-correct per 16-bit lane**
(`PADDW`/`PSUBW`/`PAND`/`POR`/`PXOR`/`PMULLW` all wrap mod 2¹⁶ exactly as the scalar `INTEGER`/`WORD`
ALU would), so the vectorised result is **byte-identical** to the scalar loop. The 4-lane MMX path is
verified by execution in DOSBox (`c(i)=a(i)+b(i)`/`-`/`*` round trips match the scalar output); the
8/16/32-lane XMM/YMM/ZMM paths are encoding-verified (DOSBox runs no SSE2/AVX). Gated off when `$ERROR`
checking is active or `SI`/`DI` are register-resident; loops with fewer than 8 trips stay scalar. A
broader pattern set (reductions, `a(i) OP scalar`) builds on this same recogniser.

## The optimizer is dialect-agnostic

The optimizer is *orthogonal* to the dialect: pb36's new **language** (the syntax
above) and the **optimizer** are independent axes that merely happen to ship
together. The optimizer lives between the binder and the emitter, operating on the
bound `SemanticModel` (the shared intermediate representation every dialect
produces), and it reads that model's *per-dialect* types, wrap rules and semantics.
So it preserves observable behavior for every dialect, not just PB. The master gate
is `CodeGenerator.Optimize` (a settable property the driver wires to `--optimize`;
it merely *defaults on* for pb36 — `model.Dialect == Dialect.Pb36`), and
`--no-optimize` is the pb35-faithful escape hatch. Even the *lean-output* features
(P7 raw-COM lowering, P1 runtime trimming, P3 BSS) and float demotion are gated on
`Optimize`, not the dialect, so a QB or TB program compiled with `--optimize` also
shrinks to a trimmed image - we have full control over the executable layout and
type (EXE/COM) for any dialect. Verified: with the optimizer forced on for *every*
dialect, all differential batteries (QB 1.0-4.5, PDS 7.0/7.1, TB 1.0/1.1, PB
2.x/3.0/3.5) stay byte-identical to their genuine compilers - the complete chain
(expression folding, SSA/SCCP/DSE, strength reduction, register allocation, float
demotion, lean output) is dialect-agnostic. So pb36 is **not** "the optimizing
dialect": optimization is available to all dialects; pb36 is the dialect that adds
the new *language*, with optimization simply preset on.

**Why pb36 is kept as its own dialect (future work).** It is reserved as the
home for features that would make it a genuinely new language rather than a flag:
`VAR`/`AUTO` type inference with fused declare-and-initialize, lambdas and
expression-bodied members (VB.NET-style), EMS/XMS-backed heaps that truly use
more than 1 MB, a deterministic reference-counting GC (C++-style, not a
stop-the-world collector), and additional data types where feasible. The first
of these have started landing (see *New syntax* below); the rest remain future
work, and the dialect slot stays so that work has somewhere to land.

## New syntax (pb36-only language features)

These constructs compile only under `--dialect pb36`; every one is rejected
below 3.6 with the standard `requires PowerBASIC 3.6` gate, and none changes the
meaning of any pb35 program (the superset guarantee holds). Each is sugar that
desugars to a construct the binder/codegen already handle, so it shares the same
verified runtime paths.

- **Expression-bodied FUNCTION** — `FUNCTION F(...) [AS T] = expression`
  declares a function whose whole body is one result expression, mirroring
  `DEF FN`'s `= expr` form for the modern `FUNCTION` syntax. It desugars in the
  parser to a single `FUNCTION = expression` result assignment, so the existing
  function-result codegen carries it unchanged. Gate:
  `LanguageFeature.ExpressionBodiedProc`; coverage in
  `ParserDeclarationTests`, `DialectGateTests`, and the DOSBox battery
  `Pb36LanguageFeatureTests`.

- **Compound assignment operators** — `target OP= value` for
  `+= -= *= /= \= ^= &=`, e.g. `n% += 1`, `s$ &= text$`. The parser desugars
  `target OP= value` to `target = target OP value` (the lvalue node is reused in
  both the read and write position, which is structurally what the operator
  means), so the existing assignment/binary codegen carries it unchanged. Gate:
  `LanguageFeature.CompoundAssignment`.

- **DIM with initializer (fused declare-and-initialize)** —
  `DIM x = value` infers the variable's type from the initializer;
  `DIM x AS type = value` uses the explicit type. Works for procedure locals and
  module/main globals. The binder binds the initializer (so its type is known),
  declares the variable with the inferred or explicit type, and records a real
  assignment which a post-bind splice pass inserts immediately after the DIM in
  the executable stream. So codegen and *every* optimizer pass (SSA, float
  demotion, dead-store, …) see an ordinary declaration-then-assignment pair —
  there are no hidden writes, which keeps the dataflow analyses sound (e.g. a
  fractional initializer correctly blocks float demotion). Inference picks a type
  wide enough for the initializer (a literal like `100000` infers LONG, not
  INTEGER). Gate: `LanguageFeature.DimInitializer`.

- **Short-circuit ternary `IF()`** — `IF(condition, whenTrue, whenFalse)` as an
  expression (VB.NET-style `If` operator). Only the selected branch is evaluated
  at runtime: codegen emits a real branch (reusing the IF/loop condition test),
  so a side-effecting or trapping untaken branch is skipped (e.g.
  `IF(x = 0, 42, 100 \ x)` never divides by zero). The result type is the common
  type of the two branches (both numeric → the wider; both string → STRING;
  mixing the two is an error). `IF` is a reserved keyword, so intercepting `IF(`
  in expression position shadows nothing. Gate: `LanguageFeature.TernaryIf`.
  Implemented as a new `IfExpr` node registered in `AstQuery.Subexpressions`, so
  the optimizer's conservative walkers handle it soundly (see below).

- **Short-circuit boolean operators `ANDALSO` / `ORELSE`** — VB.NET-style: unlike
  PB's bitwise `AND`/`OR`, they stop once the result is known. They lower in the
  parser to the ternary — `a ANDALSO b` → `IF(a, b <> 0, 0)` (b skipped when a is
  false), `a ORELSE b` → `IF(a, -1, b <> 0)` (b skipped when a is true) — so they
  reuse the ternary's short-circuit codegen and stay sound in the optimizer for
  free, and the result is the normalized PB truth value (-1 / 0). `ANDALSO` sits
  at `AND` precedence, `ORELSE` at `OR`. Gate: `LanguageFeature.ShortCircuitOps`.

- **Object initializer** — `DIM p = NEW Udt { .field = value, ... }` (and
  `DIM p AS Udt = NEW Udt { ... }`) declares `p` as the UDT and initializes the
  listed fields; fields left out keep their zero-initialized value. The binder
  lowers it to one `p.field = value` assignment per listed field (spliced after
  the DIM like any DIM initializer), so it reuses the existing UDT field-assignment
  codegen and the `NEW` node never reaches the emitter. Valid only as a DIM
  initializer (used elsewhere it is an error). Adds `{`/`}` lexer tokens. Gate:
  `LanguageFeature.ObjectInitializer`.

- **SUB/FUNCTION overloading** — several SUBs/FUNCTIONs may share a name as long
  as their parameter signatures differ; each call resolves to the best match
  (the unique arity match, then, among same-arity candidates, the one with the
  most exact argument-type matches). The procedure table became an overload set
  (`Overloads` by name, `ProcedureList` for emission, `Procedures` still the
  primary for "exists / is a function" checks); each overload gets its own
  emitted label (the first/only one keeps the plain `p_<name>` so non-overloaded
  programs are byte-identical). A redefinition with an *identical* signature is
  still the existing "already defined" error; a DECLARE prototype is matched to
  its definition by signature. Gate: `LanguageFeature.SubFunctionOverloading`
  (a same-name/different-signature definition under pb35 reports the gate error).

- **Shift / rotate / bitwise operators** — new operators whose width is the left
  operand's integral type: `<<` (shift left), `<<<` (logical shift left, same as
  `<<`), `>>` (arithmetic/signed shift right), `>>>` (logical/unsigned shift
  right), `<<>` (rotate left), `<>>` (rotate right), and `|` (bitwise OR). They
  bind looser than `+`/`-` but tighter than comparison, and each has a
  compound-assignment form (`<<=`, `>>=`, `<<<=`, `>>>=`, `<<>=`, `<>>=`, `|=`).
  16-bit operands shift/rotate via the 8086 `CL` forms; 32-bit operands use a
  per-bit loop. The lexer maximal-munches the multi-char operators without
  disturbing `<`, `<=`, `<>`, `>`, `>=` (these sequences were never valid pb35,
  so nothing existing changes meaning). Gate: `LanguageFeature.ShiftRotateOps`.

- **Scaled pointer arithmetic** — `ptr +* index` / `ptr -* index` move a typed
  pointer by `index * sizeof(target)` (the same scaling `@p[index]` uses);
  `ptr +* 1` on an `INTEGER PTR` advances 2 bytes, on a `LONG PTR` 4 bytes. The
  result is the pointer's type, so it chains and assigns to a pointer. The codegen
  is offset-only real-mode arithmetic (segment fixed, offset wraps at 64K),
  matching `@p[i]`. Distinct `+*`/`-*` operators were chosen on purpose so raw
  `ptr + n` keeps its existing unscaled DWORD meaning — pb36 stays a byte-identical
  superset of pb35. New `+*`/`-*` lexer tokens; gate:
  `LanguageFeature.PointerArithmetic`.

- **`ENUM` blocks** — `ENUM Name [AS type] : A, B = 5, C : END ENUM` declares a
  group of named integer constants (auto-incrementing from 0 / last+1, or explicit
  `= value`). Members are bare compile-time constants in their own namespace (a
  real variable of the same name wins); the enum name aliases its underlying
  integer type, so `DIM c AS Color` works. The binder records each member
  reference in `ResolvedConstants` (emitted as a literal, ungated so it is correct
  with the optimizer off) and `ConstantFolder` knows members too (for CASE/bounds/
  `DIM`-init). Compile-time only, no runtime, no OOP. Gate:
  `LanguageFeature.EnumType`.

- **`WITH expr … END WITH`** — inside the block a leading `.member` refers to
  `expr.member` (nestable; the innermost WITH wins). Pure parser desugar: the
  leading dots are rewritten to member accesses on the subject and the block is
  spliced inline (no WITH node reaches the binder/codegen, so it composes with
  every later pass for free). The subject is re-read per access — use a simple
  subject if that matters. Reduces UDT-access repetition, no OOP. Gate:
  `LanguageFeature.WithBlock`.

- **Default parameter values** — `SUB Foo(x AS INTEGER, y AS INTEGER = 10)`: a
  defaulted parameter is optional, and a call site may omit it (trailing). The
  default lives on the definition's signature (a `DECLARE` may omit it; the
  definition's params win on replace); the codegen fills omitted trailing
  arguments with each parameter's default expression, evaluated at the call site.
  It composes with overloading through the existing `Optional`/`RequiredParameters`
  mechanism. Note: IPCP was taught about defaults too — a call that omits a
  defaulted argument is folded as passing that default, so the optimizer no longer
  mistakes a parameter for a constant when some call sites use the default. Gate:
  `LanguageFeature.DefaultParameters`.

- **Named arguments** — `Foo(y := 5)`: an argument may be given by parameter name
  (`name := value`). The binder reorders the call's arguments into positional
  order (positional args first, then named by name) and fills any omitted
  parameter with its default, storing the positional list which codegen and IPCP
  consume; the AST nodes (`NamedArgExpr`) are still walked by the optimizer via
  `AstQuery.Subexpressions`. Errors on an unknown/duplicate name, a positional
  argument after a named one, or a missing argument. Gate:
  `LanguageFeature.NamedArguments`.

- **XMS/EMS arrays (opt-in memory surface)** — `DIM EMS a(...)` / `DIM XMS a(...)`
  new array storage classes alongside `VIRTUAL`. `EMS` uses the existing EMS-paged
  array allocator; `XMS` is routed through it as a working stand-in (observably
  identical — it is just where the storage lives) until the optimizer instance
  lands a true XMS-backed runtime. This is the language *surface* for the
  memory-handling work; the deeper runtime (true XMS, stack-allocation of small
  non-escaping locals via `$OPTIMIZE STACKALLOC`, heap/stack reuse) is the
  optimizer instance's lane. Gate: `LanguageFeature.XmsEmsArrays`.

- **From-end array index** — `arr(^n)` is the n-th element from the end (`^1` =
  last). The binder rewrites it to `arr(UBOUND(arr[,dim]) - n + 1)` — `UBOUND`
  folds to a constant for a static array and reads the descriptor for a dynamic
  one — and codegen substitutes the rewrite at the single index-emission point
  (`EmitInt16Argument`), so it works as both rvalue and lvalue and for every array
  class. Valid only as an array subscript (an error elsewhere). Gate:
  `LanguageFeature.FromEndIndex`.

- **Array initializer literals** — `DIM a%() = {10, 20, 30}` (auto-sized) or
  `DIM a%(n) = { ... }` (explicit size; unfilled trailing elements stay zero).
  Elements may be a value, an inclusive integer range `lo TO hi` (expanded), or a
  spread `..arr` of a 1-D **static** array (its elements flattened in). The binder
  expands the literal to a flat value list, declares the static array, and lowers
  it to one element assignment each (spliced after the DIM, reusing the array
  element-store codegen). The `..` (`DotDot`) lexer token marks spreads — the number
  lexer never eats `..` as a decimal point. Ranges are the wordy `lo TO hi` (the
  terse `lo..hi` form was dropped: BASIC spells ranges with `TO`). Spread of a
  *dynamic* array (runtime size) and the `{^3}` count-from-end form are deferred.
  Gate: `LanguageFeature.ArrayInitializer`.

- **Bracketed collection / range literal** — `[v1, v2, lo TO hi, ..arr]` is the same
  literal with square brackets instead of braces (same `CollectionElement` grammar
  and lowering), so `DIM a%() = [99 TO 105]` fills the array like `{99 TO 105}`. It also
  serves as a `FOR EACH` source. Gate: `LanguageFeature.CollectionLiteral`.

- **`FOR EACH v IN source … NEXT`** — desugared (parser-only) to a counted `FOR`:
  a `[lo TO hi]` range literal becomes `FOR v = lo TO hi`; an array (`a()` / `a`)
  becomes `FOR <hidden> = LBOUND(a) TO UBOUND(a) : v = a(<hidden>) : …` (one
  dimension; the element is copied into `v` each iteration). The hidden index's name
  contains `$`, so it can never collide with a source identifier. `FOR EACH` is told
  apart from a loop variable literally named `each` by the token after it (the loop
  variable vs `=`). Gate: `LanguageFeature.ForEach`.

- **Interpolated strings** — `$"text {expr} more {expr:fmt}"` is a string literal with
  embedded holes (the `$` sits directly before the opening quote). It desugars in the
  binder to an ordinary `&` concatenation reusing the existing string runtime, so it
  needs no new codegen: a literal run becomes a string literal; a `{expr}` hole whose
  value is a **STRING** is concatenated as-is; a **numeric** `{expr}` hole becomes
  `STR$(expr)` (exactly the text `PRINT`/`STR$` produce, leading space and all); and a
  `{expr:fmt}` hole becomes `USING$(fmt, expr)` — i.e. the **same PRINT USING formatter**
  (`EmitUsingBody`), so a format like `{x:###.##}` renders identically to
  `PRINT USING "###.##"; x`. `{{`/`}}` are literal `{`/`}`; a `"` inside a hole opens a
  nested string expression (its quotes/braces are not the interpolation's closer); a
  non-string/non-numeric hole (UDT, array, …) is a bind error. `$""` is the empty string.
  The lexer captures the raw inner text as one `InterpString` token (only when `$` is
  immediately followed by `"`, so pb35 source — where `$` is a type suffix /
  metacommand intro — is untouched and stays byte-identical); the parser splits it into
  literal/hole `InterpolationPart`s (re-parsing each hole with the active dialect) and
  the binder records the desugared concatenation in `SemanticModel.Desugared`, which
  codegen emits in the node's place. The node lists its holes in `AstQuery.Subexpressions`
  so the optimizer stays sound. Gate: `LanguageFeature.StringInterpolation`; coverage in
  `InterpolatedStringTests`, `DialectGateTests`, and the DOSBox battery
  `Pb36LanguageFeatureTests`.

- **Nested local SUB/FUNCTION (stack capture)** — a `SUB`/`FUNCTION` may be defined
  inside another proc and reference the enclosing proc's scalar locals. Each nested
  proc is **lifted** to its own top-level proc (mangled `Outer$Inner`); a referenced
  outer local is **captured as a hidden BYREF parameter**, and every (scoped) call
  site passes that local by reference — so the capture is true stack capture with no
  heap, reusing the existing BYREF codegen. The binder discovers captures via a scope
  chain (`Scope.CaptureFrom`) while binding the lifted body, then appends the capture
  arguments to the recorded call sites. Nested procs are callable only from their
  enclosing proc. **This is the stack-based first stage**; escaping closures (a
  returned method-pointer that captures locals, needing hidden heap state) remain
  future work. Current limits: one level of nesting, scalar (non-array) captures.
  Gate: `LanguageFeature.NestedProcedures`.

- **Inline lambdas** — `FUNCTION(params) [AS type] => expr` is an
  anonymous function lifted to an anonymous top-level proc; the lambda *expression*
  evaluates to that proc's far code pointer (like `CODEPTR32`), assignable to a
  `???`/DWORD variable and invoked via `CALL DWORD`. In PB 3.6 the arrow `=>` is its
  own token, lexed distinctly from the `>=` comparison (older dialects keep the
  historical `=>`-as-`>=` tolerance), so the lambda forms are unambiguous: a terser
  **concise form** drops the `FUNCTION` keyword — `(a, b) => a + b` — and a single
  parameter may drop the parentheses entirely — `x => 2 * x`. `>=` always remains the
  comparison (`x >= 2 * x` compares). Parameter types, their
  `BYVAL`, and the result type may all be **omitted and inferred** from the delegate
  the lambda is bound to (an assignment or `DIM` target — see below); a bare `(a, b)
  => a + b` assigned to a `FUNCTION(LONG, LONG) AS LONG` delegate gets `BYVAL a AS
  LONG, BYVAL b AS LONG` and a `LONG` result. A lambda may **capture** the
  enclosing procedure's stack locals: each reference to an outer local is reached
  through the closure's environment pointer (the fat delegate value's second dword),
  and capture is **by reference** for a non-escaping closure — it reads and writes the
  live local, and mutations are shared with the defining scope. A lambda may capture the
  enclosing procedure's stack **locals** and its **BYVAL parameters** (both are
  BP-relative cells); a BYREF parameter (a pointer) and a STATIC/SHARED (reachable
  directly in DS) are not captured. There are two environment kinds, chosen by escape
  analysis:
    - **Stack closure (non-escaping)** — the default first stage: the environment *is*
      the enclosing frame, so the closure is valid while that frame is live (it may be
      passed to and called from another procedure, since the env travels with the
      value). Capture is **by reference**: the closure sees later mutations of the
      captured locals, and its own writes are visible back in the defining scope.
    - **Heap closure (escaping)** — when escape analysis finds the closure value can
      outlive the enclosing frame (it is returned as the enclosing FUNCTION's result,
      or stored in a SHARED/GLOBAL/STATIC; a closure whose definition cannot be proven
      to stay local is conservatively treated as escaping), the enclosing procedure
      allocates a small **heap environment record** (in the far array heap) at
      closure-creation and copies the captured values into it. The closure then reads
      that record through the same env far pointer. Capture is therefore **by value at
      creation** — a *snapshot*: mutations of the captured locals after the closure has
      been built are **not** shared (sharing across an escape would require boxing the
      captured local into the heap env on both the producer and the closure side —
      out of scope). Each closure value gets its own snapshot, so two escaping closures
      from one producer keep independent captures.

  A returned escaping closure stays valid after the producing frame is gone (it reads
  its heap snapshot, not the dead stack). Limitation: heap closure environments are
  **never freed** — PB has no GC and the array-heap bump allocator only reclaims its
  topmost block — so closures created in a long-running loop leak their env records.
  To call a lambda *with arguments* and a return value, assign it to a typed procedure
  pointer (below) rather than the untyped `CALL DWORD` path. Gate:
  `LanguageFeature.Lambdas`.

- **Typed procedure pointers / delegates (fat closures)** — `DIM f AS FUNCTION(types)
  AS type` / `DIM g AS SUB(types)` declares an 8-byte delegate value: a far code
  pointer followed by a far environment pointer (null for a non-capturing target).
  A lambda (`f = FUNCTION(BYVAL x AS LONG) AS LONG => x*x`) or a
  named procedure's address (`f = CODEPTR32(Triple&)`) is assignable to it, and it
  is **callable directly** — `PRINT f(7)`. Because the call site knows the declared
  parameter types it pushes each argument **BYVAL coerced to the exact width** and
  reads the result in the FUNCTION's return registers. This is the proper fix for
  the untyped-`CALL DWORD` width mismatch (a bare `CALL DWORD ptr(21)` pushed an
  INTEGER where the callee read a LONG → garbage). Lambda parameters bound to a
  pointer must be `BYVAL` and match arity. The delegate is plain storage, so it can
  be reassigned to switch the callee at run time. Storing one into a 4-byte
  `???`/DWORD keeps only the code half (the `CALL DWORD` interop path, env dropped).
  Gate: `LanguageFeature.ProcPointers`.

- **Named delegate types** — a `DECLARE`d (or defined) `SUB`/`FUNCTION` name doubles
  as a procedure-pointer *type*: `DECLARE FUNCTION Comparator(BYVAL a AS LONG, BYVAL
  b AS LONG) AS LONG` then `DIM cmp AS Comparator` declares a typed pointer carrying
  that prototype's signature, and `cmp = (a, b) => a - b` infers the lambda's types
  from it. The name is equally usable as a **parameter type** — `FUNCTION Apply&(BYVAL
  f AS Comparator, ...)` accepts a proc pointer type-safely and may invoke it (`f(x,
  y)`), giving statically-checked higher-order procedures. Forward references work
  (procedures are collected before bodies bind); an overloaded name is rejected as a
  delegate type (a delegate needs one signature). Gate: `LanguageFeature.NamedDelegates`.

- **`TRY … [CATCH …] [FINALLY …] END TRY`** — structured exception handling that
  **lowers onto the existing `ON ERROR` trap** (no new runtime). A runtime fault in
  the body transfers to `CATCH` with `ERR`/`ERL`/`ERR$` set exactly as the classic
  handler sees them (there is **no RESUME** — the failing statement is not retried or
  skipped). `FINALLY` runs on **every** path: after normal body completion, after a
  `CATCH`, or — when there is no `CATCH` — before the error re-propagates. At least
  one of `CATCH`/`FINALLY` is required. Codegen: on entry the previous handler triple
  (`rt_onerr`/`rt_onerr_bp`/`rt_onerr_sp`) is **pushed** and a fresh dispatcher armed
  over the body; `rt_raise` restores `SP`/`BP` to the armed frame and jumps to the
  dispatcher, which **pops the saved triple back** (this restore is what makes
  `TRY` **nest** and what re-arms whatever trap was active before `TRY`). `FINALLY` is
  guaranteed by emitting it on each exit edge: with a `CATCH`, both the
  normal-completion edge and the caught edge run it and fall through (the catch
  swallows the error); without a `CATCH`, the normal edge runs it and ends while the
  fault edge runs it then re-raises the still-set `ERR` to the now-restored previous
  handler. pb35 has no `TRY` (output stays byte-identical). Gate:
  `LanguageFeature.TryCatch`.

- **Segmented `PEEK`/`POKE`** — `POKE seg:offset, val` and `v = PEEK(seg:offset)` carry the
  segment inline. The `:` is only special in the `PEEK`/`POKE` address position, so it never
  clashes with the statement separator `:`. It sets `DEF SEG = seg` before the access (its
  runtime semantics), so it lowers to `DEF SEG = seg : POKE offset, val`; a segmented `PEEK`
  in an expression hoists a `DEF SEG` before the statement. Gate:
  `LanguageFeature.SegmentedPeekPoke`.

- **Chained comparison** — `lo <= x < hi` desugars in the parser to `(lo <= x) AND (x < hi)`,
  reusing the middle operand (which should be side-effect-free — it is read once per link).
  Gated to pb36; under pb35 `a < b < c` keeps its classic left-associative meaning, so no
  existing program changes. Gate: `LanguageFeature.ChainedComparison`.

- **Null-conditional access** — `obj?.member` / `obj?[index]` on a nullable (`T?`) target
  desugars to `IF(obj.HasValue, obj.Value.member, fallback)` — the fallback is the `??` default
  (`obj?.m ?? d`) or a type-matched zero standalone. The lexer declines to glue a single `?`
  as a `BYTE` suffix before `.`/`[` (a scalar has no members, so no pb35 meaning is lost). New
  `NullConditionalExpr` node. Gate: `LanguageFeature.NullConditional`.

- **Events** — `EVENT name AS delegate` declares a multicast event backed by a fixed-capacity
  (32) `DWORD` handler array plus a count. `name += handler` / `name -= handler` (handler =
  `CODEPTR32(sub)`, a bare procedure name, or a lambda) append / compact-remove a handler, and
  raising is just invoking: `name(args)`, `name args` and `CALL name(args)` are all
  equivalent (there is no separate RAISE keyword) — each loops over the list invoking every handler through `CALL DWORD`,
  with arguments coerced to the delegate parameter types and passed per their BYVAL-ness. The
  whole feature lowers to ordinary pb35 (a `DIM` array, indexed stores, a compacting `FOR`
  loop, and `CALL DWORD`), so it round-trips. Gate: `LanguageFeature.Events`. (Module-level
  events, fixed capacity; a resizable list and per-instance TYPE events are later increments.)

- **First-class functions** — procedures behave as values wherever a code pointer is expected:
  a bare procedure name assigned to a delegate-typed (or `DWORD`) variable or added to an event
  takes its address implicitly (`f = Triple` == `f = CODEPTR32(Triple)`); a delegate-typed
  variable is invoked exactly like a SUB in statement position (`x 15`, `CALL x(15)`, `x(15)`),
  routed through the typed pointer-call path (closure environment included; a FUNCTION
  delegate's result is discarded, an ignored float result popped). The statement-bodied
  **SUB lambda** completes the picture: `DIM x = SUB(y AS INTEGER) PRINT y * 2` lifts to an
  anonymous SUB whose value is its code pointer, and the DIM infers a full delegate type from
  the lambda's signature, so `x 15` is immediately callable. Lambda parameters are BYVAL by
  default (a delegate's parameters are values; lambdas are pb36-only, so no legacy BYREF
  expectation exists).

- **Array slice spreads** — inside an array literal, `..b(lo TO hi)` spreads a *slice* of
  another static array (alongside the existing whole-array `..b`): either bound may be omitted
  (defaulting to the source's LBOUND/UBOUND) or be a from-end `^n` (`^1` = last), e.g.
  `DIM a = {1, ..b(0 TO 2), ..b(TO ^5), 5 TO 9, ..c(^7 TO)}`. Slice bounds must be compile-time
  constants (the array is sized at compile time); each slice expands to per-element reads of
  the source, so the whole literal lowers to plain pb35 assignments.

- **`USING` (scope-guaranteed disposal)** — `USING v AS Type[(ctor args)]` declares `v`, runs
  the TYPE's constructor when arguments are given, and schedules `v.Dispose()` for scope exit
  via `DEFER` — which wraps the rest of the block in `TRY ... FINALLY`, so disposal runs on the
  fault path too. The TYPE must expose a `Dispose` method. Gate:
  `LanguageFeature.UsingStatement`.

- **Anonymous types** — `DIM p = NEW { .X = 3, .Y = 4& }` with no type name synthesizes a UDT
  from the field names and their inferred value types; two literals with the same shape share
  the synthesized type. Lowers exactly like the named object initializer (a DIM plus per-field
  assignments). Rides the `ObjectInitializer` gate.

- **Dense bit-field packing** — a run of `AS BIT * n` fields packs into the *smallest*
  containers: up to 8 used bits cost one BYTE, up to 16 a WORD, 17 a WORD plus a BYTE (a field
  never straddles containers). One flag therefore costs a single byte, not a word. Accesses
  lower minimally: a constant write folds its masked/shifted value to one literal
  (`s = s AND 248 OR 5`, and writing 0 drops the OR entirely), a field covering its whole
  container stores/reads the container member directly (no read-modify-write), and a field
  reaching the container's top bit reads shift-only — the logical shift already cleared the
  low bits, so the width mask is redundant.

- **Type aliases** — `TYPE Handle AS DWORD` (single line, no `END TYPE`) names an existing
  type: scalars, UDTs, pointers, fixed strings, even other aliases (chains resolve
  transitively; cycles are a bind error, as is reusing an existing type name). The alias is
  fully resolved at bind time — zero runtime cost — and the decompilation substitutes the
  underlying type everywhere, so pb35 never sees the alias name. Gate:
  `LanguageFeature.TypeAlias`.

- **`IN` membership test** — `x IN lo TO hi` lowers (in the parser, like chained
  comparison) to `(x >= lo) AND (x <= hi)`; `x IN {a, b, lo TO hi}` to an OR chain of
  per-element tests (a range element tests its bounds). The tested value is reused per
  element, so it should be side-effect-free. A bare range also serves as a `FOR EACH`
  source — `FOR EACH v IN 1 TO 9 STEP 2` needs no brackets and desugars to a counted
  `FOR`. Gate: `LanguageFeature.InOperator`.

- **Discriminated unions** — a `UNION` whose members are `CASE` tags with per-case payload
  fields:

  ```basic
  UNION Shape
    CASE Circle
      Radius AS SINGLE
    CASE Rect
      W AS INTEGER
      H AS INTEGER
    CASE Dot
  END UNION
  ```

  Lowered entirely in the parser onto existing machinery: each payload case becomes a view
  TYPE `Shape_Circle`, and the union a TYPE carrying a hidden `$tag` INTEGER plus one
  view-typed slot per case, all overlapping `AT` offset 2. Case names are module-wide
  constructors — `s = Rect(3, 4)` stores the tag and the payload fields, `s = Dot` just the
  tag. The pattern test `IF s IS Rect r THEN ... r.W` compares the tag and binds `r` as a
  DIM'd *copy* of the payload hoisted before the enclosing statement (unconditional byte
  copy — harmless on tag mismatch; mutations through the binding do not write back). Works
  in ELSEIF arms, in ternary conditions (`r = IF(s IS Circle c, c.Radius, 0!)`), and in
  `SELECT CASE` matching:

  ```basic
  SELECT CASE s
    CASE Circle c
      PRINT c.Radius
    CASE Rect r
      PRINT r.W * r.H
    CASE ELSE
      PRINT "other"
  END SELECT
  ```

  (the subject rewrites to the hidden tag, each `CASE Tag [v]` to the tag index; mixing
  pattern and ordinary selectors in one SELECT is an error). A binding in a loop *test*
  is rejected — the hoisted copy would be taken once, not per pass. Gate:
  `LanguageFeature.DiscriminatedUnions`.

- **Stack arrays** — `DIM STACK a(1 TO 8) AS INTEGER` inside a SUB/FUNCTION places the
  array data in the procedure's stack frame (`[BP+DI]` addressing) instead of the data
  segment: reentrant (recursion-safe - each invocation gets its own copy), zero DGROUP
  footprint, freed on return. Compile-time bounds required; not available at module level
  or in STATIC procedures. Element access and LBOUND/UBOUND are supported; whole-array
  operations (passing `a()`, ERASE) are compile errors. Decompiles as a plain `DIM`.
  Gate: `LanguageFeature.StackArrays`.

- **Static assertions** — `$ASSERT cond [, "message"]` is evaluated by the binder: a
  non-constant condition or a false one is a compile error (the message is carried into the
  diagnostic); a passing assertion emits no code at all and vanishes from the decompilation.
  Gate: `LanguageFeature.StaticAssert`.

- **Compile-time reflection** — `TYPEOF$(x)` (the PB spelling of x's type; x may be a TYPE
  name or any expression), `SIZEOF(T)` for a TYPE/alias name (the variable form remains the
  regular intrinsic), `FIELDCOUNT(T)`, `FIELDNAME$(T, i)` (1-based), `FIELDOFFSET(T, f)` and
  `FIELDSIZE(T, f)` (f = field name or 1-based constant index). All fold to literals at bind
  time — zero runtime footprint, and they compose with `$ASSERT`
  (`$ASSERT FIELDOFFSET(Msg, Payload) = 4`). Gate: `LanguageFeature.CompileTimeReflection`.

- **`DEFER` fault-path guarantee** — `DEFER` has always lowered (in the parser) to
  `TRY ... FINALLY` around the rest of the block; the decompiler now also reconstructs the
  fault edge under pb35 (`ON ERROR GOTO` + re-raise via `ERROR ERR`), so the emitted source
  keeps the guarantee instead of flattening the cleanup to a sequential statement.

## Optimizer soundness for new expression nodes

Adding an expression node (the ternary above, and the operators/initializers to
come) is only sound if every optimizer pass that reasons about reads, escapes or
purity accounts for the node's children. Rather than touch ~13 walkers per node,
there is one registration point — `AstQuery.Subexpressions(expr)` lists a node's
immediate child expressions — and the conservative passes fall back to it for any
node they do not model explicitly: `SsaForm` escapes every contained variable
(excluding the node from SSA/SCCP/dead-store), float demotion blocks contained
candidates, IPCP assumes a contained write, and the DEF SEG pruner treats a
contained PEEK as observing the segment. So a new expression node is sound by
default (merely unoptimized inside); each new node need only be added to
`Subexpressions`, bound, and emitted.

Beyond sound-by-default, the optimizer now actively optimizes the new constructs:

- **Shift/rotate operators** are pure integral `BinaryExpr`s, so they are already
  SSA-tracked; they are now recognized as pure by CSE (`IsPure`) and as
  value-exact by float demotion (`TreeIsValueExact`), so they participate in
  common-subexpression elimination and never block de-floating. `ConstantFolder`
  folds shift-*left* (`<<`/`<<<`) at compile time (it is width/sign-independent;
  the emitter wraps to the bound type). Shift-*right* and rotates stay runtime —
  their result depends on the operand width and signedness, which the type-less
  folder does not know, so folding them would risk a wrong value.
- **The ternary `IfExpr`** is now tracked through the whole SSA pipeline rather
  than excluded: `SsaForm` (escape analysis + `RecordUses`), `Sccp`
  (`TrackedReads`/`Substitute`) and `DeadStore` (seeded from `UseVersions`) all
  recurse its condition and both branches. This matters because escaping is a
  *global* property — without this, a single ternary use would disable SSA/SCCP
  for that variable everywhere, not just in the ternary. The emitter already
  folds proven-constant reads inside the ternary (each branch emits through
  `EmitExpression` → `TryEmitProvenConstant`), and a constant-condition ternary
  folds to its taken branch at compile time (`ConstantFolder` + the
  `TryEmitFolded` path), with the untaken branch never evaluated.
- **CSE/folding correctness** is gated the same way as the existing ops: shifts
  are pure and never trap, and the constant-condition ternary fold only takes the
  selected branch (preserving short-circuit and never evaluating a side-effecting
  untaken branch). Verified by `Pb36LanguageFeatureTests` running under the
  optimizer (on by default for pb36): constant folds, SSA-through-ternary
  consistency with dead-store, and a non-constant-param ternary whose store must
  survive.

## Implementation status (— first wave landed)

`--dialect pb36` exists and emits optimized code today:

- **P1 Runtime trimming** — implemented (`CodeGen/RuntimeTrimmer.cs`): a
  one-time probe emission maps every runtime label to its providing section
  and every section to its referenced labels; a reachability closure from the
  labels the user program references selects the minimal section set, emitted
  AFTER the user code (`DosRuntime.BindDeferred` pre-binds the label surface).
  The probe derives from the genuine emission, so the graph cannot drift.
- **P2 partially** — section-granular data (string console cells split from
  the 2 KiB descriptor table; per-subsystem data sections).
- **P4 heap demand** — unused string/array heap segments are not reserved
  (MZ MinAlloc): hello world drops from ~192 KiB resident to the single
  64 KiB main segment.
- **O1 constant folding** — pure integral expressions fold at the emitter,
  wrapped to the bound type (`CodeGenerator.WrapToType`), bit-equal to the
  runtime ALU result.
- **O4 subset** — `x * 2^n` (and `* 0` / `* 1`) lower to 8086-safe shifts
  with operand side effects preserved. Under `$ERROR OVERFLOW ON` the
  strength reducer backs off (a shift chain cannot raise the genuine `IMUL`'s
  error 6) so the checked multiply keeps its real instruction and `JNO` guard
  - oracle battery `tests/diff/DIFF41.BAS`. In the modular int16 path
  (`v% * c`) `$OPTIMIZE SPEED` widens the reduction past powers of two:
  two-bit multipliers `2^a+2^b` lower to `(v + v<<(a-b))<<b`, contiguous-run
  multipliers `2^a-2^b` to `(v<<(a-b) - v)<<b`, negatives via a trailing
  `NEG`, three-term multipliers keeping the compact `IMUL` - sound because the
  modular path only runs unchecked, so every chain reproduces the product's
  low 16 bits exactly (oracle battery `tests/diff/DIFF42.BAS`).
- **P7 trivial-I/O lowering** — implemented (`CodeGen/CodeGenerator.Trivial.cs`):
  programs whose only effects are PRINTing compile-time strings/integrals and
  END lower to a raw COM-style image (DOS/DOSBox load signature-less files as
  .COM regardless of extension): the whole output text - including PB number
  formatting, 14-column comma zones and CRLFs - is precomputed and written
  with one DOS call (AH=9 when '$'-free, else AH=40h), exit via INT 20h /
  AH=4Ch. Hello world: **25 bytes**, verified running in DOSBox.
- **O19 definite-assignment zero elision** — implemented for stack frames
  (`CanElideFrameZeroing`): a conservative straight-line prefix proof (whole
  variable assignments, FOR headers; aborts at calls/branches/labels reads of
  unassigned locals) drops the per-invocation `REP STOSW`, keeping individual
  zeroing only for dynamic-string handle slots; main frames (temps only)
  always qualify when no error handler exists. Array/ArrAlloc elision is
  roadmap (needs O16). Oracle battery: `tests/diff/DIFF22.BAS` (locals must
  read 0 / "" before assignment on every call, with and without elision).
- **O21 register parameters** (`$OPTIMIZE SPEED`, `OptRegParm`) — when the
  compiler owns every call site of a procedure (defined in a self-contained
  module, never address-taken via CODEPTR/`CALL DWORD`), its leading word-sized
  BYVAL scalar parameters are passed in registers (AX,DX,BX,CX) instead of on
  the stack, reusing the WATCALL lowering (see docs/LINKER.md). Caller and callee
  flip together, so behaviour is identical and the per-call push/pop traffic
  disappears. Disabled wholesale if any procedure address is taken; skipped when
  external units/libraries are linked (they may call with the stack convention)
  and for non-pb36 dialects (the pb35 golden output is never touched).
- **O22 dead procedure elimination** (`OptReachability`) — under `Optimize`, a whole
  program's entry point is its top-level code (the synthetic "main"); tracing the call
  graph from there (direct calls, CODEPTR/`CALL DWORD` references — recorded in
  `CallBindings` — and lambdas) marks every procedure that can actually run. Unreachable
  procedures are dropped. It is **transitive**: a procedure reached only from other dead
  procedures is itself dead. Only *fully-owned* procedures are dropped (`IsFullyOwned`:
  a nested procedure, or any procedure in a self-contained main) — an exported
  `$COMPILE UNIT` entry point, or a procedure a linked foreign object could call by name,
  is kept regardless. Soundness rests on `OptReachability.DescendantNodes` visiting every
  statement and expression by reflection (complete by construction, so no reference is ever
  missed). Unoptimized/pb35 output is unchanged (gated on `Optimize`). *Dead global data and
  the CODEPTR-to-dead-global cascade build on this reachability (next).*
- **O23 dead global / data tree-shaking** (`OptDeadGlobals`) — adds the DATA dimension to the
  tree-shaker. A fully-owned simple scalar module global that no reachable code ever **reads** is
  dead: its data slot and every pure store to it (`global = <pure rhs>`) contribute nothing.
  References are classified soundly — a global occurrence is a *read* unless it is exactly a
  top-level `AssignStmt` whose target is `NameExpr(global)`; every other form (INCR/SWAP, array
  index, BYREF arg, VARPTR/VARSEG, a dotted-name `MemberExpr`, any operand) keeps it live. A
  `CODEPTR(P)` that appears **only** as the RHS of a store to a dead global is not a live edge to
  `P`, so the dead-global set, the dead-store set and the live-procedure set are solved together to
  a **fixpoint** (excluding dead stores from the `OptReachability` walk): a method kept alive only
  by a never-read global pointer cascades to dead too. Hard conservative guards keep a global no
  matter what — address taken (VARPTR/VARSEG/STRPTR/…/32), SHARED/COMMON/exported, array/UDT/
  string/BCD/FIX, `DIM … AT`, a PB internal cell, or a store whose RHS could trap (a function call,
  or — under `$ERROR NUMERIC/OVERFLOW/BOUNDS` — arithmetic/an array read, since dropping it would
  skip the Error 6/9 trap). Restricted to a self-contained main (`Optimize && !unit && !linked`), so
  pb35/unoptimized output is byte-identical.
- **O24 multi-concat single-allocation builder** (`EmitMultiConcat` + runtime `rt_strcatn`) — a
  chain or tree of **three or more** string concatenations (`&`/`+`) builds with a SINGLE heap
  allocation and one byte-copy per operand, instead of the pairwise `StrCat` chain's N-1 allocations
  and O(n²) recopying. `FlattenStringConcat` collapses the maximal `&`/`+` tree (over string
  operands) into its ordered list of leaves; `EmitMultiConcat` evaluates every leaf **strictly
  left-to-right**, stages the handles into `rt_catlist`, and `rt_strcatn` then sums every operand's
  length in one pass, calls `StrAlloc` **once**, copies each operand's bytes in order
  (`rt_strcopyinto` re-reads the descriptor, so a heap compaction during the alloc is harmless —
  operands stay live and are relocated with their handles intact), and frees every operand handle —
  consuming them exactly as the equivalent `StrCat` chain would. The result string and the freed
  temporaries are identical; only the allocation count (1 vs N-1) and the bytes copied (O(n) vs
  O(n²)) differ. **Soundness:** because all operands are staged up-front and only then concatenated,
  every leaf must yield a *fresh, independent, freeable* handle that a later operand's evaluation
  cannot invalidate. A literal or a plain string variable does; a function/intrinsic call
  (`LEFT$`/`MID$`/`UCASE$`/a user `FUNCTION`) returns a **shared, volatile result buffer** the next
  call reuses, and an array element / member / pointer deref *borrows* live storage — so
  `FlattenStringConcat` requires every leaf to satisfy `IsReorderableStringExpr` (the same predicate
  O9 uses), and a chain containing any such operand falls back to the pairwise path (which consumes
  each operand immediately after evaluating it). Empty operands (handle 0) read length 0, copy
  nothing and free nothing. This **subsumes** the O9 dead-temp reuse for
  chains of three-plus operands (which it does strictly better — one allocation rather than in-place
  growth at each node); O9's loop self-append (`s$ = s$ + x$`) and two-operand substring-left cases
  keep their `rt_strcatlit`/`rt_strcatvar` in-place paths. Gated on `Optimize`, so pb35/unoptimized
  output is byte-identical (oracle batteries `tests/diff/DIFF94/95/107/108.BAS` still pass via the
  rerouted single-alloc path).
- **O25 subset — pure-function compile-time evaluation** (`CodeGen/OptPureFold.cs`) — the
  compiler *infers* purity rather than requiring a `CONSTEXPR` keyword: a `FUNCTION` whose
  result depends only on its `BYVAL` arguments (no I/O, no globals/SHARED reads, no `BYREF`,
  no side-effecting statements, and calling only other pure functions) is **pure**. When such
  a function is called with all-compile-time-constant arguments, a small tree-walking
  interpreter (`Evaluator`) executes its body and the call is **replaced by the resulting
  literal** — the function frame, CALL/RET and the whole computation vanish (and, once no
  caller references it, O22 purges the body). Purity is a greatest fixed point over the call
  graph (`ClassifyPure`), so mutually-recursive pure helpers all qualify. **Soundness:** the
  interpreter wraps every intermediate to its node's static type via `WrapToType`, exactly as
  the runtime ALU would at each operation width, so the folded value is bit-identical to the
  executed result (e.g. a 16-bit `INTEGER` product silently wraps); integer-division/MOD by
  zero, an unmodelled operator, a non-constant sub-expression, or exhausting the step
  (500k) / recursion (64) budget simply abandons the fold and emits the genuine call.
  **Sound subset (v1):** integer-typed functions and locals/params only, with
  `IF`/`SELECT CASE`/`FOR`/`DO-LOOP`/`WHILE` and `EXIT FUNCTION`/`FOR`/`DO`; floats, strings,
  arrays, pointers and intrinsics keep the real call (a roadmap extension). Output is
  byte-identical to the unfolded program — the differential harness's pb36 pass (all 241
  batteries) is unchanged, since folding a call to its provably-equal value cannot alter
  observable behaviour.
- **R3 subset — DWORD string copy**: the string runtime's literal/concat copy
  (`EmitRepMovsbWidened`) moves DWORDs plus a &lt;=3-byte tail under `$CPU
  80386` (~4x on long strings) instead of `REP MOVSB`; the copied bytes are
  identical (oracle battery `tests/diff/DIFF40.BAS`, a 386 string storm). The
  whole-TYPE/array block copies were already widened (below).
- **C1/R3 subset — block-move widening**: whole-TYPE copies (and LSET/BCD
  block moves) run word-wide (`REP MOVSW`, 8086-safe) under pb36 and
  DWORD-wide (`REP MOVSD`) under `$CPU 80386`, odd tails byte-copied; the 3.1
  whole-value TYPE compare runs `REPE CMPSW` for even sizes. Oracle battery:
  `tests/diff/DIFF23.BAS` (odd/even TYPE sizes, copy + compare).
- **O2 unreachable-statement elimination** — implemented
  (`CodeGen/OptPruner.cs`): statements after an unconditional transfer
  (GOTO/END/EXIT/RETURN/RESUME) drop until the next label; DATA/equates/
  DEFtype/metastatements survive (compile-time effects). Applied recursively
  through IF/SELECT/loop blocks before emission.
- **O7 small-trip unrolling** — implemented under `$OPTIMIZE SPEED`:
  constant-trip INTEGER FOR loops with at most 4 iterations and a small
  straight-line body (no jumps/exits/nested loops/counter writes) unroll
  completely; the counter slot ends on the increment-then-test final value
  (QUIRK 2.28, wrap included). Oracle battery: `tests/diff/DIFF26.BAS`.
- **O9 literal concat folding** — implemented: pure string concatenations
  (`+`/`&` over literals/equates) fold into one pooled literal at the emitter
  (and the `ConstantFolder` now folds `&` for string equates).
- **O10 DEF SEG coalescing** — implemented (`OptPruner`): a DEF SEG whose
  window to the next DEF SEG contains only provably segment-transparent
  statements drops; PEEK-family expressions, POKE/BLOAD/BSAVE/interrupts,
  inline asm, user calls and any control flow end the window conservatively.
- **O11 literal pool packing** — implemented (containment + suffix/prefix
  overlap): `"World!"` and `"lo, W"` share the bytes of `"Hello, World!"`.
  Sound because generated code only reads literals (StrMem copies/PrintStr).
- **O8 subset** — zero idiom: `XOR r,r` for constant zeros at expression
  positions (flag-dead by construction). In the modular int16 path, `v% +/- c`
  for a compile-time constant folds to one immediate `ADD AX,imm` (subtraction
  adds `-c`; `c - v` negates then adds), dropping the constant load and the
  push/pop around the second operand - unconditional, since it is both smaller
  and faster (oracle battery `tests/diff/DIFF43.BAS`). The general int16 binary
  path folds a constant operand the same way: `AND/OR/XOR AX,imm` for bitwise
  masks, `ADD/SUB AX,imm` (keeping the `JNO` overflow trap under `$ERROR
  OVERFLOW`), and `CMP AX,imm` for comparisons - the constant may sit on either
  side (commutative ops; an ordering compare with the constant on the left
  mirrors the operator), and the value is taken modulo 2^16, the same low word
  the register path would coerce into BX (oracle batteries
  `tests/diff/DIFF44.BAS` bitwise/compare, `tests/diff/DIFF45.BAS` checked
  add/sub overflow). A comparison against zero collapses further to `OR AX,AX`
  (two bytes, same ZF/SF; the cleared OF is harmless because the signed and
  unsigned conditions reduce to SF/CF tests when OF = 0). A `+/-1` add/subtract
  (modular or checked) folds to `INC`/`DEC AX` (one byte) - INC/DEC still set
  OF so the `JNO` overflow trap is preserved, and they leave CF alone, which
  the add/sub paths never read (oracle battery `tests/diff/DIFF46.BAS`). The
  32-bit (LONG/DWORD) binary path folds a constant the same way into immediate
  pair ops - `AND/OR/XOR` on the low word in AX and high word in DX, and
  `ADD AX,imm`/`ADC DX,imm` (`SUB`/`SBB`) keeping the `JNO` trap, and `=`/`<>`
  subtracting the halves to test for zero (against `0` the operand's own
  `AX|DX` already decides, so the subtract is skipped - the common `ptr& = 0`)
  - dropping the constant's CX:BX load and the push/pop dance (oracle battery
  `tests/diff/DIFF47.BAS`).
- **O15 subset — UDT copy/compare lowering** — the whole-TYPE block copy and
  `=`/`<>` compare are already lowered to word/dword-wide `REP MOVSW`/`MOVSD`
  and `REPE CMPSW` (the C1/R3 wide-op work). Added here: a self-copy
  (`rec = rec`, structurally identical non-string lvalue) is elided as a pure
  no-op, and a self-compare folds to its constant truth (`rec = rec` -> -1,
  `rec <> rec` -> 0; memcmp of identical bytes is always equal, NaN-immune).
  Field access is already a direct constant-offset memory access (zero-cost).
  Full scalar replacement / register-resident UDT fields await O5 register
  allocation. Oracle battery: `tests/diff/DIFF34.BAS`. Escape-blocked types
  (dynamic string handles) keep the real copy/compare.
- **O4 divide subset** — `x \ 2^n` and `x MOD 2^n` lower to shift/mask
  sequences with the PB truncation fix-up (signed forms bias by `2^n - 1`
  before the arithmetic shift; MOD reconstructs the dividend-signed remainder
  as `((x + b) AND mask) - b`), 8086-safe shift counts (CL beyond four 1-bit
  shifts, never the 186+ immediate form), DWORD forms unsigned (plain
  `SHR`/`AND`). Legal under every $ERROR mode - a positive constant divisor
  can neither raise error 11 nor overflow a quotient. Oracle battery:
  `tests/diff/DIFF27.BAS`.
- **O12 float demotion (first wave)** — implemented
  (`CodeGen/OptFloatDemotion.cs`): SINGLE/DOUBLE variables whose writes are
  FOR headers with foldable integral bounds (plus integral constant resets)
  and whose reads all sit in value-exact contexts (no `/`/`^`, no float
  literals, no calls over the value, no USING/WRITE#) silently re-type to
  INTEGER/LONG - the accidental-float counters of DOS-era code run on
  integer registers again. Range proofs respect SINGLE's 2^24 exact-integer
  bound; call arguments (BYREF), INPUT/READ/SWAP targets, INCR (unbounded),
  non-integral CASE comparisons and inline asm/indirect flow block or kill
  the pass. Oracle battery: `tests/diff/DIFF28.BAS` (demoted and blocked
  twins side by side).
- **O14 tail-call subset** — implemented in two shapes. (1) *Self-call*: a
  self-call in tail position (last statement of the body or of trailing
  IF/SELECT arm chains) rewrites its parameter slots in place and jumps back
  to the frame entry, re-zeroing locals exactly like a fresh invocation -
  recursion in constant stack space (60 000-deep tail recursion completes
  where the genuine compiler's default 2 KiB stack dies at ~170 frames).
  (2) *General (cross-procedure) tail call*: a SUB A whose last action is
  `CALL B(args)` (B another in-module SUB) tears down A's frame, lays B's
  whole call frame (return address + arguments) at A's caller's pre-call SP
  boundary, and `jmp`s B's entry - so B's own `RET nb` returns straight to
  A's caller, removing one frame + return per tail call (mutual recursion
  through two procs runs in constant stack). The teardown accounts for A's
  and B's argument-byte counts independently (B's return-address slot lands
  at `[BP+2+(na-nb)]`), so the convention's callee-cleans `RET n` discipline
  stays balanced even when A and B take different argument bytes. Conservative
  gates (both shapes): every parameter a small (≤4-byte) BYVAL non-float
  scalar, numeric-only locals (no string/FLEX cleanup pending), no ON ERROR,
  no GOSUB, a stack callee-cleans convention (not CDECL, not a register
  convention), no capturing-lambda env. The general shape additionally
  requires B to be a defined in-module SUB (a known local jump target) and is
  not applied to FUNCTIONs - a FUNCTION's result-load epilogue, and a
  discarded FUNCTION result's StrFree / FPU pop, must still run, so those
  fall back to an ordinary CALL. Oracle batteries: `tests/diff/DIFF29.BAS`
  (self-recursion + BYREF/blocked twins), `tests/diff/DIFF87.BAS` (mutual
  recursion, a forwarding call with a different argument count, and a
  deliberately non-tail call that stays an ordinary CALL).
- **O18 subset — interprocedural constant propagation** — implemented
  (`CodeGen/OptIpcp.cs`): a scalar parameter that receives the same
  compile-time constant at every call site and is never written (directly or
  via a BYREF pass to another proc, in statements or expressions) reads as
  that literal inside the callee - feeding O1 folding, O2 dead-code and O17
  branch elimination there. The call ABI is unchanged (the argument is still
  passed), so output is identical; only the callee body specializes. Disabled
  wholesale when any procedure address is taken (CODEPTR / CALL DWORD), whose
  indirect call could pass an unseen argument. Leaf-frame zeroing elision is
  O19; the internal register calling convention remains roadmap. Oracle
  battery: `tests/diff/DIFF38.BAS`.
- **O6 inlining subset** — implemented: a small **leaf** SUB/FUNCTION inlines as
  its body at every call site - the frame, CALL and RET overhead disappear and
  (when every call inlines) the procedure is reachability-purged from the image.
  BYVAL scalar arguments evaluate once into fresh per-inline frame temps (effects
  and order preserved); the body's statements emit with every read and write of a
  parameter, body local or the result variable remapped onto those temps (so two
  inlinings - or a self-mutating BYVAL param at two call sites - never collide),
  body locals start zeroed exactly like a real frame, and a FUNCTION's result is
  the value left in the result temp. Conservative leaf gate: BASIC convention only,
  not STATIC, no ON ERROR, no closure/capture, BYVAL scalar parameters only, and a
  body of at most a few plain scalar assignments and LOCAL declarations - no calls,
  loops, labels, GOTO/GOSUB/RETURN, EXIT, SELECT or nested procs (the trivial
  single-result-assignment FUNCTION is the fast path, emitting the expression
  straight into the registers with no result temp). The reachability purge
  (`OptInlining.FullyInlinedProcedures`) only fires for a self-contained main and
  bails the moment a procedure's address is taken (CODEPTR) or the program uses any
  error handling - either of which can force a real call that must keep the body.
  Anything uncertain falls back to the genuine call, so output is byte-identical.
  Oracle battery: `tests/diff/DIFF30.BAS` (mixed eligible/ineligible callees,
  side-effecting and nested arguments).
- **O16/O17 subset — check & branch elimination** — implemented: a constant
  IF/ELSEIF condition selects its arm at compile time and the dead arms are
  not emitted (SCCP-lite, cascading through the ELSEIF chain; the folder is
  pure so dropping the untaken arm is sound). Under `$ERROR BOUNDS ON`, an
  array access with a constant index provably inside the static DIM bounds
  drops its Error-9 check entirely (a check that *could* fire is kept, and a
  constant out-of-range index is already a genuine compile error). Oracle
  battery: `tests/diff/DIFF37.BAS`. Full SSA range-narrowing/GVN/LICM remain
  roadmap.
- **O17 SSA + SCCP mid-end** — implemented (`CodeGen/Ssa/`): a real
  static-single-assignment pipeline now runs between binder and emitter for
  structured bodies. `ControlFlowGraph` builds basic blocks over straight-line
  code, IF/ELSEIF/ELSE, and FOR / pre-test or infinite DO-WHILE/UNTIL loops
  (back-edge to the header, so loop phis form; the FOR counter is treated as an
  implicit write and never tracked), with EXIT SUB/FUNCTION/FOR/DO and END as
  region exits and EXIT/ITERATE wired to the enclosing loop. SELECT CASE is
  modeled conservatively as an opaque multi-way branch (every arm and the
  no-match path reachable, the subject and selector expressions recorded as
  reads) so SCCP/DSE analyze SELECT bodies instead of bailing; EXIT SELECT is
  wired to the merge. It still bails on post-test loops, GOTO/labels, GOSUB,
  ON ERROR or any construct it cannot model precisely - so every graph it
  produces is sound; the cyclic constant lattice converges because the lattice
  is monotone. `DominatorTree` computes immediate dominators
  (Cooper-Harvey-Kennedy) and dominance frontiers (Cytron); `SsaForm` places phi
  functions and renames every non-escaping integral scalar local/global into
  versioned values, mapping each read to the version that reaches it
  (variables that escape via a call BYREF, an address intrinsic or any opaque
  statement are conservatively dropped). `Sccp` then solves the constant lattice
  and block reachability together (Wegman-Zadeck): a branch whose condition
  folds constant lights only its taken edge, so phi merges ignore dead arms, and
  PB's zero-initialized locals make uninitialized reads provably zero. The
  arithmetic is delegated to the emitter's `ConstantFolder` (via leaf
  substitution) and every stored value is wrapped to its variable's type, so a
  proven constant equals the exact value the program computes. The emitter folds
  each proven read (`TryEmitProvenConstant`) - cross-block constant propagation
  the local folder cannot do - disabled under `$ERROR OVERFLOW/NUMERIC` (a
  folded constant would skip the runtime trap the real arithmetic must still
  raise). Oracle battery: `tests/diff/DIFF48.BAS` (and `DIFF49.BAS` for loops);
  unit coverage in `PowerBasic.Compiler.Tests/CodeGen/SsaTests.cs` (CFG,
  dominators/frontiers, SSA renaming, SCCP). This is the mid-end the deeper
  O16/GVN/LICM passes will build on.
- **O2 SSA dead-store elimination** — implemented (`CodeGen/Ssa/DeadStore.cs`):
  an aggressive mark-sweep over the SSA removes assignments to non-escaping
  tracked scalars whose version is never really read - either the value is dead
  outright, or SCCP already folded every read to a constant, so the store that
  produced it is now pointless. Liveness is seeded from real (unfolded) reads in
  statements that are not themselves removable and from branch conditions, then
  propagated through phi inputs and the right-hand sides of kept assignments, so
  a value kept alive only by a dead copy chain still dies. Only literal / equate
  / variable-copy right-hand sides qualify (they cannot trap and have no side
  effects, so dropping the store is unobservable); the emitter skips the dead
  statements. Composes with SCCP - `x% = 5 : PRINT x%` folds the print to 5 and
  then drops the assignment entirely. Oracle battery: `tests/diff/DIFF50.BAS`.
- **Promotion lowering (O12/O17 family)** — implemented: assignments of
  +,-,*/negate trees over 16-bit integral leaves into 16-bit integral
  targets run on the plain 16-bit ALU - the low bits of the exact x87
  result ARE the modular result at every depth, so the FPU round-trip the
  integral-promotion semantics would otherwise cost disappears; checked
  arithmetic stays integral in the binder and never reaches the lowering.

**Measured** (hello world, current runtime): pb35 **14 254 bytes** on disk /
~192 KiB resident → pb36 **25 bytes** (P7 fast path; 916 bytes via the general
trimmed path when a variable is involved) / 64 KiB resident, output verified
running in DOSBox. Acceptance gate: the differential harness re-runs every pb35 battery
with `--dialect pb36` against genuine PBC 3.50 — byte-identical output

## What's left — the next optimizations (priority order)

The SSA mid-end (`CodeGen/Ssa/`: CFG → dominators/frontiers → SSA → SCCP) now
exists and SCCP / dead-store / dead-arm run on it. That unblocks the passes the
matrix still calls "subset" or "roadmap". Each builds on the SSA and must stay
byte-identical under the differential harness.

1. **O5 register allocation (the big speed win, partially landed).** Most locals
   are still stack cells. A real allocator keeps hot locals in registers across a
   region, using the SSA liveness:
   - *8086*: SI/DI are the only safe callee-stable GP registers (BX/CX/DX/AX are
     the evaluation/ABI scratch). **Done so far**: an SI/DI-clean FOR loop keeps
     its counter in SI *and* one hot 2-byte INTEGER accumulator in DI
     (`TryEmitForCounterInRegister` + the residency paths; battery DIFF52) - the
     per-iteration cell load/store of both disappears. A **nested** INTEGER loop
     under an SI-resident outer keeps *its* counter in DI instead of an accumulator
     (`TryEmitNestedForCounterInRegister`; battery DIFF90): both counters live in
     the two safe index registers, so neither spills to the stack. Two levels is the
     hard limit - SI and DI are the only callee-stable index registers, and they have
     no 8-bit halves, so a third level falls back to memory (`IsNestedRegisterableFor`
     keeps the nest leaf-only). The inner counter is flushed to its cell on loop exit,
     so a post-loop read sees the increment-then-test end value. A **DO/WHILE/LOOP** (no
     counter, so SI is free) likewise keeps one hot INTEGER accumulator in SI when its body is
     SI/DI-clean and its loop tests are SI-clean (`TryEmitDoLoopInRegister`; battery DIFF96) -
     the first generalization past the FOR-loop shape. A DO loop has no counter, so **both** SI
     and DI are free: a second hot INTEGER accumulator lives in DI (two register-resident
     accumulators at once). The clean-body proof
     also accepts a **conditional** (`IF`/`ELSEIF`/`ELSE`) whose test is SI-clean and whose
     arms are themselves SI-clean (battery DIFF91) - the branch touches no GP register, so
     the counter in SI and any DI resident survive it, covering the common
     `FOR i … : IF c THEN s = s + i : NEXT` conditional-accumulate shape. Next: generalize
     beyond the FOR-loop shape to any hot non-escaping scalar whose live range is
     CALL/GOSUB-free (needs the interval liveness + interference graph).
   - *386/486*: a true win — six 32-bit GP registers (EAX-EDX, ESI, EDI) and
     EBX/ESI/EDI survive the internal ABI, so several hot LONG/INTEGER locals
     can live in registers at once. Pairs with the C1 DX:AX→EAX representation
     change.
   - **8-bit sub-register packing** (user-suggested): two non-escaping BYTE
     locals can share one 16-bit register's halves (e.g. `DL`/`DH`, `BL`/`BH`).
     Sound only when the allocator proves neither half is clobbered by an op
     that writes the whole 16-bit register (MUL/DIV/string ops touch AX; LEA/
     address math touches BX/SI/DI) — so AX's halves are poor candidates but
     BX/DX halves work for BYTE-heavy code. Best done inside the allocator,
     which already tracks per-register liveness, rather than as a separate pass.
   - Hard parts: spilling, the call ABI (calls clobber AX/BX/CX/DX), ON ERROR
     re-entry (a handler must see memory, not registers), and string/FLEX
     locals (handles the epilogue must free). Gate conservatively, like O5.
2. **O9 string-temp reuse (user-suggested).** `LEFT$/RIGHT$/MID$/`concat build a
   fresh heap temp per expression node today. With the SSA live ranges, a temp
   whose handle is dead can be reused for the next string temp instead of
   alloc/free per node, and a whole-string `MID$(s,i)` over a fixed buffer can
   reuse an existing local's storage. Cuts heap churn and the descriptor-table
   pressure. Lower risk than register allocation (no ABI concerns) - a good
   next target. ✅ first step done — **self-concat** `s$ = s$ + rhs` (append) *or*
   `s$ = lhs + s$` (prepend), where the other operand is a string literal or bare
   variable: s$'s handle is passed straight to `StrCat` (which copies both operands
   then frees them) and the result stored, dropping the redundant `StrDup` of s$ and
   the `StrAssign` free — one fewer full copy of the growing string per concat; pure
   codegen, no heap-routine change (`tests/diff/DIFF83.BAS`). ✅ second step done —
   **in-place literal self-append**: `s$ = s$ + "literal"` calls a new `rt_strcatlit` runtime
   routine that, when `s$` is the topmost heap block (and there is room under the `$STRING`
   cap), appends the literal bytes straight after `s$`'s data and grows the block in place,
   keeping the SAME handle — so an `O(n)` build loop is `O(n)` total instead of recopying the
   whole string each append. A literal needs no heap temp, so `s$` stays topmost across loop
   iterations; when `s$` is not topmost the routine falls back to the exact `StrMem`+`StrCat`
   path, so the result is always identical (`tests/diff/DIFF94.BAS`). ✅ third step done —
   **in-place variable self-append**: `s$ = s$ + v$` (`v$` a bare string variable) reads `v$`'s
   RAW handle (no `StrDup` temp, so `s$` stays topmost) and `rt_strcatvar` copies `v$`'s bytes
   heap-to-heap straight after `s$` when topmost, leaving `v$` intact; this also covers the
   self-double `s$ = s$ + s$` (the destination begins exactly where the source ends and `REP
   MOVSB` copies forward, so no byte is read after being overwritten), and falls back to
   `StrDup`+`StrCat` when `s$` is not topmost (`tests/diff/DIFF95.BAS`). ✅ fourth step done —
   **concat-chain dead-temp reuse**: in a left-associative chain `a$ + b$ + c$ = (a$ + b$) + c$`
   the inner concat produces a fresh, dead, topmost temp, so the next barrier-free operand
   (literal or variable) is appended to it in place (reusing `rt_strcatlit`/`rt_strcatvar`)
   instead of allocating a new `StrCat` result at every node — `O(n)` rather than `O(n²)`. Sound
   because the left is a temp (operands are only read as raw handles, never mutated); the runtime
   checks topmost and falls back to a copy otherwise (`tests/diff/DIFF97.BAS`). Still to do:
   dead-temp reuse across non-left-leaning / non-barrier-free concat shapes — needs SSA string
   live ranges.
3. **GVN / cross-block CSE.** ✅ first step done: `OptCommonSubexpr` now inherits its
   live value cache from before an `IF` into the (dominated) branches, so a value computed
   before the IF and recomputed inside a branch reloads the slot instead - the common
   `y*320+x` "compute then reuse in a branch" pattern. Gated on barrier-free conditions;
   byte-identical across the full harness. ✅ second step done (`RetainPastMerge`): the
   value now flows PAST the merge too - an inherited entry survives the join (instead of the
   whole cache being cleared) when no branch can have overwritten its inputs, so a value
   computed before an IF and reused *after* it reloads as well. Sound only when every branch
   is a flat, call-free straight line (`IsRetainableBranch`), so `CollectWrites` captures the
   exact write set; nested control or a call falls back to the conservative clear. Battery
   `tests/diff/DIFF67.BAS`. ✅ third step done: the same inherit + `RetainPastMerge` now also
   covers `SELECT CASE` joins (barrier-free subject and selectors), so a value flows into the
   arms and past the merge exactly as for an IF (`tests/diff/DIFF68.BAS`). ✅ fourth step
   done — **redundant-load elimination**: a repeated array-element read `a%(i%)` with no
   intervening write to the array or an index name reloads the first read's stashed value
   instead of re-reading memory. A safe array read (`CacheableArrayReadSymbol`: plain static,
   non HUGE/VIRTUAL/ABSOLUTE, 2-byte non-float element, simple name/literal indices) is now a
   cacheable CSE leaf keyed by array symbol + indices; any write to the array (any element),
   to an index, or a barrier invalidates it, a write to a *different* array keeps it live
   (`tests/diff/DIFF69.BAS`). Still to do: cross-block reuse through loop pre-headers.
4. **LICM (loop-invariant code motion).** ✅ done for **FOR and DO/WHILE loops**
   (`OptCommonSubexpr.AnalyzeLicm` + `CodeGenerator.EmitLicmPreheader`): a pure integer or
   modular-int16 subexpression in a flat loop body whose operands are all loop-invariant is
   hoisted to the preheader (computed once into a CSE frame slot via the existing
   DEFINE/reload mechanism) and reloaded each iteration. For a FOR loop "invariant" excludes
   the counter; a DO/WHILE loop has no counter (the analysis takes a nullable counter), so
   invariance is simply "not written in the body". Zero-trip-safe: only fires under
   `$OPTIMIZE SPEED` with no checked arithmetic / error handler, and `\`/`MOD` need a
   constant non-zero divisor, so no trap can fire in the preheader of a loop the body skips.
   Battery `tests/diff/DIFF66.BAS`; DO/WHILE covered by `DoLoopLicmTests`. Still to do:
   hoisting loads (needs alias/memory-SSA).
5. **Induction-variable strength reduction.** ✅ first shape done (O6b): a FOR loop whose
   single-statement body reads a static rank-1 INTEGER array by the loop counter
   (`x% = a%(i%)`) steps a DS-relative pointer (advanced by `elementSize*step` per
   iteration) instead of recomputing `base + (i-lbound)*size` - the hot path becomes a
   plain load with no per-iteration multiply. Gated very conservatively ($OPTIMIZE SPEED,
   constant STEP, no bounds/overflow/numeric checking, no aliasing/calls); byte-identical
   under the harness (battery `tests/diff/DIFF64.BAS`). Array STORES `a%(i%) = expr` also
   step the pointer now (the value lands in AX via the normal expression emitter, BX
   saved/restored across it, then `MOV [BX], AX`; `expr` must not reference the array, so
   there is no read-after-write through the stepped pointer; battery `DIFF65.BAS`). ✅ widened
   to **signed-LONG (4-byte) element arrays** for both read and store: the pointer steps by 4
   (two 8086-safe shift-by-1), the LONG value moves as DX:AX (battery `DIFF76.BAS`). Broader
   shapes (multiple arrays, non-counter index strides) remain.
6. **Copy propagation.** ✅ done (`CodeGen/OptCopyProp.cs`): a copy `y = x` (RHS a
   bare read of another tracked scalar of the same type) redirects every read of `y` to
   `x`'s cell and drops the copy; sound because the source must be assigned at most once
   (its cell is stable across the live range) and copy chains resolve to the root whose
   cell is actually written, so a removed copy never leaves a read on an unwritten cell.
   Composes with the SSA dead-store pass; byte-identical across the full harness.
7. **Reciprocal-multiply division by a constant.** `x \ 10`-style divides by a
   non-power-of-two constant become a multiply by a magic reciprocal plus a
   shift (the standard libdivide trick) - removes the runtime divide loop;
   pairs with the two-digit-table number formatter (R3).
8. **SELECT → jump table.** ✅ done (`CodeGenerator.TryEmitSelectJumpTable`): a 16-bit
   `SELECT CASE` whose arms are all single integer-constant cases (no ranges/IS) with a
   dense value span (≥4 cases, span ≤256 and ≤4×cases) dispatches through a word table -
   subtract the minimum, one unsigned bounds check, then `JMP [table + index*2]` to the
   matching arm (CASE ELSE / no-match → the default). The same arm runs as the compare
   chain, so output is byte-identical (battery `tests/diff/DIFF62.BAS` under pb35 + pb36).
9. **O16 range/value lattice.** Extend SCCP to intervals/known-bits so types
   narrow (LONG that fits a BYTE runs as BYTE), `$ERROR` checks that provably
   can't fire are dropped, and more branches fold. The widest remaining mid-end.
   ✅ FOR-counter range lattice landed — registered by `EmitFor` (disposable scope,
   strict call-free counter-stable body) and applied to two of the three named uses:
   (a) **bounds-check elimination** — an array index that is a FOR counter, an affine
   counter expression (`a(i)`, `a(i±k)`), or the sum/difference of two range-known operands
   (`a(i+j)`, `a(i-j)` with `j` a derived range-known var) whose `[lo,hi]` lies inside the
   array bounds drops its Error-9 check under `$ERROR BOUNDS ON` (`IndexRangeOf` now combines
   two range-known operands by interval arithmetic — an over-approximation that is sound for
   every consumer; `tests/diff/DIFF77.BAS`, `tests/diff/DIFF89.BAS`). `IndexRangeOf` also bounds
   `x AND m` (m a non-negative constant) to `[0,m]` for any `x`, `x MOD k` (k constant) to
   `[-(|k|-1),|k|-1]` (to `[0,|k|-1]` when `x ≥ 0` is provable), and `x \ k` (k constant) by
   dividing the endpoints (truncated divide is monotonic in the dividend), so masked / modular /
   scaled-down indexing `a(h AND mask)` / `a(i MOD n)` / `a(i \ 2)` drops its check too
   (`tests/diff/DIFF92.BAS`, `tests/diff/DIFF93.BAS`);
   (b) **branch folding** — a signed comparison of such a range against a constant whose
   result is invariant over the range folds to the constant boolean in ordinary code
   (`TryEmitRangeComparison`/`FoldRangeCompare`; `tests/diff/DIFF78.BAS`);
   (c) **overflow-check elimination** — an INTEGER add/subtract over an affine counter
   range that stays inside 16 bits drops its Error-6 check under `$ERROR OVERFLOW ON`
   (`ProvablyNoOverflow`; `tests/diff/DIFF79.BAS`); the same proof extends to LONG
   add/subtract whose exact value range stays inside the signed 32-bit range, dropping the
   32-bit `ADD/ADC` (`SUB/SBB`) Error-6 trap (`ProvablyNoOverflow32`; `tests/diff/DIFF87.BAS`);
   (d) **divide-by-zero guard elimination** — an INTEGER `\`/`MOD` whose divisor is a
   counter range excluding zero drops its always-emitted Error-11 guard, in ordinary code
   (`DivisorNonZero`; `tests/diff/DIFF80.BAS`). Still to do: **type narrowing** (LONG
   that fits a BYTE runs as BYTE) - needs the full interval lattice tracking ranges
   through arbitrary computations, not just FOR counters.
10. **C1 full 32-bit representation**, **C3 x87 scheduling**, **R1/R2 fast
    video** (needs a screen-capture oracle), **S3 link-time tail merge** - as
    in the matrix.

## Architecture: a real optimization pipeline

Today statements are emitted directly to the assembler. pb36 inserts passes
between binder and emitter, each independently testable and switchable:

```
Binder → SSA construction → [SCCP const-prop] → [Range analysis / narrowing]
       → [GVN] → [Alias / memory SSA] → [LICM + sink] → [Strength reduce]
       → [Inline + IPCP] → [Unroll / Duff] → [If-convert] → [TCO]
       → [Register allocate + coalesce] → Emitter → [Peephole] → [Align]
       → [Runtime trim] → [Layout/BSS] → MZ/COM writer
```

The mid-level passes operate on an SSA form of the bound AST (every
assignment creates a version; PHIs at joins), which is what makes the
whole-program reasoning below tractable — the same representation family a
modern C++/LLVM pipeline uses, adapted to PB's wrap-and-error semantics.

`$OPTIMIZE OFF` bypasses the whole pipeline and reproduces today's codegen
exactly — that is the pb35-compatibility escape hatch and the differential
control: every pass must keep all suites byte-identical in *output*.

## Pillar 1 — size: pay only for what you use (Must)

- **P1 Runtime trimming.** The assembler knows every label and fixup; emit the
  runtime as a reachability-closed set seeded from the labels generated code
  actually references. Hello world keeps `rt_print_str`, `rt_print_nl`,
  `rt_exit` — not the string heap, file table, x87 formatter or array engine.
  Gate: per-golden size regression tests + all suites green.
- **P2 Data-on-demand.** String descriptor table, capture buffer, file table,
  REG block, DATA pool: emitted only when the trimmed runtime references them;
  sizes become tunables next to `$STRING` (descriptor count 512 → configurable).
- **P3 BSS instead of image bytes.** Zero-initialized data (variable slots,
  tables) moves behind the image via MZ `MinAlloc` instead of being written as
  zero bytes into the EXE — costless on disk, zeroed by the entry stub.
- **P4 Right-sized memory footprint.** The 64-KiB-main + 2×64-KiB-heap layout
  becomes demand-driven: no string usage → no string segment; `$STACK` honored
  downward; MinAlloc computed from actual use instead of the fixed worst case.
- **P5 `.COM` output (`$COMPILE COM`).** Tiny model (CS=DS=SS, org 100h, no
  header, no relocations) for utilities — a trimmed hello world is the DOS
  classic `MOV AH,9 / MOV DX,msg / INT 21h / RET` ≈ 25–40 bytes.
- **P6 Header & padding squeeze.** Minimal MZ header (0x20 paragraph-aligned),
  no padding between trimmed sections, literal deduplication (exists) extended
  to cross-procedure tail-merging of identical code sequences.
- **P7 Intrinsic lowering of trivial I/O.** Pattern-match whole-program shapes
  before runtime selection: a program that only PRINTs literals and ENDs
  lowers to the DOS string writer directly (`MOV AH,9 / MOV DX,msg / INT 21h`
  with a `$`-terminated literal, then `INT 21h`/4Ch) — no PrintStr, no column
  tracking, no capture buffer; with the direct-video option (R1) the same
  shape becomes a `REP MOVSW` into B800h. That is the "hello world in a few
  bytes" path: ≈ 12 bytes of code plus the text in a `.COM`. Falls back to
  the generic runtime the moment column state, zones, USING or non-literal
  operands are involved.

## Pillar 2 — speed: compiler optimizations (Must)

- **O1 Constant propagation + folding** beyond equates (the `ConstantFolder`
  exists): variable-free expressions, single-assignment locals within a basic
  block, `IF` with constant conditions drops dead arms (the preprocessor
  already drops `$IF` regions).
- **O2 Dead-code & dead-store elimination.** Unreachable statements after
  `GOTO`/`EXIT`/`END`, stores to never-read temporaries (the stack-machine
  pattern produces many provably dead push/pop pairs).
- **O3 Common subexpression elimination** within a basic block — the SVGA
  corpus recomputes `y * 320 + x`-style addresses constantly. *(implemented,
  `CodeGen/OptCommonSubexpr.cs`)* A pre-pass marks pure integer subexpression
  trees that recur within a straight-line run; the first occurrence computes
  into a frame slot, the rest reload it. Two emission contexts are cached
  separately: genuinely integer-typed trees (LONG/DWORD/comparison) through
  the normal emitter, and the SINGLE-promoted modular-int16 trees (the
  `y*320+x` graphics case, computed on the 16-bit ALU) through
  `EmitModularInt16`. Soundness: a reload only ever follows a define from
  identical inputs with no intervening write or barrier, so any $ERROR trap
  the define would raise fires exactly where the un-CSE'd first occurrence
  would. Block-local: every call/branch/label/loop/POKE clears the cache, a
  scalar write invalidates the slots reading it; modular CSE is disabled when
  `$ERROR NUMERIC/OVERFLOW/ALL` is active (matching the emission gate).
  Oracle battery: `tests/diff/DIFF33.BAS`.
- **O4 Strength reduction & LEA multiply-add.** `* 2^n` → `SHL`; `\ 2^n` →
  `SAR` with PB-truncation fix-up; `MOD 2^n` → `AND`; loop induction
  variables (array pointers stepped by element size instead of re-indexed
  each iteration). Integer **multiply-add fuses into `LEA`**: even on 8086,
  `a + b + const` is one `LEA AX,[BX+SI+const]`; under 386 the scaled forms
  make `x*2+y`, `x*4+y`, `x*8+y` single instructions and `x*3`, `x*5`, `x*9`
  one `LEA EAX,[EAX+EAX*n]` — chains cover `*320` (`LEA` ×5, `SHL` 6) and
  the corpus's `y*320+x` pixel addressing in two flag-free instructions that
  also leave the operands intact for CSE reuse.
- **O5 Register allocation.** Hot 16-bit locals cached in SI/DI (today every
  local is a memory cell); FOR counters live in a register across bodies free
  of CALL/GOSUB; spills proven safe by the corpus gate.
- **O6 Procedure inlining.** `$OPTIMIZE INLINE` plus automatic inlining of
  small leaf SUB/FUNCTIONs (no STATIC, no ON ERROR, no GOSUB): parameters map
  to argument places, eliminating frame setup and BYREF indirection.
- **O7 Loop unrolling.** Constant-trip FOR loops unroll fully below a size
  budget or by factor 2/4 (`$OPTIMIZE UNROLL n`). Variable-trip loops unroll
  with a **Duff's-device entry** in the emitted assembler: the body repeats N
  times and execution enters the chain at offset `count MOD N` via a computed
  jump, so no scalar prologue loop is needed — profitable for strided or
  structured bodies that `REP` string ops cannot express (planar masks,
  per-element transforms). Must preserve the PB increment-then-test counter
  end value (QUIRK 2.28) — the counter cell holds the same final (possibly
  wrapped) value afterwards.
- **O8 Peephole + jump threading.** `MOV AX,0` → `XOR AX,AX` (flags-dead),
  push/pop elision, store/reload forwarding, jump-to-jump collapse,
  fallthrough inversion, `CMP x,0` → `TEST x,x`.
- **O9 String-temp economy.** Reuse handles across expression nodes instead of
  alloc/free per node; fold literal concatenation runs at compile time
  (feeding the O11 overlap packer); `LEN`/`MID$`/`LEFT$` over fixed buffers
  become constants/direct moves.

- **O10 Redundant-statement elimination.** Statements with provably
  unobservable effects disappear:
  - **Empty loops**: a FOR/DO body with no statements and no volatile reads
    reduces to its closed-form effects — the counter cell is set directly to
    the final (possibly wrapped, QUIRK 2.28) value, and an `$ERROR NUMERIC`
    overflow still raises exactly when the looped original would have.
    CAUTION: DOS-era code uses empty loops as **delay loops** — the pass is
    part of `$OPTIMIZE SPEED` only, and any TIMER/INP/PEEK access or
    `$OPTIMIZE HOT` annotation (C5) in scope keeps the loop.
  - **DEF SEG coalescing**: consecutive `DEF SEG`s with no intervening
    PEEK/POKE/PEEK$/POKE$/BLOAD/BSAVE/CALL ABSOLUTE collapse to the last;
    `DEF SEG` to the value already in effect drops entirely. Inline asm or an
    external call in between blocks the pass (either may read `rt_defseg`).
  - **Bounds-check elimination**: under `$ERROR BOUNDS`, duplicate checks of
    the same index/position in a dominating position collapse to one,
    loop-invariant checks hoist out of the loop, and checks proven in-range
    from constant bounds vanish. A check that *can* fail is observable
    behavior (error 9) — it is only deduplicated or hoisted, never dropped.
- **O11 Static-string interning with overlap.** The literal pool already
  deduplicates exact matches; pb36 packs literals into a greedy shortest
  common superstring so substrings and overlapping parts share bytes
  ("Hello, World!" also serves "World!" and "lo, W") — lengths are supplied
  at each use site, so any slice of the pool is addressable. Sound only while
  the pool stays provably read-only: escape analysis disables packing for
  literals whose storage can leak through VARPTR/STRPTR on literal-backed
  values, inline asm referencing literal labels, or BYREF/external (unit)
  calls that could write through the reference — exactly the
  pointers/asm/external-ref-call hazards. Escaping literals fall back to
  private copies.
- **O12 Float demotion ("de-floating").** PB defaults bare variables to
  SINGLE, so most DOS-era counters and flags are floats by accident. When
  whole-program analysis proves a SINGLE/DOUBLE variable only ever holds
  integral values inside INTEGER/LONG range (assignments from integer
  expressions, `+`/`-`/`*` chains with integral operands, FOR counters with
  integral bounds/STEP), re-type it silently and run it on integer registers
  — no x87 traffic, no scratch round-trips. Soundness: any `/`, fractional
  literal, EXP/SIN-class intrinsic, VARPTR/SEG escape, BYREF pass to an
  unproven callee, or DATA/READ blocks the demotion; PRINT/STR$ formatting is
  safe by construction (integral floats already print without a decimal
  point — verified against genuine PBC, QUIRKS.md).
- **O13 Silent fixed-point arithmetic.** Where float values provably carry a
  constant scale (monetary `*0.25`/`*0.01`-step chains, FOR loops with
  fractional constant STEP, interpolation accumulators), compute in scaled
  LONG fixed-point and convert at the observation boundary (PRINT/STR$/
  store-to-escaping-location). Only applied when **bit-exactness is
  provable**: power-of-two scales are always exact; decimal scales only when
  every intermediate stays within the exact-integer range of the original
  float type, otherwise the rounding of the x87 original could differ by an
  ULP and leak into PRINT output. FOR with STEP 0.25 becomes an integer
  counter with 2-bit fraction — the classic DOS demo-effect win.
- **O14 Tail-call optimization.** A CALL in tail position (last statement
  before END SUB/FUNCTION or EXIT) reuses the frame: arguments are rewritten
  in place and the call becomes a `JMP`, turning self-recursion into loops
  (PB allows recursion — deep recursions stop eating stack). Blocked when
  the frame must outlive the call: string/FLEX locals pending release, a
  BYREF argument pointing into the current frame, armed local ON ERROR
  state, or GOSUB return addresses on the stack. GOSUB+RETURN pairs in tail
  position thread to plain jumps the same way.
- **O15 Zero-cost UDT abstractions.** Escape analysis (shared with O11)
  classifies TYPE/UNION values; non-escaping ones (no VARPTR/SEG, no whole
  BYREF to unproven callees, no inline-asm reference, not in arrays/files)
  get:
  - **Scalar replacement (SROA)**: the UDT decomposes into independent field
    variables that register-allocate like plain locals — field access costs
    exactly a scalar access, the abstraction is free.
  - **Copy elision**: whole-UDT assignment between non-escaping values
    becomes per-live-field moves or nothing at all (forwarded source);
    `REP MOVS` block copies remain only for escaping values.
  - **Compare lowering**: the 3.1 whole-value `=`/`<>` memcmp becomes
    field-wise compares with early-out, which then fold further when fields
    are constant.
  - UNIONs decompose only when a single member is ever touched; LSET, FIELD
    and file GET/PUT force materialization back to the packed layout.
- **O19 Definite-assignment zero elision.** PB guarantees LOCALs start at
  0 / empty; the runtime today pays a whole-frame `REP STOSW` per invocation.
  When every local is provably assigned before any use, the fill is
  unobservable and disappears. Safety rails: dynamic STRING/FLEX handle slots
  always stay zeroed (their first assignment frees the previous handle and the
  epilogue releases them), error-handler re-entry (`ON ERROR`/`RESUME`) blocks
  the proof, and types embedding string handles never qualify. The same idea
  extends to arrays and string buffers (skip ArrAlloc zero fill when a full
  initialization loop dominates every read) — roadmap, needs the loop-fill
  pattern proof from O16's range analysis.
- **O16 Whole-program assignment tracking & value-range analysis.** Every
  assignment to every variable is tracked over SSA (constants, intervals,
  known bits, congruences `a MOD n = k`); ranges propagate through
  arithmetic, FOR bounds, and branch conditions (a `IF x% > 0` refines the
  range on each arm). What the lattice buys:
  - **Range narrowing as far as possible**: a LONG whose every reaching value
    fits 0..255 runs as a BYTE; EXT/DOUBLE collapse to SINGLE when precision
    is provably unused; cascades feed O12/O13 (de-floating, fixed-point) and
    shrink data slots, frames and spill traffic. CAUTION — PB wraps silently:
    narrowing must prove that *intermediates*, not just stored values, stay
    in range under the original type's wrap behavior, otherwise a 16-bit wrap
    would appear where 32-bit code wrapped differently (observable). With
    `$ERROR NUMERIC ON` the proof must also preserve *which* statement
    overflows first.
  - **Constant folding on steroids**: a variable assigned once (or assigned
    equal constants on all paths) folds at every use; decidable comparisons
    (`x% < 300` when x% ∈ 0..255) fold their branches, cascading into O2
    dead-code removal.
  - **Check elision**: array/string bounds checks (O10) and `$ERROR
    NUMERIC/OVERFLOW` test sites vanish where the range proves them
    redundant — never where they could fire.
- **O17 The modern pass catalog, adapted to PB.** Everything a C++/LLVM
  mid-end does that pays off at this scale, with PB-specific legality rules:
  - **SCCP** (sparse conditional constant propagation): constants and
    reachability solved together — stronger than O1's local folding.
  - **GVN** (global value numbering) superseding block-local CSE, with
    redundant-load elimination across statements.
  - **Memory SSA / alias analysis**: loads and stores get dependency edges;
    PB's aliasing barriers are explicit and few — VARPTR/STRPTR escape,
    BYREF parameters, `@p` stores, PEEK/POKE after DEF SEG, inline asm,
    external unit calls — everything else is provably non-aliasing (better
    than C++: no arbitrary pointer arithmetic to spoil the analysis).
  - **LICM + sinking**: loop-invariant address computations and string-handle
    lookups hoist; rarely-used computations sink into their branch.
  - **Reassociation & if-conversion**: integer chains reassociate to expose
    LEA/CSE patterns; short branches become branchless `SETcc`/`SBB` idioms
    (no CMOV before Pentium Pro — stays inside the 486 gate).
  - **Loop rotation, induction-variable simplification, fusion** of adjacent
    same-trip loops over the same arrays.
  - **Iterative cleanup**: inline → SCCP → GVN → DCE rounds until fixpoint,
    LLVM-style.
- **O18 Interprocedural & ABI optimizations ("plus more").** PB-Compiler
  sees the whole program by default (units only via `$LINK` — and even then
  it links the objects itself), so it can go where separate compilation
  stops C++ compilers:
  - **IPCP**: constant arguments propagate into callees; dead parameters are
    dropped; SUBs called with one argument shape get specialized clones.
  - **Internal calling convention**: intra-module calls pass leading scalar
    args in registers (AX/BX/CX:DX) instead of pushed near pointers; BYREF
    collapses to direct access after inlining (zero-cost with O15).
  - **Leaf-frame elision**: SUBs without locals/strings/GOSUB skip the whole
    BP frame and the frame-zeroing `REP STOSW`.
  - **Segment-register allocation**: keep ES pinned to the string/array heap
    across statement runs instead of reloading per access — a register class
    LLVM never gets to play with.
  - Escape hatches stay absolute: any inline asm, CALL INTERRUPT, CODEPTR
    or external reference in scope pins the standard ABI and full frames.

- **O20 Algorithmic idiom replacement.** Beyond statement-level passes, the
  compiler recognizes whole algorithms and substitutes better ones: series
  summations fold to closed forms, constant fills become string ops, empty
  loops become their counter end value (first wave implemented, above);
  copy loops (`dst(i)=src(i)` over a range) lower to one `REP MOVSW` between
  distinct 16-bit arrays (near/far segment dance, counter end preserved);
  further idioms (MIN/MAX scan, bubble-sort shapes -> ARRAY SORT) remain
  roadmap - each gated on bit-identical observables and `$OPTIMIZE SPEED`.

## Pillar 3 — 386/486 code generation (Must)

Real mode on a 386+ executes 32-bit operations via operand/address-size
prefixes — no protected mode required. Gated by the existing `$CPU`
metastatement (`-G386`, new `-G486`):

- **C1 `$CPU 80386`: 32-bit registers wherever they pay.**
  - LONG/DWORD arithmetic in EAX/EDX: one `ADD EAX, [x]` replaces the 4-op
    DX:AX pair dance; `IMUL r32, r/m32, imm` replaces the LongMul runtime
    call; 32-bit `DIV`/`IDIV` replaces LongDiv/LongMod. ✅ **divide/modulo by a
    compile-time-constant divisor of magnitude >= 2** uses the exact hardware
    `IDIV`/`DIV` (truncate toward zero, remainder takes the dividend's sign =
    PB's `\`/`MOD`); the `>= 2` gate rules out the divide-by-zero and `MININT \ -1`
    traps, so the runtime path is dropped only where it can't trap. Battery
    `tests/diff/DIFF71.BAS`. (Variable divisors still use LongDiv/LongMod.)
  - QUAD in EDX:EAX pairs (add/sub/cmp, shifts via `SHLD`/`SHRD`) instead of
    x87 round-trips where profitable. ✅ **64-bit bitwise AND/OR/XOR/EQV/IMP**
    (`EmitQuad386Bitwise`) run inline as two 32-bit halves in EAX instead of the
    runtime `QuadAnd/..` call (bitwise can't trap); battery `tests/diff/DIFF72.BAS`.
    ✅ **64-bit SHIFT LEFT/RIGHT** by a constant count 1..31 collapse the per-bit
    loop to `SHLD`/`SHRD` across the dword halves (EAX/EDX only); counts ≥ 32 and
    rotates stay on the loop; battery `tests/diff/DIFF73.BAS`. (QUAD *arithmetic*
    add/sub/mul stay on the x87 — they match PBC's lossy >2^53 behaviour.)
  - ✅ **32-bit SHIFT/ROTATE collapse** (`EmitShiftRotate`): a LONG `SHIFT`/`ROTATE`
    statement with a compile-time-constant count in 1..31 becomes a single
    `SHL/SHR/ROL/ROR dword [cell], imm8` instead of the CX-times per-word
    RCL/RCR loop. Constant 1..31 only (the 386 masks the count to 5 bits, so
    `>= 32`/runtime counts stay on the loop); `SHIFT RIGHT` stays logical.
    Battery `tests/diff/DIFF70.BAS` (byte-identical to genuine PBC 3.50, which
    accepts `$CPU 80386`).
  - `MOVZX`/`MOVSX` for BYTE/WORD widening (kills the `XOR AH`/`CWD` chains);
    `SETcc` for relational results (kills the branchy −1/0 sequences).
  - Scaled `LEA` for array addressing — base + index*size in one instruction.
  - **DWORD-wide block primitives**: `REP MOVSD`/`STOSD`/`CMPSD` for memory
    fills, copies, UDT assignment/SWAP/compare, string assigns, array zeroing
    and the BeginFrame zero-fill — misaligned head/tail bytes handled, ≈4× on
    (✅ `REP STOSD` ERASE static-array zero-fill `tests/diff/DIFF74.BAS`; ✅ `REP
    STOSD` constant FOR-loop array fill — 16-bit value broadcast into both EAX
    halves — `tests/diff/DIFF75.BAS`)
    fills and copies.
- **C2 NEW `$CPU 80486` gate** (new `LanguageFeature.Cpu486`, `-G486`):
  - `BSWAP` for endian flips (MKx$/CVx big-endian helpers, graphics masks);
    `XADD`/`CMPXCHG` exposed to inline-asm authors.
  - **Alignment-driven layout**: procedure entries are 16-byte-aligned (reached only by
    CALL, so the NOP pad never executes), and — **implemented** — under `$CPU 80486`/`80586`
    + `$OPTIMIZE SPEED` **hot loop tops are NOP-padded to a 16-byte boundary** (`AlignLoopTop`,
    on every loop emitter: the general FOR/DO, the int16-fast FOR, every register-resident /
    array-IVSR / auto-vectorized loop). The pad runs once on the fall-through entry and is
    skipped by the back-edge, so it is **output-invariant** — better instruction-fetch and
    branch-target prefetch on a 486/Pentium, with the differential oracle still byte-identical.
    DWORD-aligning hot data slots is the remaining piece.
  - Instruction selection tuned to the 486's 1-cycle simple ops: prefer
    `MOV/ADD/INC` chains over microcoded instructions (`LOOP` → `DEC CX/JNZ`,
    avoid `XLAT`/`ENTER`/`LEAVE`) — partially beneficial on the 386 too.
- **C3 x87 scheduling.** Keep loop-invariant constants resident on the FPU
  stack across unrolled bodies; avoid `FSTSW/SAHF` stalls where comparisons
  can run on pre-truncated integer values.
- **Branch-prediction-aware layout** (implemented, by construction). The codegen lays
  branches out for the static predictor *forward-not-taken / backward-taken*: an `IF`
  emits `EmitCondition; Jz else` — a **forward** conditional whose fall-through is the
  `THEN` body, so the predicted-not-taken path is the likely (`THEN`) one — and every loop
  closes with a **backward** `JMP top`/`Jcc top` back-edge (predicted-taken, the iterating
  case). So the common path is the fall-through and loop continuation by default.
- **Inline-assembly instruction scheduling** (implemented — `InlineAsmScheduler`). A run of
  three-plus consecutive single-instruction `!` lines is reordered to **group memory and ALU
  operations** and let independent dependency chains interleave (better load/store- and ALU-port
  / U-V-pipe utilization). A conservative def/use model per line (register RAW/WAR/WAW, flags, and
  memory where any write-involving pair with possibly-aliasing operands is ordered) yields a
  dependency partial order; the result is one valid topological order, so it is **output-preserving**
  (`MOV AX,a · ADD AX,5 · MOV BX,b · ADD BX,7` → both loads, then both adds). SAFETY BY CONSTRUCTION:
  the scheduler only *decides* the order — emission stays the unchanged text assembler — and any line
  it cannot model with certainty (an unknown mnemonic, jump, label, segment/FPU/SIMD operand,
  multi-instruction line) makes the whole block non-reorderable, so it is emitted verbatim. Gated to
  pb36 + `$OPTIMIZE SPEED` with no error handler in scope (reordering must not be observable through a
  fault's resume point); verified by the 241-battery oracle (byte-identical) + scheduler unit tests +
  execution (a regrouped block computes the same result).
- **Assembler-level instruction scheduling** (implemented — `Assembler.RunSchedule`). The same
  dependency-driven list scheduler now runs on the **final byte stream** — *after* loop unrolling,
  inlining and const-folding, since it operates on the emitted instructions, downstream of every
  codegen transform. Each MOV/ALU instruction records a conservative def/use descriptor (word-register
  reads/writes — a byte half maps to its word slot — flags, and memory with direct-cell / `[BP+disp]`
  stack / unknown-indexed aliasing); the scheduler finds maximal contiguous fixup-free, label-free
  windows (any *unrecorded* instruction — a jump, CALL, the implicit-AX MUL/DIV, an FPU/SIMD op — is a
  byte gap that ends the window), builds the dependency partial order, and rewrites the window's
  instruction byte-blocks in a topological order that issues loads first (latency hiding) and clusters
  memory/ALU work. The recorded instruction set is **MOV, the ALU group, INC/DEC, NEG/NOT, the shift
  family, LEA, TEST and the two-operand IMUL** — so a shift, an increment or an address computation no
  longer splits a window; the scheduler reorders *through* them (flag-writers pin a following ADC/SBB by
  the flag dependency, LEA contributes its address-register reads, CL-count shifts read CL). The
  implicit-AX/DX MUL/DIV/IDIV and one-operand IMUL stay barriers — their hidden operands make a
  conservative model unprofitable. Permuting whole instruction blocks inside a window needs no position
  fixups (length unchanged, nothing inside referenced), so it is **output-preserving** — verified
  byte-identical across all 241 batteries with the scheduler active on every pb36 + `$OPTIMIZE SPEED`
  program. It is the optimized-standalone counterpart to the peephole (the two rewrite by recorded
  position, so they are mutually exclusive: pb36 + SPEED gets the scheduler, every other optimized
  standalone keeps the peephole). DOSBox models no pipeline/cache, so the *benefit* is unmeasurable
  here — only correctness is.
  - **Register reassignment** to break the AX-centric serialization (so independent statement chains can
    interleave across registers) is the remaining amplifier, and it is a *distinct subsystem* rather than
    a small extension of the scheduler, for two concrete reasons. (1) **Free-register proof.** Renaming a
    value's register lifetime to a free register is sound only if that target is dead across the
    lifetime; at the byte level a window is bounded by barriers where, conservatively, *every* register
    is live-out, so without an external liveness signal the only provably-free targets are registers
    *redefined later in the same window* — which never holds in the exact AX-serial code the rename is
    meant to fix. Breaking AX-serialization therefore needs **codegen-supplied liveness** (the codegen
    knows almost nothing but `SP`/`BP` and the loop-induction `SI`/`DI` is live between scalar
    statements, so `BX`/`CX`/`DX` are genuinely free) threaded into the scheduling records. (2)
    **Length-changing re-encoding.** The scalar codegen emits the accumulator short forms (`MOV AX,imm` =
    `B8`, `ADD AX,imm` = `05`); renaming `AX`→`BX` turns `ADD AX,imm` into the modrm form `81 /0` which
    is one byte longer, so a rename is *not* length-preserving and forces the window — and every label
    and fixup after it — to be re-laid-out. That makes register reassignment a re-encoding register
    allocator (codegen liveness + per-operand register-field tracking + function relayout), built and
    verified on its own, not a byte-permute tweak.

3. **Speed gates**: cycle batteries (TIMER-bracketed fills, loops, PRINT

   merge-blocking (house rule).
4. **CPU gates**: 386/486 batteries run with DOSBox `cputype=386/486`, plus a

   assembler knows per-instruction CPU levels).
5. New surface (R4 intrinsics, S2 completions) gets NUnit + golden batteries;
   where genuine PB has the feature, differential batteries pin the behavior.
6. **Elimination-pass safety batteries**: empty-loop removal is pinned by
   counter-end-value and `$ERROR NUMERIC` batteries (the closed-form result
   must equal the looped result, including wrap); DEF SEG coalescing by
   PEEK/POKE interleavings; bounds-check passes by error-9 batteries; O11
   interning by a battery that takes STRPTR of literal-backed strings and
   mutates via MID$ — the packer must have backed off for those literals.
7. **Re-typing safety batteries**: O12/O13 are pinned by PRINT/STR$

8. **Range-analysis batteries** (O16-O18): wrap-semantics probes at every

## PB 3.6 object model & `YIELD` coroutines

A minimal, fully compile-time object model for pb36: TYPEs gain methods and
properties, and any `SUB`/`FUNCTION` containing `YIELD` becomes a generator whose
call returns a first-class enumerator built from that same object model. No
inheritance, no virtual dispatch, no late binding — every member call resolves
from the static type of the receiver at compile time.

This supersedes the separate-stack fiber strategy sketched in
the coroutines section below: coroutines lower to a **state machine** that rides on the
object model below, not to a context-switching fiber.

### 1. TYPE members (the foundation)

Surface (chosen): members are declared **inside** the `TYPE` block; the receiver
keyword is **`THIS`**.

```basic
TYPE Stack
  Count AS INTEGER
  Items(1 TO 100) AS LONG
  SUB Push(BYVAL v AS LONG)
    INCR THIS.Count
    THIS.Items(THIS.Count) = v
  END SUB
  FUNCTION Pop() AS LONG
    Pop = THIS.Items(THIS.Count)
    DECR THIS.Count
  END FUNCTION
  PROPERTY GET Size() AS INTEGER
    Size = THIS.Count
  END PROPERTY
  PROPERTY SET Size(BYVAL n AS INTEGER)
    THIS.Count = n
  END PROPERTY
END TYPE
```

#### Lowering

Every member lifts to an ordinary top-level procedure whose **implicit first
parameter is `THIS`, passed BYREF**, of the enclosing TYPE:

| member            | lifted procedure                                  | call site                       |
|-------------------|---------------------------------------------------|---------------------------------|
| `SUB M(p…)`        | `SUB Stack.M(THIS AS Stack, p…)`                  | `o.M(a)` → `Stack.M(o, a)`      |
| `FUNCTION M(p…) AS T` | `FUNCTION Stack.M(THIS AS Stack, p…) AS T`     | `o.M(a)` → `Stack.M(o, a)`      |
| `PROPERTY GET P() AS T` | `FUNCTION Stack.get_P(THIS AS Stack) AS T`   | `o.P` (rvalue) → `Stack.get_P(o)` |
| `PROPERTY SET P(v)` | `SUB Stack.set_P(THIS AS Stack, v)`             | `o.P = x` → `Stack.set_P(o, x)` |

The mangled names use `.` (`Stack.Push`, `Stack.get_Size`), which a user
identifier can never contain, so there is no collision; call resolution just
constructs the name from the receiver's static type + member and looks it up.
Member bodies reuse the existing BYREF-UDT-parameter machinery: `THIS.field`
is an ordinary `MemberExpr` field access through the BYREF param.

#### Auto-implemented & anonymous properties

A `PROPERTY GET`/`SET` with **no body** is auto-implemented over a hidden backing
field `$Prop`. Inside an explicit body, **`FIELD`** names that backing field and
**`VALUE`** names the setter's incoming value; `=>` gives an expression body:

```basic
TYPE Rect
  PROPERTY Width  AS LONG                       ' anonymous: auto getter + setter + field
  PROPERTY Height AS LONG
  PROPERTY GET Area AS LONG => THIS.Width * THIS.Height   ' computed, read-only
  PROPERTY SET Size() => FIELD = 2 * VALUE               ' FIELD = backing $Size, VALUE = incoming
END TYPE
```

`PROPERTY Name AS Type` with no `GET`/`SET` (anonymous form) expands to an auto
getter **and** an auto setter over one `$Name` field.

**Trivial methods inline (optimizer).** Accessors are ordinary lifted procedures
(`get_P` = `THIS.$P`, `set_P` = `THIS.$P = VALUE`) with no special-casing. The
general O6 inliner then inlines *any* trivial method body — auto-generated or
hand-written — by treating the `THIS` receiver as what it is: an ordinary BYREF
argument. A trivial method whose every call inlines is reachability-purged, so
`o.Count` (an anonymous property) ends up exactly as cheap as a field access, and a
hand-written `FUNCTION Sum() = THIS.x + THIS.y` inlines the same way. A method whose
body is too large, or a call where the receiver is not a near lvalue, falls back to
a real call.

#### Constructors

A member `SUB` **named like the TYPE** is its constructor; it has `THIS` access and
runs when an instance is built with `p = TypeName(args)`:

```basic
TYPE Point
  x AS LONG
  y AS LONG
  SUB Point(BYVAL px AS LONG, BYVAL py AS LONG)   ' constructor (same name as the TYPE)
    THIS.x = px
    THIS.y = py
  END SUB
END TYPE

DIM p AS Point
p = Point(3, 4)            ' -> Point.Point(p, 3, 4) with p as the BYREF THIS
```

`p = Type(args)` desugars to a call of the lifted `Type.Type(THIS, args…)` with the
assignment target as the BYREF receiver.

#### `READONLY` types

`TYPE Name READONLY … END TYPE` makes every field **write-once**: a field store is
allowed only inside that type's own constructor and rejected everywhere else at
compile time. This composes with anonymous properties — their setter routes through
the same field-store path, so `obj.Count = x` outside the constructor is a compile
error for a readonly type, while the constructor may set it.

```basic
TYPE Vec2 READONLY
  x AS LONG
  y AS LONG
  SUB Vec2(BYVAL ax AS LONG, BYVAL ay AS LONG)
    THIS.x = ax : THIS.y = ay     ' OK: inside the constructor
  END SUB
END TYPE
DIM v AS Vec2 : v = Vec2(1, 2)
v.x = 9                            ' compile error: field 'x' of READONLY TYPE Vec2 …
```

#### Bit-field members

A field declared `Name AS BIT * width` (1..16; `AS BIT` alone is width 1) occupies
`width` bits rather than a whole storage cell. Consecutive bit-fields are **packed**
into a hidden 16-bit `$bits` WORD in declaration order; a bit-field that would overflow
the current word starts a new one, and any non-bit field breaks the run.

```basic
TYPE StatusReg
  Mode    AS BIT * 3      ' bits 0..2  of $bits0
  Enabled AS BIT          ' bit  3     of $bits0
  Level   AS BIT * 4      ' bits 4..7  of $bits0
END TYPE
DIM r AS StatusReg
r.Mode = 5 : r.Level = 12 ' each write preserves the neighbouring fields
```

**Lowering** (pure binder desugar, no new codegen — `PackBitFields` + `BitFieldOf`):

- a **read** `r.Mode` → `(r.$bits0 >>> offset) AND ((1 << width) - 1)`
- a **write** `r.Mode = v` → `r.$bits0 = (r.$bits0 AND clearMask) OR ((v AND mask) << offset)`,
  a read-modify-write so the other fields in the word are untouched.

Because both desugar to ordinary WORD arithmetic, bit-fields ride the existing
shift/and/or codegen and the optimizer folds constant masks for free.

#### Layout control

By default a `TYPE` is **byte-packed** (no padding) — matching genuine PBC. pb36 adds
explicit control for hardware registers, file/wire formats and overlays:

```basic
TYPE Header ALIGN 4      ' each field on its natural boundary (capped at 4); total padded to 4
  tag    AS BYTE         ' offset 0
  length AS LONG         ' offset 4 (3 padding bytes after tag)
  flags  AS INTEGER      ' offset 8        -> LEN(Header) = 12
END TYPE

TYPE Sector SIZE 512     ' pad the whole record to exactly 512 bytes
  used AS INTEGER
END TYPE

TYPE RegView            ' explicit offsets: an overlay / union-style view
  whole AS LONG          ' offset 0
  lo    AS INTEGER AT 0  ' overlaps the low word
  hi    AS INTEGER AT 2  ' overlaps the high word -> LEN(RegView) = 4
END TYPE
```

- `PACKED` — the default byte layout, stated explicitly.
- `ALIGN n` (n = 1/2/4/8/16) — pad each field up to an n-byte boundary, but never past its
  own natural alignment (a `BYTE` stays contiguous even under `ALIGN 4`), and round the whole
  type up to a multiple of n.
- `SIZE n` — pad the whole type to exactly n bytes (must be ≥ its natural size).
- `field AS T AT offset` — place a field at an explicit byte offset; gaps and overlapping
  fields are allowed, and the type's size spans to the highest field end.

This is pure binder layout (`DefineUdt` computes each `UdtField.Offset` and the `UdtType`
size), so member access, array-of-TYPE strides and whole-TYPE block copies all use the
controlled offsets with no codegen change. pb36-only — genuine PBC has no layout keywords,
so it is verified by `LEN`/`VARPTR` execution tests, not the differential oracle.

#### Nullable types

`DIM x AS T?` is a **nullable**: a synthesized value-type UDT with a `Value` field of T and an
INTEGER `HasValue` presence flag (so `$nul@LONG`, etc.). It models "a value, or nothing"
without sentinel values.

```basic
DIM age AS INTEGER?
age = 30              ' Value = 30, HasValue = TRUE
age = NOTHING         ' HasValue = FALSE (the empty state)
PRINT age ?? -1       ' 30 here; -1 after NOTHING  (null-coalescing)
DIM n% : n% = age + 5 ' a nullable auto-unwraps to .Value in arithmetic / plain assignment
IF age.HasValue THEN PRINT age.Value
```

- `x = value` sets `Value` and `HasValue = TRUE`; `x = NOTHING` clears the flag; `x = otherNullable`
  copies both fields.
- `x ?? d` (null-coalescing) lowers to `IF(x.HasValue, x.Value, d)` — `d` is evaluated only when `x`
  is empty.
- A nullable used as a value auto-reads `.Value` in a binary operand position and when assigned to a
  plain (non-nullable) variable; `.Value` / `.HasValue` are also directly accessible.

**Syntax note (the `?` collision).** `?` / `??` / `???` are already the BYTE / WORD / DWORD type
suffixes, so the lexer disambiguates a glued `?` run **by context** — what follows it, not
whitespace: a `??` immediately before an operand is the coalescing operator, otherwise it is the
type suffix. So `a??15` is `a ?? 15`, `a????5` is `(a AS WORD) ?? 5`, while terminal `a??` (or
`a?? + 1`) stays the WORD suffix; `a ?? 15` with spaces works too. The split triggers on an
unambiguous operand — a digit, string or `$"…"` — only; a default that begins with an
*identifier/keyword/sign/paren* needs a space (`a ?? other`, `a ?? -1`, `a ?? (x+1)`), so a
binary keyword like `AND` or an array subscript `w??(i)` after a suffixed value is never read as
an operand. In a type position a type keyword carrying a single `?` (`LONG?`) is the nullable marker. v1 covers nullable **variables**
(a nullable struct field or array element is a plain UDT — assign its `.Value`/`.HasValue`
explicitly) and integer/string value types; floats work as the value too. pb36-only, verified by
execution + binder tests.

#### Wide integer types (`INT128` … `UINT512`)

pb36 adds fixed-size **wide integers** beyond the native 64-bit `QUAD` — signed `INT128`,
`INT256`, `INT512` and unsigned `UINT128`, `UINT256`, `UINT512` — for cryptography, checksums
and bignum-style work. They are **emulated as multi-word values** (`ByteSize / 2` little-endian
16-bit words in memory: 8 / 16 / 32 words), so they work on any 8086+ target, not just modern CPUs.

```basic
DIM big AS INT128          ' 16 bytes (LEN(big) = 16), 8 words
big = -5                   ' the constant is sign-extended across all 8 words
DIM x&  : x& = SomeLong()
big = x&                   ' a runtime LONG sign-/zero-extended (by the source's signedness)
DIM lo& : lo& = big        ' truncate back to the low 32 bits
```

**Foundation (this increment):** declaration and sizing (`DIM`, `LEN`/`SIZEOF`), and the conversions
to and from the native scalars — a compile-time constant stores its sign-extended words directly; a
runtime narrow value is loaded into `AX`/`DX:AX` and the upper words filled with the sign (`CWD`) or
zero per the source's signedness; `wide = wideVar` copies the common low words and extends; `narrow =
wideVar` truncates to the low word(s).

**Add / subtract** of two same-width wide values is wired: `c = a + b` / `c = a - b` emits a multi-word
**ADC / SBB chain** from the low word up, so a carry (or borrow) propagates through every word —
`3000000000 + 3000000000` correctly carries past the 32-bit boundary, and `0 - (-1) = 1` borrows
correctly. Verified by execution (round trips and carry/borrow cases match) + binder/codegen unit
tests; pb36-only (genuine PBC has no wide integers). **Follow-ups:** compare, bitwise, shift and
multiply, decimal `PRINT`, and `>64`-bit literals — those still report a clear *"not yet supported"*
diagnostic rather than miscompiling.

#### Implementation status

**Implemented** (`PowerBasic.Compiler/Semantics/Binder.cs`): methods, properties
(explicit, auto, anonymous, `=>` / `FIELD` / `VALUE`), trivial-accessor inlining,
constructors, `READONLY` enforcement, **bit-field members** (`AS BIT * n`), and
**layout control** (`PACKED` / `ALIGN n` / `SIZE n` / field `AT offset`).
Members lift in `DefineTypeMembers`; calls
resolve in the `MemberExpr` / `IndexExpr` / `MemberCallStmt` binding paths via
`Desugared` / `DesugaredStatements`; the FUNCTION/PROPERTY-GET result alias is the
member's simple name (`proc.ResultName`); `THIS` BYREF reuses the existing
BYREF-UDT-parameter backend (no new codegen).

Verification: pb36-only surface with **no differential oracle** (PBC 3.50 has no
TYPE methods), so each feature is verified by *execution* (compile + run in DOSBox,
compare to a hand-computed expected) plus unit tests
(`TypeMemberBinderTests`, `CoroutineBinderTests`); the full differential harness
stays byte-identical (the feature is inert for every existing battery).

### 2. `YIELD` → state machine → enumerator

Any `SUB`/`FUNCTION` whose body contains `YIELD` is **automatically** a generator
(no `ITERATOR` keyword). Calling it returns a first-class **enumerator** value
(a synthesized UDT) that can be stored in a variable and driven manually with
`.Reset` / `.MoveNext` / `.Current`, or consumed by `FOR EACH`.

```basic
FUNCTION Squares(BYVAL n AS INTEGER) AS LONG
  FOR i AS INTEGER = 1 TO n
    YIELD i * i
  NEXT
END FUNCTION

DIM e AS Squares                 ' the synthesized enumerator type
e = Squares(5)
WHILE e.MoveNext : PRINT e.Current : WEND
' or:
FOR EACH v AS LONG IN Squares(5) : PRINT v : NEXT
```

#### Lowering

For a generator `G` returning element type `T`, synthesize a UDT
`G` (the enumerator) with fields:
- `__state AS INTEGER` — resume point (0 = not started, -1 = done, k = after yield k),
- the generator's **parameters and locals** (captured as fields so they persist across resumes),
- `__current AS T` — the last yielded value.

and members (lifted exactly as in §1):
- `FUNCTION MoveNext() AS INTEGER` — `SELECT CASE THIS.__state` dispatches to the resume
  label; runs the body until the next `YIELD x` (set `THIS.__current = x`, `THIS.__state = k`,
  return true) or the end (`THIS.__state = -1`, return false). Built as an AST→AST transform
  to `SELECT` + `GOTO` + labels, reusing the existing control-flow backend.
- `PROPERTY GET Current() AS T` — returns `THIS.__current`.
- `SUB Reset()` — `THIS.__state = 0` and re-seed the captured parameters.

The generator call `G(args)` lowers to: allocate a `G` instance, store `args` into its
parameter fields, set `__state = 0`, return it.

**Supported `YIELD` positions** (all flattened to the resumable state machine, nesting
freely): top level, inside `FOR` / `WHILE`-`DO`-`LOOP` / `IF` / `SELECT CASE`, inside a
`FOR EACH` over *another* generator (the inner enumerator persists across the outer yields
as a `$fe<n>` UDT field, and the loop variable persists as its own captured field), and
inside `TRY` / `CATCH` / `FINALLY`. Parameters and locals (suffix- or `AS`-typed) are
captured as enumerator fields and survive suspension; `INCR`/`DECR` of a captured variable
persists too. A `SELECT CASE` that yields requires a side-effect-free subject (it is
compared once per arm).

#### `YIELD` inside `TRY` / `CATCH` / `FINALLY`

The normal `TRY` arms the ON ERROR handler on the **stack** (it pushes the previous
`rt_onerr` / `_bp` / `_sp` triple and pops it on exit). A `YIELD` does `EXIT FUNCTION`,
which unwinds that frame — so the stack save can't survive a suspension. The generator
state machine instead:

- snapshots the **caller's** handler triple into three enumerator fields
  (`$gonerr` / `$gbp` / `$gsp`) at the top of every `MoveNext` invocation;
- **arms** its own catch dispatcher (`rt_onerr = OFFSET catch`, `_bp = BP`, `_sp = SP`) on
  entry to the protected body and again at each resume into it (each `MoveNext` runs in a
  fresh frame, so the armed SP/BP must be this frame's);
- **disarms** (restores the caller's triple from the fields) before each in-`TRY` `YIELD`'s
  `EXIT`, so consumer code between `MoveNext` calls runs under the caller's handler, and on
  normal completion / at the catch-dispatch label.

A fault in the protected body during a `MoveNext` call lands on the armed dispatcher (SP/BP
restored to that invocation's frame), runs `CATCH` then `FINALLY`; a `TRY … FINALLY` with no
`CATCH` re-raises the still-set `ERR` to the now-restored outer handler. Yields in `CATCH`
and `FINALLY` are ordinary (the handler is already restored there). These are synthesized
`HandlerSave` / `HandlerArm` / `HandlerRestore` / `HandlerReraise` statements with bespoke
codegen. **Not yet supported**: a `TRY` that yields while itself nested inside another
yielding `TRY` (rejected with a clear diagnostic).

### Generated-name safety

Every compiler-synthesized name that shares the user's namespace is prefixed so it can
never collide with source identifiers. A user identifier must START with an ASCII letter
(`Lexer.IsIdentifierStart`), so:
- variable/field-namespace names (property backing fields `$Prop`, coroutine state fields
  `$state`/`$current`, ...) use the leading `$` prefix (`Binder.GeneratedPrefix`) — untypeable;
- procedure-namespace names (`Type.Method`, `Type.get_P`) embed a `.` — also untypeable as one
  identifier.

User-facing keywords inside member/property bodies (`THIS`, `VALUE`, `FIELD`) are deliberately
ordinary letter identifiers — they are written by the programmer, not hidden sugar.

### Future work: decompiling weaved code

A pretty-printer that re-emits BASIC source from the fully-bound, desugared, optimized AST/IR
(after member lifting, property/coroutine weaving, and the optimizer passes) would let us read
what the compiler actually produced "without the magic" — invaluable for debugging the lowerings
and the optimizer. Tracked as a later task (see memory: pb36-source-writer).

### 3. `FOR EACH` over a generator

`FOR EACH` is currently parse-time sugar to a counted `ForStmt`, which only fits
arrays/ranges. Introduce a real `ForEachStmt` AST node lowered by the **binder**
per the collection's static type:
- array / `[lo..hi]` range → today's counted loop (unchanged),
- generator/enumerator type → `e = coll : WHILE e.MoveNext : v = e.Current : <body> : WEND`.

Because the enumerator is an ordinary UDT with lifted members (§1), `FOR EACH` and
manual `.MoveNext`/`.Current` use the identical machinery.

## PB 3.6 compile-time generics (monomorphization)

**Status: generic TYPEs and generic procedures implemented (procedure type arguments are inferred;
explicit `Name OF type(args)` call syntax is the remaining follow-up).** A design for generic `TYPE`s and
procedures that are *fully vivified into concrete implementations at compile time*
— like C++ templates / Rust / .NET value-type generics: no runtime type info, no
boxing, no dispatch. Each distinct instantiation becomes an ordinary concrete TYPE
or procedure, after which the existing object-model machinery
(see the object-model section) handles it unchanged.

This rides directly on the existing model: a generic `Stack OF T` is just a
template; `Stack OF LONG` substitutes `T := LONG` to produce a concrete `Stack`
UDT whose members lift exactly as today.

### Surface syntax

Recommended: the VB-idiomatic **`OF`** keyword (parens conflict with array bounds,
angle brackets conflict with the `<` / `>` operators).

```basic
TYPE Stack OF T
  Count AS INTEGER
  Items(1 TO 100) AS T
  SUB Push(BYVAL v AS T)
    INCR THIS.Count
    THIS.Items(THIS.Count) = v
  END SUB
  FUNCTION Pop() AS T
    Pop = THIS.Items(THIS.Count)
    DECR THIS.Count
  END FUNCTION
END TYPE

DIM s AS Stack OF LONG          ' instantiates the concrete Stack OF LONG
s.Push(10) : PRINT s.Pop()
```

- **Multiple parameters**: `TYPE Pair OF (K, V)` / `DIM p AS Pair OF (INTEGER, STRING)`
  (parens required for >1 to keep `DIM a AS T OF X, b AS U` unambiguous; a single
  parameter needs no parens).
- **Generic procedures**: `FUNCTION Max OF T (BYVAL a AS T, BYVAL b AS T) AS T`.
  Call as `Max(3, 4)` (T inferred from arguments) or `Max OF LONG (3, 4)` (explicit).
- **Generic generators / constructors / properties / READONLY** all follow for free —
  the instantiated TYPE is a normal TYPE, so generators, `THIS`-constructors, auto
  properties and `READONLY` work per-instantiation with no extra machinery.

### Mechanism: a pre-bind monomorphization pass

A new pass runs **before** the binder's main scan, turning templates + use-sites
into concrete declarations the rest of the compiler already understands.

1. **Collect templates.** Parse a `TYPE`/`SUB`/`FUNCTION` carrying an `OF <params>`
   list into a *template* (its AST + the type-parameter names). Templates are NOT
   bound or lowered directly — they have no concrete layout.
2. **Discover instantiations.** Scan the whole program for instantiation sites:
   `AS <Generic> OF <args>` in DIM / parameters / fields / `NEW`, and generic
   procedure calls (explicit `OF` or inferred from argument types). Each yields a
   `(template, type-args)` key.
3. **Fixpoint.** Substituting a template can reference *other* generics
   (`Stack OF T` whose field is `List OF T` ⇒ needs `List OF LONG`). Iterate a
   work-list until no new instantiation appears. Dedupe by key so each concrete
   form is produced once.
4. **Substitute.** For each instantiation, clone the template AST with a
   `TypeName` rewriter mapping each type parameter (`TypeName(None, UserTypeName:
   "T")`) to its concrete `TypeName`, across fields, member signatures, and member
   bodies (including `DIM`s and casts inside bodies). Emit a concrete `TypeDecl` /
   procedure named by a **collision-free mangle** — e.g. `Stack@LONG`,
   `Pair@INTEGER@STRING` (the `@`/`.` separators can't occur in a user identifier,
   like the existing `Type.Member` mangling).
5. **Bind normally.** Inject the concrete declarations into the unit; the existing
   `DefineUdt` / `DefineTypeMembers` / member-call resolution handle them with zero
   changes. `DIM s AS Stack OF LONG` resolves to the concrete `Stack@LONG` UDT.

Result: after this pass the program contains only concrete types — the generic
surface has been fully "vivified", and the back end is unchanged.

### Type inference for generic procedures

`Max(3, 4)` binds the arguments, unifies each parameter's declared type pattern
against the argument type (`a AS T`, `b AS T` ⇒ `T = INTEGER`), checks consistency,
then resolves the call to the `Max@INTEGER` instantiation. Explicit `Max OF LONG`
skips inference. Mirrors the existing overload-resolution tie-break that already
ranks by argument-type match.

### Open decisions

- **Constraints** (later): `OF T AS NUMERIC` / `AS ANY` for friendly diagnostics
  and to gate operator use. v1 is unconstrained — an unusable `T` surfaces as an
  ordinary error inside the instantiated body (C++ pre-concepts style).
- **Recursive generics**: distinct `(template,args)` keys terminate the fixpoint,
  but a *direct, non-pointer* self-containing field (`Tree OF T` with a `Tree OF T`
  field) is infinite-size and must error like any recursive TYPE; a `Tree OF T PTR`
  field is fine.
- **Separator char** for the mangle (`@` vs `.`) — pick one unused elsewhere.
- **Inference depth** — v1 infers only from direct parameter types (no nested
  `Stack OF T` argument unification); widen later if needed.

### Verification

pb36-only surface with **no differential oracle** (PBC 3.50 has no generics):
verify each piece by *execution* (compile + run in DOSBox vs. a hand-computed
expected) plus binder/parser unit tests, and keep the full differential harness
byte-identical (generics are inert for every existing battery — no template, no new
code). Suggested first slice: a single-parameter generic `TYPE … OF T` with one
method, instantiated at two concrete types, proving both monomorphize and run; then
generic procedures with inference; then transitive/fixpoint instantiation.

### Implementation status

**Done — generic TYPEs** (`PowerBasic.Compiler/Semantics/Monomorphizer.cs`): `TYPE Name OF T … END TYPE`
templates and `AS Name OF <args>` uses parse (the `Generics` feature, pb36-gated); a pre-bind pass
collects templates, discovers uses (reflection walk over the AST), and runs the work-list fixpoint,
deep-cloning each template with `T`→argument substitution into a concrete `TypeDecl` named by
[`Mangle`](#mechanism-a-pre-bind-monomorphization-pass) (`Box@Long`), spliced in just after the user
type declarations (in dependency order). The binder resolves a generic-use type name to that mangle in
`ResolveTypeName`, so the object-model machinery (fields, methods, properties, the BYREF `THIS`
receiver, the trivial-method inliner) all apply per instantiation with no back-end change. Verified by
execution (`Box OF LONG`/`OF INTEGER`/`OF STRING` distinct instances, fields and methods correct) and
`GenericsBinderTests`; the full differential harness stays byte-identical (the pass is inert when a
program declares no generic template).

**Done — generic procedures** (`Binder.ResolveGenericCall`): `SUB`/`FUNCTION … OF T` declares a
template; a call **infers** each type parameter from the argument types (read off the first parameter
declared as that bare type), monomorphizes a concrete instance (`Max@Long`) by deep-cloning the
parameters/return/body with the type parameters substituted, and binds the call to it. A user generic
template shadows a same-named intrinsic. Instance bodies are bound by a drain after the main pass (so
instantiating during binding never mutates the procedure list mid-iteration; an instance that itself
calls a generic is covered). Verified by execution (`Max`/`Exchange` at LONG/INTEGER/STRING, including
a `DIM t AS T` body local and BYREF write-through) and `GenericsBinderTests`.

**Pending — explicit procedure type arguments** (`Max OF LONG (…)` at the call site) and inference from
nested positions (a `Stack OF T` parameter); a type parameter appearing only in the return type is
rejected (it cannot be inferred from arguments).

**Known limitation (pre-existing, not generics-specific):** assigning to an *array field element*
through a method's `THIS` receiver (`THIS.Items(i) = v` inside a member) is rejected ("expression is
not assignable") in any TYPE, generic or not — tracked separately.

### Why it fits now

The object model already lowers every member to a concrete procedure keyed by the
receiver's static type, and already mangles names with characters users can't type.
Generics add exactly one front-end stage — substitute-and-name — ahead of that, so
the "cool stuff resolved entirely at compile time" is a source-to-source expansion
with no runtime surface and no back-end change.

## PB 3.6 — coroutines via `YIELD`

Design sketch for a coroutine facility in `--dialect pb36`: a SUB/FUNCTION that
can **suspend** mid-execution, hand a value back to whoever resumed it, and later
**continue** from exactly that point with all of its locals intact.

This is a pure pb36 extension. Genuine PowerBASIC 3.50 — the differential oracle
— has no `YIELD`, so a coroutine program can never be byte-verified against PBC.
Like the other pb36-only surface (shift/rotate operators, lambdas, `FOR EACH`),
it is gated to pb36 and rejected in every older dialect with the standard
`requires PowerBASIC 3.6` message; pb36 execution tests in DOSBox are the only
available verification gate for the eventual code generator.

Status: **front-end prototype only.** Lexer/parser/AST and the dialect gate are
in place and unit-tested; binding type-checks the yielded value. No code is
generated yet — `YieldStmt` falls through to the code generator's `Unsupported`
path, which is intentional until the strategy below is built out.

---

### 1. Surface syntax

#### 1.1 Declaring a coroutine

A coroutine is an ordinary SUB or FUNCTION marked with a leading `COROUTINE`
modifier. The marker is required (rather than inferring "is a coroutine" from the
presence of `YIELD`) so the property is visible at the declaration and at every
`DECLARE`, and so a non-coroutine proc that happens to contain the word `YIELD`
is never silently reinterpreted:

```basic
COROUTINE FUNCTION Counter(BYVAL first AS LONG, BYVAL last AS LONG) AS LONG
  DIM i AS LONG
  FOR i = first TO last
    YIELD i            ' suspend, surfacing i; resume continues the FOR
  NEXT
END FUNCTION
```

A coroutine FUNCTION's return type is the **element type** surfaced by `YIELD`
(here `LONG`). A coroutine SUB yields nothing typed and is consumed only for its
side effects between suspensions.

`YIELD <expression>` is the suspension point. Its expression must be assignable to
the coroutine's return type. `YIELD` outside a `COROUTINE` proc is a bind-time
error.

#### 1.2 Consuming a coroutine

Two consumption forms, both idiomatic to the existing language:

**(a) `FOR EACH` drive (preferred).** pb36 already has `FOR EACH ... IN ...`
(see `LanguageFeature.ForEach`). Extend its `IN` source to accept a coroutine
call. Each pass resumes the coroutine to its next `YIELD`; the loop ends when the
coroutine runs off its `END FUNCTION`:

```basic
DIM n AS LONG
FOR EACH n IN Counter(1, 5)
  PRINT n                       ' 1 2 3 4 5
NEXT
```

**(b) Explicit handle + `RESUME`-style pull.** For producers consumed
irregularly, a coroutine call in a value context yields a *coroutine handle*
(a fat value: a far pointer to the saved context — see §3). A new intrinsic
advances it:

```basic
DIM g AS COROUTINE              ' opaque handle type (DWORD-sized)
DIM v AS LONG
g = Counter(1, 5)              ' create, do not start
DO WHILE RESUMING(g)          ' advance to next YIELD; FALSE once exhausted
  v = YIELDED(g)              ' the value from the last YIELD
  PRINT v
LOOP
```

`RESUMING(g)` resumes `g` and returns non-zero while a value was produced;
`YIELDED(g)` reads the most recently surfaced value. Form (a) is sugar over (b).

The prototype in this branch parses only the **`YIELD <expression>` statement**;
`COROUTINE`, the handle type, and the consumption intrinsics are specified here
but deferred to the implementation phases.

---

### 2. Semantics

- **First call does not run the body.** Calling a coroutine constructs a context
  and returns a handle in the suspended-at-entry state. The body advances only on
  the first resume. (This matches generator semantics and keeps `FOR EACH`'s
  pre-test loop natural.)
- **Suspend.** `YIELD e` evaluates `e`, stores it where the resumer can read it,
  saves the coroutine's execution state, and transfers control back to the
  resumer.
- **Resume.** Control re-enters immediately after the last executed `YIELD`, with
  every local, the FOR/DO loop state, and the instruction pointer restored.
- **Completion.** Falling off the end (or `EXIT FUNCTION`/`EXIT SUB`) marks the
  handle exhausted: `RESUMING` returns false and `FOR EACH` stops. Resuming an
  exhausted handle is a no-op returning false.
- **Local state preservation** is the whole point: locals live in the
  coroutine's own frame, which persists between suspensions (it is *not* torn
  down on `YIELD` — see §3).
- **Re-entrancy.** Each call to a coroutine creates an independent context, so
  the same coroutine can have many live instances; a coroutine may itself drive
  other coroutines.
- **Lifetime.** A handle's context must outlive the last resume. For the explicit
  form the context is heap-allocated and freed when the handle goes out of scope
  or is exhausted; for the `FOR EACH` form the loop owns it and frees on exit.

---

### 3. Compilation strategy for 16-bit x86

Two classic implementations were weighed against the *actual* shape of this
compiler (recursive-descent parser → AST → binder → `CodeGenerator` emitting
real x86; frame model in `CodeGenerator.Procs.cs` / `CodeGenerator.cs`).

#### 3.1 Option A — state-machine / CPS transform (rejected for now)

Rewrite the coroutine body into a switch over a saved "resume state", hoisting
every local that is live across a `YIELD` into a heap record, and turning each
`YIELD` into "store state, return". This is how C#/Roslyn lowers iterators.

Why it is hard *here*:

- It is an **AST-to-AST control-flow transform**, but the AST mixes structured
  blocks (`FOR`, `DO`, `SELECT`, `IF`, `TRY`) with unstructured `GOTO`/`GOSUB`
  and label statements. A correct transform must reconstitute arbitrary control
  flow as a resumable state machine — essentially a full CFG-relooper. The
  compiler has a CFG only under the optional SSA path (`CodeGen/Ssa`), not on the
  mainline AST→asm route, so this would be sizeable new infrastructure.
- Liveness across suspensions, the closure-style hoisting of locals, and
  interaction with `ON ERROR`/`RESUME` and `GOSUB` return stacks make it
  error-prone.

It is the more portable technique (it would survive a future non-x86 backend via
the IR), but it does not fit the current mainline. Keep it as a long-term option
should coroutines need to ride the typed IR.

#### 3.2 Option B — separate-stack fiber / context switch (**recommended**)

Give each coroutine instance its **own stack**, and implement `YIELD`/resume as a
register-level stack switch. The body is emitted as an *ordinary* SUB/FUNCTION —
same prologue/epilogue, same BP-relative locals via the existing `LayoutFrame`
(`CodeGenerator.Procs.cs:52`) and `BeginFrame` (`CodeGenerator.cs:649`) — and its
frame simply *lives on the coroutine's stack* across suspensions instead of being
unwound. No body rewrite, no liveness analysis, no relooper. This reuses almost
all of the existing procedure machinery and is the natural fit for the AST→asm
pipeline.

##### Context record

A coroutine handle is a far pointer to a heap-allocated context:

```
CoroCtx (in the coroutine's own stack block, header at the base):
  +0   resumer_sp    WORD   ; resumer's SP, saved on resume / restored on yield
  +2   resumer_bp    WORD
  +4   coro_sp       WORD   ; coroutine's SP,  saved on yield  / restored on resume
  +6   coro_bp       WORD
  +8   state         WORD   ; 0 = at-entry (not started), 1 = suspended, 2 = done
  +10  value_lo      WORD   ; last YIELDed value (widened to the proc's return slot)
  +12  value_hi      WORD
  +14  stack_seg     WORD   ; segment/handle of the allocated stack block (for free)
  ...  (coroutine's growing stack grows downward from the top of the block)
```

The model is single-threaded cooperative: only one of {resumer, coroutine} runs
at a time, so a single saved (SP,BP) pair per side is sufficient. SS stays the
program's single stack segment in the small/compact memory model the compiler
targets, so the stacks are distinct *regions* of the one stack segment (a block
carved from the runtime heap), and a switch is just an `SP`/`BP` reload — no SS
reload, no far stack. (If a future large/huge model is supported, the switch must
also swap SS; the context record already reserves `stack_seg` for that.)

##### `YIELD e` — emitted inline at each suspension point

```asm
        ; ... evaluate e into AX[:DX] as usual ...
        mov   bx, [bp + ctx]        ; ctx = hidden first parameter (far/near ptr to CoroCtx)
        mov   [bx + 10], ax         ; value_lo
        mov   [bx + 12], dx         ; value_hi (for LONG; omitted for INTEGER)
        mov   word ptr [bx + 8], 1  ; state = suspended
        mov   [bx + 2], sp          ; (resumer_sp/bp were stored by the resumer; we save ours)
        mov   [bx + 4], sp          ; coro_sp  <- our SP
        mov   [bx + 6], bp          ; coro_bp  <- our BP
        mov   sp, [bx + 0]          ; restore resumer SP
        mov   bp, [bx + 2]          ; restore resumer BP
        ret                          ; returns into the resumer right after its RESUMING call
yield_resume_N:                      ; resume re-enters here
        ; locals are exactly as they were — same SS, same BP-frame
```

The trick: the coroutine's frame is never torn down at `YIELD`. We switch the
hardware stack to the resumer's, so the coroutine's frame sits dormant until the
next resume reloads `coro_sp`/`coro_bp` and jumps to `yield_resume_N`.

##### Resume (`RESUMING(g)`) — runtime helper

```asm
        ; bx = ctx
        cmp   word ptr [bx + 8], 2   ; done?
        je    .exhausted
        mov   [bx + 0], sp           ; save resumer SP/BP into ctx
        mov   [bx + 2], bp
        cmp   word ptr [bx + 8], 0   ; at-entry (never started)?
        jne   .resume_suspended
        ; first resume: set SP to top of the coro stack block, BP=0, call the body
        mov   sp, <top of stack block>
        xor   bp, bp
        push  bx                      ; pass ctx as the hidden parameter
        call  Coro_Body               ; runs until its first YIELD (which does the switch back)
.resume_suspended:
        mov   sp, [bx + 4]            ; restore coro SP
        mov   bp, [bx + 6]            ; restore coro BP
        jmp   <saved resume IP>       ; continue after the last YIELD
```

(The "saved resume IP" is the simplest variant: each `YIELD` site stores its own
`yield_resume_N` label address into the context, so resume is an indirect jump.
Equivalently, the body can keep its own resume dispatch — but the IP-in-context
approach keeps the body a straight-line emission with no added switch.)

When the body falls off the end, its epilogue sets `state = 2` and switches back
to the resumer one last time; `RESUMING` then returns false.

##### Why this fits

- **Reuses the frame model unchanged.** Prologue/epilogue, BP-relative locals,
  parameter passing, string cleanup — all emitted exactly as today. A coroutine
  is "a normal proc whose stack we keep around".
- **No control-flow rewrite.** `FOR`, `DO`, `GOSUB`, nested calls inside the
  coroutine all just work, because they run on the coroutine's own stack.
- **Small, local codegen.** Each `YIELD` is a fixed instruction sequence; resume
  is one runtime helper. The only new allocation is the per-instance stack block.

##### Hard parts (must be handled before this ships)

- **Stack sizing.** Each coroutine instance needs a stack big enough for its
  deepest call chain. Honour `$STACK`; expose a per-coroutine size (e.g.
  `COROUTINE(2048) FUNCTION ...`); detect overflow with the same
  `CMP SP,[rt_stackmin]` guard the existing prologue uses
  (`CodeGenerator.Procs.cs:112`), but against the *coroutine's* limit.
- **`ON ERROR` / `RESUME` and the GOSUB return stack.** The error-handler
  context (`rt_onerr`, `rt_onerr_bp`, `rt_onerr_sp`) is already saved/restored
  around procedures (`CodeGenerator.Procs.cs:188`). The stack switch must
  save/restore these as part of the context so a fault inside a suspended
  coroutine resolves against *its* handler, not the resumer's. `RESUME` /
  `RESUME NEXT` semantics across a `YIELD` boundary must be defined (initial
  rule: an unhandled error in a coroutine propagates to the resumer with the
  handle marked done).
- **Lifetime / leaks.** The heap stack block must be freed on exhaustion and on
  early `FOR EACH` exit (`EXIT FOR`, error unwind). The `FOR EACH` lowering owns
  this; the explicit-handle form frees at end of scope (tie into the existing
  local string/closure cleanup pass in the epilogue).
- **Re-entrancy and nesting** are naturally supported (independent contexts) but
  need tests: coroutine driving a coroutine, recursive coroutine.
- **Interaction with `$CPU 80386` 32-bit codegen.** When the coroutine body uses
  32-bit registers/`ESP`, the saved SP/BP must be the 32-bit forms; reserve
  DWORD slots in the context under that mode.

---

### 4. Phased implementation plan

**Phase 0 — front-end prototype (this branch).**
`YIELD` token path, `YieldStmt` AST node, pb36 gate, binder type-check of the
value, unit tests. No codegen. *Done.*

**Phase 1 — declaration surface + binder model.**
Parse the `COROUTINE` modifier on SUB/FUNCTION/DECLARE; mark `ProcedureSymbol`
as a coroutine; bind-time errors for `YIELD` outside a coroutine and for a
coroutine whose return type does not match its yields. Add the `COROUTINE`
handle type to the type system. Front-end + binder unit tests.

**Phase 2 — runtime context + stack switch helpers.**
Implement `CoroCtx`, the stack-block allocator/free (off the runtime heap), and
the `RESUMING`/`YIELDED` runtime helpers (or inline sequences). Pb36 DOSBox
execution tests: a hand-written single-`YIELD` coroutine driven by the explicit
handle form, checked against a golden transcript.

**Phase 3 — `YIELD` codegen + body emission.**
Emit the suspension sequence and the resume re-entry label per `YIELD`; emit the
coroutine body as a normal proc that takes the hidden `ctx` parameter; wire the
completion epilogue. Execution tests: multi-`YIELD`, FOR/DO across suspensions,
nested calls inside the coroutine.

**Phase 4 — consumption.**
`FOR EACH ... IN <coroutine call>` lowering (resume/test/read/free); the explicit
`g = Coro(...)` handle form. Execution tests for both, plus early-exit and
exhaustion cleanup.

**Phase 5 — robustness.**
`ON ERROR`/`RESUME` across suspensions, stack-overflow detection per instance,
re-entrancy/recursion, `$STACK`/`COROUTINE(size)` sizing, 32-bit (`$CPU 80386`)
context slots. Stress execution tests.

Each phase keeps the pb35 differential harness green (coroutine surface is
pb36-only, so it never reaches the oracle path) and adds pb36 execution tests as
its verification gate.

  literal `(a, b)` builds a tuple value (`t = (99, "x")`) and gives **parallel assignment /
  swap** `a, b = (b, a)` (and longer rotations) simultaneous semantics (all right-hand values
  read into temps first). A tuple type `(T1, T2, …)` is a synthesized UDT (`Item1`…`ItemN`).
- ~~**Discriminated unions / variant records**~~ — **DONE**: `UNION Shape / CASE Circle /
  Radius AS SINGLE / ... / END UNION` lowers to a tagged TYPE (hidden `$tag` plus per-case
  view TYPEs overlapping `AT` offset 2); case names are module-wide constructors
  (`s = Rect(3, 4)`), and `IF s IS Rect r THEN ... r.W` is the pattern test with a payload
  binding. Exhaustive `SELECT CASE` matching remains open.
- ~~**Nullable / option types**~~ — **DONE**: `DIM x AS LONG?` synthesizes a value-type UDT
  with a `Value` field and a `HasValue` presence flag. `x = v` sets both, `x = NOTHING` clears
  the flag, `x ?? d` is the null-coalescing operator (value when present, else `d`), and a
  nullable auto-unwraps to its `.Value` in arithmetic and when assigned to a plain target.
  The `?`/`??` collide with the BYTE/WORD type-suffixes, so the lexer disambiguates a glued
  `?` run by context — a `??` before an operand is the coalescing operator (`a??15`), otherwise
  the type suffix (`a??`) — and a type-keyword carrying a single `?` in type position is the
  nullable marker.
- ~~**`OPERATOR` overloading for TYPEs**~~ — **DONE**: `OPERATOR + (other AS Vec) AS Vec`
  inside a TYPE (`THIS` left operand, `RESULT` the result), resolved at compile time; a
  TYPE-returning operator uses struct return, a scalar-returning one works in any expression.
- ~~**Type aliases**~~ — **DONE**: `TYPE Handle AS DWORD` (single line, no `END TYPE`) —
  transparent, resolved away at bind time; chains resolve transitively, cycles are errors.
- ~~**Bit-field members in TYPE**~~ — **DONE**: `Mode AS BIT * 3` / `Enabled AS BIT` packs
  consecutive bit-fields into a hidden `$bits` WORD; a read desugars to `(word >> offset) AND
  mask` and a write to a read-modify-write that preserves the neighbouring fields — pure binder
  desugar over WORD storage, no new codegen. A run of bit-fields fills 16-bit words in order; a
  non-bit field breaks the run.

### Functional / iteration

- **Range expressions & lazy sequence operators** (M) — **partly DONE**: ranges are the
  wordy `lo TO hi` everywhere (collection literals, `FOR EACH v IN 1 TO 9 STEP 2` without
  brackets) and `x IN lo TO hi` / `x IN {a, b, lo TO hi}` is the membership filter, all
  lowered to plain comparisons in the parser. Lazy `MAP`/`FILTER`/`REDUCE`/`TAKE` over
  generators remain open.
- **Pipeline / `|>` operator** (S) — `x |> f |> g` = `g(f(x))`; pure parser sugar over
  calls, great with the above.
- **Partial application / function composition** (M) — bind some arguments of a delegate;
  compose two delegates. Extends the existing typed-delegate support.
- **Array slicing / spans** (M) — `a(2..5)` a borrowed view; `a(^3..)` from-end slices
  (we already have `arr(^n)` indices).

### Control flow & error handling

- **Pattern matching `SELECT CASE`** (M) — **partly DONE**: the `IF s IS Case v THEN`
  pattern test with payload binding ships with discriminated unions; `SELECT CASE`-based
  matching with exhaustiveness checking remains open.
- ~~**`DEFER` / scope guards**~~ — **DONE**: `DEFER CloseFile(h)` runs on scope exit
  (normal or fault), lowered onto `TRY ... FINALLY`; the re-raise propagates the saved
  error code so a FINALLY that handles its own errors cannot corrupt it.
- **Result/error-return types & propagation** (L) — an `Outcome OF T` plus a `?`
  propagation operator as a typed alternative to `TRY/CATCH`; rides generics + tuples.
- **`ITERATE`/`EXIT` with labels** (S) — **partly DONE**: unlabeled `ITERATE [FOR|DO|
  LOOP|WHILE]` (continue) works, targeting the innermost loop of the given kind; labeled
  forms for outer loops remain open.

### Compile-time / metaprogramming

- ~~**Compile-time function evaluation**~~ — **DONE** (no `CONSTEXPR` keyword): the
  compiler *infers* purity — a `FUNCTION` whose result depends only on its `BYVAL`
  arguments (no I/O, globals, `BYREF` or side effects) — and when such a function is called
  with all-constant arguments it is **interpreted at compile time** and the call replaced by
  the resulting literal (`CodeGen/OptPureFold.cs`). Sound subset v1: integer functions with
  IF / SELECT / FOR / DO-LOOP / WHILE and recursion; every intermediate is wrapped to its
  static type so the folded value is bit-identical to the runtime ALU, under a step/recursion
  budget. Floats, strings, arrays and intrinsics keep the real call (a roadmap extension).
- ~~**Static assertions**~~ — **DONE**: `$ASSERT cond [, "msg"]` is evaluated by the
  binder (non-constant or false = compile error) and emits no code.
- ~~**Compile-time reflection over TYPEs**~~ — **DONE**: `TYPEOF$` / `SIZEOF(T)` /
  `FIELDCOUNT` / `FIELDNAME$` / `FIELDOFFSET` / `FIELDSIZE` all fold to literals at bind
  time (no runtime RTTI) and compose with `$ASSERT`.
- **`$RESOURCE` / embed-binary** (S) — bake a file into the image as a byte array
  (sprites, tables), with `$INCLUDE`-style ergonomics.

### Memory & performance (pb36's core mission)

- **Arena / region allocators** (M) — `WITH ARENA ... END` bulk-frees temporaries; cheap
  scratch memory without per-object frees.
- ~~**`ALIGN` / `PACKED` TYPE layout control**~~ — **DONE**: `TYPE Name PACKED` (the
  byte-packed default, made explicit), `TYPE Name ALIGN n` (each field on an n-byte boundary
  capped at its natural alignment, total rounded to n), `TYPE Name SIZE n` (fix the total size),
  and per-field `field AS T AT offset` (explicit placement — gaps or overlapping/union-style
  views). Pure binder layout (`DefineUdt`), so field access, array strides and block copies all
  pick up the offsets/size for free; pb36-only (genuine PBC always byte-packs).
- ~~**EMS/XMS array element access**~~ — **FIXED/DONE** (2026-07): EMS/XMS arrays now ride
  the full paged (VIRTUAL) machinery end to end - element access page-maps per access
  through a **global** frame cache (`rt_ems_curhnd`/`rt_ems_curpage`: all paged arrays
  share the one EMS page frame, so the cache covers handle *and* page; the zero-fill
  invalidates it), descriptors reserve the full 20-byte paged slot (was: EMS/XMS slots
  were sized as plain 12-byte dynamic descriptors, so the handle/cache words of one array
  overlapped the next array's descriptor), and LBOUND/UBOUND/REDIM-PRESERVE dispatch
  includes the EMS/XMS classes. UDT elements work fully: member reads/writes and
  whole-element copies through the far paged window, arrays beyond 64 KiB, and multiple
  EMS/XMS arrays without cross-talk.

- **SIMD/MMX (586/MMX gate)** (L) — **in progress**: MMX integer intrinsics are available in
  the inline assembler (`! PADDW MM0, MM1`, `MOVQ`, packed multiply/compare/shift, `EMMS`),
  `$CPU 80586 MMX|SSE|AVX|AVX512|AES` feature flags gate the SIMD width, and the optimizer
  **auto-vectorises** `FOR i: c(i)=a(i) OP b(i)` integer loops to 4-wide MMX with a scalar tail
  (execution-verified in DOSBox). Wider widths (SSE/AVX/AVX-512) and wide integer datatypes
  (128–512-bit, signed/unsigned, emulated on older targets) are the next tiers.
- **`FORCEINLINE` / `NOINLINE` hints** (S) — override the trivial-method inliner's
  heuristic when the programmer knows better.
- ~~**Stack arrays**~~ — **DONE**: `DIM STACK a(1 TO n) AS T` places the array in the
  procedure frame — reentrant, zero DGROUP footprint, freed on return.

### Tooling / dialect

- **The source-writer / decompiler** (M) — already on the list: re-emit BASIC from the
  fully woven, optimized AST/IR to see the program "without the magic" (see memory
  `pb36-source-writer`).
- ~~**`$IF` with full constant expressions**~~ — **already supported**: the preprocessor
  evaluates a full constant expression (`$IF (%A > %B) AND (%A + %B = 8)`) via its `EvalOr`
  precedence chain, more lenient than the bare-equate condition genuine PBC allows.
- **Contracts** (M) — `REQUIRE` / `ENSURE` pre/postconditions, compiled out in release.

### Suggested near-term order

1. **Tuples + multiple return values** — high payoff, moderate size, broadly useful.
2. **`OPERATOR` overloading** — completes the value-type story alongside generics.
3. **`DEFER`** — small, reuses `FINALLY`, immediately useful for resource handling.
4. **Range + lazy sequence operators** — leverages the generator model already built.
5. **Discriminated unions + pattern matching** — the bigger, higher-value pair once the
   above land.

### Optimizations below the source level

The bulk of the optimizer rewrites the *generated machine code*, not the AST, so it does not surface
in a source decompilation. For completeness, these passes run during code generation (see
docs/PIPELINE.md for the tier model and docs/PB36.md for the per-pass detail):

| Pass | Tier | What it does |
|------|------|--------------|
| Constant folding | 2 (emit) | folds compile-time-constant arithmetic / comparisons |
| Sparse conditional constant propagation (SCCP) | 1 (IR) | propagates constants through branches, prunes dead arms |
| Copy propagation | 2 (emit) | replaces a copy's uses with its source, killing the copy |
| Common-subexpression elimination (local + cross-block) | 2 (emit) | reuses an already-computed value instead of recomputing |
| Global value numbering (GVN) | 1 (IR) | unifies provably-equal computations |
| Dead-store elimination (DSE) | 1 (IR) | drops stores whose value is never read |
| Loop-invariant code motion (LICM) | 1 (IR) | hoists invariant work out of a loop |
| Induction-variable simplification | 2 (emit) | strength-reduces `i*const` loop addressing |
| Strength reduction | 2 (emit) | rewrites `x*const` as shift+add, `x\const` as a reciprocal/shift |
| Loop unrolling | 2 (emit) | unrolls small constant-trip loops |
| Inlining | 2 (emit) | inlines small/leaf procedures |
| Tail-call optimization | 2 (emit) | reuses the frame for a tail self-call (constant stack) |
| Dense `SELECT CASE` -> jump table | 2 (emit) | replaces the compare chain with an indexed indirect jump |
| Instruction scheduler | post-emit | reorders the final byte stream to group loads / ALU work (latency hiding) |
| Jump threading | post-emit | retargets a JMP/Jcc whose destination is an unconditional JMP straight to the final target (ITERATE/GOTO cascades collapse to one hop) |
| Peephole | post-emit | local instruction-pattern rewrites (accumulator short forms, sign-extended imm8, ...) |
| Register-parameter passing | 1 (pre) | passes leaf-call arguments in registers |
| Float demotion | 1 (pre) | demotes a DOUBLE to SINGLE when the program never needs the precision |
| Reachability tree-shaking (O22) | 3 (layout) | drops unreachable procedures, runtime helpers and unread DATA |
| Runtime trim / virtual BSS / `.COM` | 3 (layout) | shrinks the image: unused runtime, zero-init data behind the image, tiny-model `.COM` |
